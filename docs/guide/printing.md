# Printing

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 8f. Printing: printers, plates, slicing and sending

Stage 5 of the loop (§1). The plan, findings and what's still unverified: [docs/Print plan.md](../../docs/Print%20plan.md). Nothing about a printer is hard-coded: the P1S is one catalog entry.

- **Printer catalog** (`src/data/printerCatalog.ts`, generated; types and helpers in `data/printers.ts`): 103 printers from two slicers' bundled machine profiles. Bambu Studio's (`bambulab/BambuStudio` at tag `v02.09.01.70`) give 93; OrcaSlicer's (`OrcaSlicer/OrcaSlicer` at `v2.5.0`) add the makers listed beside it in `tools/printers/import.mjs` (Prusa today: CORE One, CORE One L, their HF versions, MK4, MK4S, MK4S HF, MK3.5, MINI IS and XL), and Bambu Studio stays the source for any printer both have (the MINI and MK3S). Multi-tool printers (MMU, INDX, the XL 5T) stay out; the XL is its single-tool configuration. Each entry has its bed polygon, height, keep-out zones, nozzles, default plate type, `source` (the slicer and version it came from) and, for the 0.4 mm nozzle, the machine, default process, process presets by layer height and a filament preset per material (Prusa's FLEX counts as TPU). The importer (`tools/printers/catalog.mjs`) resolves `inherits` within a maker, reads presets in subfolders, and matches processes and filaments to the machine by `compatible_printers`, or by `compatible_printers_condition` when the list is empty (`condition.mjs` evaluates the `=~`, `!~`, `==`, `and`, `or` forms Prusa's profiles use). Regenerate with `node tools/printers/import.mjs`: it sparse-clones `resources/profiles` of both repos at the pinned tags into the system temp folder and rewrites the file; bump the tags there to update. Never edit the generated file by hand. Custom printers take a build volume.
- **My printers** (`library/printers.json`, `electron/print/printers.mjs`): app-wide, one default. On first launch the list is seeded from the printer selected in Bambu Studio (`BambuStudio.conf`), sending through Bambu Studio. Access codes and API keys are encrypted with `safeStorage` in `library/agent-config/printer-keys.json` (`AgentKeys` with `file`), never in the scene. A scene's `project.printer` resolves with `resolvePrinter` (a My printers id, a catalog id, or the default printer).
- **Plates** (`src/print/`): the analysis worker returns a printer-independent `PrintShape` per shape (poses: 6 axes plus up to 6 flat faces the part rests on, each with its rotation, footprint, overhang, support and contact). `choosePose` picks one for the bed (`bed.ts`: keep-outs, 90° turn, diagonal fallback); `pack.ts` packs per material with MaxRects around the keep-outs; `buildPrintPlan` returns plates with a matrix per item (part frame → 3MF bed frame, Z up) and a hash per plate. User choices live on the part (`ScenePart.print`: `down` face, `plate`, `at`, `turned`, `copies`, `skip`), so they undo like any edit.
- **Orientation feeds strength** (§8b): layers bond more weakly than a line of plastic, so the face a part prints on decides how strong it is. Strength in Checks grades a part at its chosen face (`print.down`, or the pick above) and at every other candidate, and its Fix sets the strongest face. Best Face in Print mode returns to the pick above, which only weighs support and contact.
- **3MF** (`print/threeMf.ts`, run in the analysis worker): one file per material, plates laid out on Bambu's plate grid (plate i at column × width × 1.2, row × −depth × 1.2, columns = ⌈√n⌉ rounded as Bambu does), plain 3MF core, names kept. Export ▸ 3MF Plates downloads them.
- **Slicing** (`electron/print/`: `slicers.mjs` finds Bambu Studio, OrcaSlicer, PrusaSlicer in `/Applications` on macOS and in Program Files or `%LOCALAPPDATA%\Programs` on Windows (`bambu-studio.exe`, `orca-slicer.exe`, `prusa-slicer-console.exe`, profiles in `resources\profiles`); `openFile` in `jobs.mjs` opens files with `open -a` or the slicer's exe; `slice.mjs`, `jobs.mjs`): each printer slices with the slicer its profiles came from (`slicerOrder` in `data/printers.ts`, carried in the job as `slicers`; `slicerFor` in `slicers.mjs` takes the first one installed): Bambu printers try Bambu Studio then OrcaSlicer, other Bambu Studio entries OrcaSlicer then Bambu Studio, and OrcaSlicer entries only OrcaSlicer. PrusaSlicer isn't a fallback for them: its presets are INI bundles with other names (“Original Prusa CORE One…”), so Orca's names don't map onto them. Sending a plate with no connection opens it in that same slicer. The CLI runs headless per material with **flattened** profiles (the CLI doesn't follow `inherits` for loaded files and falls back to a 200 × 200 × 100 plate), `--arrange 0`, infill and the printer's default plate type (`curr_bed_type`) written into the process. Results come from `result.json` and the sliced 3MF: time, grams, supports, warnings and the plate thumbnail per plate, cached per material by plate hash in `library/prints/<scene>/`. The CLI can't take per-object filaments with 3MF input and crashes on edited Bambu projects, so materials are separate jobs. `electron/print/slice.test.mjs` slices for real when Bambu Studio is installed.
- **Sending** (`electron/print/index.mjs`, connectors in `electron/print/connectors/`): Bambu Studio (default for Bambu printers: opens the sliced plates, where Print uses the user's own sign-in), Bambu Connect (URL scheme), Bambu LAN (Developer Mode: FTPS upload + MQTT `project_file`, live status, AMS trays), Moonraker, PrusaLink, OctoPrint (plain G-code pulled from the sliced 3MF). Find on Network reads Bambu SSDP and mDNS (`dns-sd` on macOS; on Windows a small `node:dgram` client, `connectors/mdns.mjs`, that sends one-shot queries from an ephemeral port so it never binds 5353). **Only the user starts a print**: Print Plate N opens a Start Print sheet: the plate's time and grams, one line that names the material with what to load or the AMS slot it prints from, and Clear the bed; the agent's `slice_plates` never sends.
- **Print mode** (⌘P, and Print in the File menu, the Build tab's Printing section and ⌘K: one name wherever it opens): the canvas shows one plate (`three/plates/plateView.ts`, its own WebGL canvas while open; the scene viewport pauses) with the bed, its keep-outs and the parts in print orientation (shared geometry). Drag to move (saved as `at`), F Lay on Face, R Turn 90°, ←/→ plates, Esc closes. R and the panel's Turn 90° are one action (`printing.turnPart`, from `turnedPrint` in `print/plan.ts`): the part turns where it sits, saving its spot as `at` with `turned`, since a part without `at` is packed loose and the packer picks its own turn. The Print panel replaces the inspector and holds everything about printing; the Build tab shows only the plate count and total time (§8b). The panel: Print Fit Test beside Done in its header (below), Printer (with Label parts, and Skip N printed parts once something is printed), the selected part (Lay on Face, Turn 90°, Plate, Copies, Don't print, Don't label), the plate (thumbnail when sliced, its state, warnings, Send / Print Plate N, Open in Bambu Studio, Mark Printed / Failed) and **Parts** (`PrintedSection`, collapsed with its count: per-part size, time, plate and issues, parts with issues first, copies as “2 ×” before the name; a click selects the part on its plate), with Done (Esc) in its header. With no saved printer the plate's primary button is Add Printer, which opens Settings ▸ Printers (the web demo, which can't save printers, shows none); the section is called Parts, not Printed parts, because Skip N printed parts already uses “printed” for parts that came off the printer. Slicing every plate at once is ⌘K ▸ Slice Plates; Send slices a plate that isn't. Either way a progress toast with Stop follows the slice wherever you are and turns into the result or the error; the plate section shows the progress with Stop too, and keeps the error. The bottom bar is the only plate list (each plate's number and material) and holds Auto Arrange; it has no close button, since Done, Esc and ⌘P already close.
- **Fit test** (`print/fitTest.ts`, `three/analysis/fitCoupons.ts`, `workspace/useFitTest.ts`): Print Fit Test (in the Print panel's header and ⌘K, offered while the scene has a printed part and a fit) plates small coupons cut from the design, so a tight pocket shows up in a short print, not after the full plate. Fits are grouped by kind and spec (`fitKey`): a heat insert by its size, length and outer diameter, a servo or motor pocket by catalog component, a bearing seat by bearing type and size, a screw clearance by size. For the first instance of each group with a host, the analysis worker (task `fitCoupons`, rest pose) finds the printed part that holds it (its surface within 0.5 mm of the bought part's box, or the box's centre inside it; the largest box overlap wins) and intersects that host with the bought part's own box plus a 4 mm wall (`FIT_WALL_MM`, three-bvh-csg). Each coupon keeps its host's chosen print pose (`down` from the design's plan) and goes through the same `reportFromShapes` → `buildPrintPlan` path as any part, so the plate packs, slices and sends as usual; its 3MF is written from the coupons' own triangles (`useFitTest`'s `threeMf`), and its slices go to their own job (`<scene>-fit-test`), so the design's cached slices stay. The plate is temporary: the coupons are `sculpt_mesh` parts that exist only while it's open, never in the scene; you can't move them, Auto Arrange and Mark Printed are hidden, and sending one records no print. The panel's header reads Print Fit Test, and Done or Esc returns to the design's plates.
- **Merge** (`print/merge/`, `workspace/useMerges.ts`, `print/MergeSection.tsx`): while Print mode is open, the analysis worker plans which printed parts could print as one. It runs inside the `assembly` task (`AssemblyGeometryInput.merges`, `mergeInput` builds it on the main thread), after the assembly geometry, on the same placed solids. Candidates are visible printed parts not set to Don't print; a pair is joined when a screw chain (`clampedBy`: its stack, a printed or catalog part it threads into, or the host of its insert) clamps only candidates of one rigid link (`buildRig`'s owner, or none) and one material, and their meshes are within 0.5 mm. Each connected group passes three checks, in order: the removal plan with the group as one part (`mergedGeometry` folds the members' moves, renames them in chains and drivers, and drops the joining hardware) has no part that came out alone but now only comes out sealed in a unit with it (`seals`), and nothing newly stuck (`stuck`); then the union, members' triangles in world space minus faces lying on another member (0.05 mm), fits the bed in some pose (`choosePose`) with no more than 2 cm³ of support beyond the members printed apart (`NEW_SUPPORT_MM3`). A group that fails tries its connected subsets, largest first and in id order (64 tries at most), and names each part left out with the reason it fails when added back. Planning stops taking new groups after 10 s. The kept part has the most joint references, then the largest box; the joining hardware is every screw whose clamped parts are all members, with its inserts, nuts and washers. Steps saved come from the guide planner (`buildGuidePlan` on the approximate scene, members replaced by their union box), so the press-in step of removed inserts counts too. Each group is a row in the Print panel's Merge section, with what it saves (parts, screws, steps), its left-out parts and **Merge**; ⌘K lists Merge ⟨names⟩ for each row while Print mode is open. Merge plans again on the current scene, unions the members through the editable boolean path (`booleanPart`, the kept part's id and material, operands stay editable) and removes the joining hardware in one `commitParts`, so one undo restores everything. The BOM, Checks, plates and the guide follow from the scene. On the 81-part quadruped fixture (`merge.fixtures.ts`) the worker task takes about 0.6 s on an M-series Mac, 0.2 s of it planning; `mergePlan.test.ts` holds it under 2 s.
- **Labels** (`print/labels/`, `workspace/usePlateWriter.ts`, `three/analysis/plateFiles.ts`): each printed part gets its build guide letter debossed on a face nobody sees once the robot is built, in the plate's mesh only; the scene, Checks, the BOM, shape keys and plate hashes never change. Label parts under Printer in the Print panel (`project.labelParts`, on unless turned off) and Don't label on a selected part (`PartPrint.noLabel`) decide which parts get one. The letters are the guide's own: `usePlateWriter` asks `useBuildGuide.currentPlan` for the plan (the one Build Along reads; an out-of-date guide is made first) and `partLetters` maps each printed item's parts to its label, so the PDF, Build Along and the parts agree. Writing plates with letters snapshots every visible solid at rest, and the analysis worker's `plateFiles` picks a face per part (`pickLabel`): the flat faces (connected coplanar triangles, largest first, 16 at most) that don't face the bed (normal · down ≤ 0.7, down read from the plate item's matrix), fit the letters (`fitLabel`: cap height 4–10 mm, strokes 0.8–1.4 mm, a 0.8 mm wall to every edge of the face, so a label is shrunk or skipped, never clipped), keep 1.2 mm of plastic behind the label, have no sample within 1.5 mm of another part (the guide's contact distance), and let no ray out from any sample in 96 directions (hidden). The first that clears gets the letter, centred, 0.4 mm deep: strokes of the built-in single-stroke font (`labelFont.ts`, A–Z) as prisms, subtracted with Manifold (`manifoldCsg`). A part with no such face, or a mesh Manifold can't take, prints plain, and its row in Parts says why in amber. Slices carry a labels key (`labelsKey`: the guide fingerprint and the Don't label parts) in the job and the slice record, so a plate sliced before its letters could change is sliced again (`freshSlice`, `groupHash` in `electron/print/jobs.mjs`). Fit test plates are never labeled. Labeling the 81-part quadruped fixture's plates adds about 0.05 s in the worker on an M-series Mac (none of its 13 printed parts has a hidden face), and the lidded tray fixture's letter about 0.03 s; `partLabels.test.ts` holds the quadruped under 2 s.
- **Prints tracker** (`print/tracker.ts`, `project.prints`): a record per plate sent (parts with their shape keys, printer, state from live status or marked by hand). A part counts as printed while its shape is unchanged, and Skip N printed parts (on by default) leaves those parts off the plates, so editing one bracket after printing gives a plate with just that bracket.
