# Scene tabs

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 5a. Scene Tabs

Several scenes stay open at once, each with its own parts, undo history, selection, comments and agent conversation.

- **Architecture:** `App.tsx` is the tab host; each tab is a `SceneWorkspace` (`src/SceneWorkspace.tsx`).
  - Every tab stays mounted (background tabs mount shortly after launch, §0f), so a background agent keeps building and can render its review shots. Background tabs are `invisible` + `inert`, and their `Viewport3D` is `paused` (no render loop; captures still render on demand). Closing a tab frees its WebGL context (`forceContextLoss`).
  - Up to 8 tabs (browsers cap WebGL contexts near 16). A ninth says “Close a scene to open another. Up to 8 stay open.”
  - App-wide state lives in the host and reaches scenes as `studio` (`StudioShared`): preferences, panel open state and widths, libraries, chat list, the agent connection, Settings. Per scene: everything about the scene, Left/Right panel tabs, the palette, toasts.
  - **Reading another tab's robot:** `studio.robotsBeside(tabId)` returns every other open tab's robot (`sceneRobots` in `src/app/tabModel.ts`: the scene's name, parts and joints, from the tab's live snapshot, or its seed while unmounted; tabs without joints are skipped). It's a call, not state, so a scene reads it in a handler (opening the Case builder, opening a Case, starting a try) and never during render. A Case's extra robot slots are filled this way (§8h).
  - Only the scene in front listens to the keyboard, paste, the menu bar and the dev `__studio` hook. Background scenes skip re-renders for app-wide changes (custom `memo` comparator) and catch up when brought to front.
- **Where:** in the title bar (§2), ending 8px before the scene's actions. With the sidebar open, the first tab starts over the canvas card's left edge (rail + sidebar width + 8px gap), so the strip lines up with the canvas, and slides with it as the sidebar resizes or toggles; with the sidebar closed (or too narrow to clear the title bar controls) it starts 8px after the Scenes menu. `App.tsx` lays the sidebar toggle and `SceneTabs` over each scene's title bar drag region. No glass: the tabs are part of the window chrome.
- **Tabs (`SceneTabs`):** 28px rounded pills (8px corners), 180px wide, shrinking to 96px, 6px apart, on the title bar's centerline.
  - The active tab sits on a flat `#262626` fill (no edge or highlight); its label is `white/90`, 13px medium, and its × always shows.
  - Background tabs are labels (`white/50`, `white/80` on hover) in a faint `white/[0.07]` inset ring (box-shadow, so it takes no space), with a soft fill on hover and × on hover.
  - Nothing else: no icons or separators. While a scene's agent works, a 12px white spinner sits before its name.
  - Past their minimum width they scroll sideways (the wheel scrolls; an edge fades only while tabs are hidden past it, measured from layout so sliding tabs don't trigger it).
  - New tabs grow in (`animate-tab-in`); tabs slide into place after insert, close and drop (FLIP, 220ms).
  - Press selects. Drag past 4px reorders. Double-click renames inline. Middle-click closes. × closes (`Close  ⌘W`); it's a 28px mouse target hidden from the accessibility tree, since a button inside a tab breaks the tab role, so keyboard and screen reader users close with ⌘W or the tab's menu. Right-click: Rename, Duplicate, New Scene, Reopen Closed Scene, Close, Close Other Scenes, Close Scenes to the Right.
  - Resting 800ms on a background tab opens a small preview card under it: a fresh frame of that scene, its name, and its part count in the Scenes list's words (“0 parts”, “1 part”, `scenes/partCount.ts`), or the agent's live activity while it works.
  - + (28px) 2px after the last tab (its glyph carries 6px of air, so it reads about as far out as the tabs are apart): `New scene  ⌘T`.
- **Opening and closing:**
  - New scenes are numbered so open tabs never share a name: Untitled, Untitled 2…
  - Library → a scene: shows its tab if it's open, reuses the tab in front if it's untouched (blank, unrenamed, unused), otherwise opens a new tab after it.
  - Closing a tab stops its agent, saves its chat and ends its session. The toast reads “Closed ⟨name⟩” + [Undo] (“…and stopped its agent” when one was running); Undo reopens it in place with its chat. Untouched tabs close silently. Closing the last tab leaves a blank one, which Undo removes again.
  - ⇧⌘T reopens the last 10 closed scenes. Duplicate (the tab's menu, ⌘K, or the Scenes menu) copies the scene, not the chat, and names it “Sprout copy”, then “Sprout copy 2”, skipping any name an open tab or a saved scene already has (`sceneCopyName`).
  - When a background agent finishes: “Agent finished in ⟨name⟩” + [Show].
- **Sharing scenes** (`utils/sceneFile.ts`): Export ▸ Scene (also File ▸ Export Scene and ⌘K) downloads `<name>.basecase`, gzipped JSON `{ format: 'basecase-scene', version, scene }` holding the name, description, parts, comments, project settings and preview, built from the scene in memory. It leaves out what belongs to the sender's machine: the chat, `prints` (so Skip N printed parts doesn't skip the sender's prints), `policies` and `buildGuide` (their files live in the sender's `library/`). File ▸ Open Scene File, ⌘K, or dropping the file on the canvas saves it to the Library under a new id and opens it in a tab (`importSceneFile` in `useSceneLibrary`). The file is untrusted: it must match the format, parts need an id, kind and position, images must be `data:image/` URLs, and a newer `version` says “Made with a newer Basecase. Update to open it.” Bump `VERSION` only when an older app can't read the new shape. A robot imported from Onshape keeps its link as ids only, never the account's keys: `group.onshape` on each of its parts (document, workspace or version, element), `robotLink.onshape` (its Onshape occurrences) and `onshape` on each joint (the mate's id, and `gone` once the mate is deleted in Onshape), which Update from Onshape uses (§8c). A shared scene keeps them, so whoever opens it can update the robot with their own keys if their account can open the document.
- **Shortcuts:** ⌘T new, ⌘W close, ⇧⌘T reopen, ⌃Tab / ⌃⇧Tab and ⇧⌘] / ⇧⌘[ next / previous, ⌘1–⌘8 a tab, ⌘9 the last. They work while typing (except with Settings open). ⌘K lists every other open scene under Open Scenes, plus New / Duplicate / Close / Reopen Scene.
