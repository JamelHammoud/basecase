# Shared design system

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 14. Shared Design System (`src/design-system`)

Use these primitives. Never hand-roll a styled `<button>` or input when one fits.

- `Button` (primary, secondary, ghost, danger, contrast; xs/sm/md; optional `title` + `shortcut` tooltip)
- `MenuItem` (shared by `PopoverMenu` and `ContextMenu`): `tone: 'danger'` paints the label and its icon red. Every menu draws its icons at one size: `MenuIconSlot` (`menuGutter.tsx`) sets a 14px icon in the 16px column, for a submenu's row too, and ⌘K sets its own at 16px. Pass a menu entry's or command's icon without a size (`<DeleteIcon />`), so one element serves an action's right-click entry and its ⌘K command. Labels in one menu line up: when any item leads with an icon or a tick column (`checked`, even `false`), an item with neither keeps an empty 16px column in their place (`menuGutter.tsx`). Each menu surface is its own scope: a `ContextMenu` decides from its entries, while a `PopoverMenu` or a submenu counts the items rendered in it, so a submenu never shifts the menu that opened it. Never pass `checked={false}` or an empty span to fake the column. A menu's Rename, Duplicate and Delete come from `renameEntry`, `duplicateEntry` and `deleteEntry` (`menuEntries.tsx`), so each has one label and icon in every menu (Delete red, with an optional shortcut). Duplicate wears `DuplicateIcon` wherever it appears, Inspector buttons and the part commands included; `CopyIcon` is Copy's alone. The same holds for every action in buttons, menus and ⌘K: Stop wears `StopIcon` (`CloseIcon` is for Close, Cancel, Remove and clearing a field), New Scene `PlusIcon` like New Case and New Routine (`ComposeIcon` is the agent's new chat), Save to Library `BookmarkAddIcon`, Run Checks `CheckIcon`, Compare `CompareIcon`, Coach `CoachIcon`, Stress `StressIcon`, and Recheck `RefreshIcon`, which also marks Retry and Update from Onshape. `CrosshairIcon` is Center on Origin's alone: Zoom to Selection wears `FitIcon`, like the image viewer's Zoom to fit, and Reset View wears `RotateLeftIcon`, like Reset Rotation.
- `IconButton` (required `title`, `shortcut`, `isActive` solid accent, `isToggled` soft fill; xs/sm/md/lg). `variant="send"` with `className="rounded-full"` is the round white button that sends what's typed: the agent composer's Send, Update and Stop, and a comment's Post.
- Both take `className="rounded-full"` for a fully round button: `sizeRadius` drops the size's own radius, because Tailwind's stylesheet order, not class order, decides which radius wins and `rounded-lg` beats `rounded-full`. Any other whole-button radius passed through `className` needs `!`.
- `Tooltip` (portal, 500ms delay, instant while “warm”), `Kbd`. A tooltip never shows while the popover its trigger controls is open: give every popover or menu trigger `aria-expanded={open}` (and `aria-haspopup="menu"` for menus), and `Tooltip` stays hidden while it's true. Don't hand-roll `disabled={open}` or drop the title instead.
- `FieldRow` (`label`, then the field): an 88px muted label left of a form field, as in the Routines step fields and the New Case card. With `group` it is a `div` with the label above and the field across the full width, for a `ChoiceGrid` of names too long for the 88px column (New Case's **Spot**); a `label` would hand its clicks to the first button.
- `NumberInput` (scrub, math, live/commit; `title` names a one-letter `label` in a tooltip on that letter, such as W for Width (X), and a field whose name is already on screen passes `aria-label` instead), `Slider` (double-click resets; `stacked` puts label and value above a full-width track), `Switch` (an 18px track in a 28px hit box; without `label`, pass `aria-label` with the row's label so screen readers name it), `TextInput` (`bare` for a name always editable in place, as the Inspector's part and group titles), `RenameField` (the field a Rename or double-click swaps in for a name: it opens with the name selected, Enter or a click away keeps the change, Esc cancels, and `onDone` gets the trimmed new name, or `null` when it's blank, unchanged or cancelled, so nothing is saved and no undo step is added; it keeps its keys and clicks from the row or tab under it; 24px tall, `className` resizes it), `TextArea`, `Select`
- `SearchField`: the search at the top of a sidebar view. 40px tall, 10px corners, 14px text, a 16px glass icon; the whole field is the click target. `onBack` swaps the glass icon for a Back button in the same spot (the text doesn't move), for drilled-in views. Idle it shows its shortcut as key caps on the right (hidden on focus); with a query, a round clear button takes that spot. Focus is a 1px blue ring with a soft 3px blue halo. Use it for any list-filtering search; keep `TextInput` for form fields.
- `ColorField`: swatch + hex field. The picker opens beside the inspector with a saturation/brightness square, hue strip, hex input, eyedropper (`EyeDropper` API) and “In this scene” colors. Never list fixed swatch rows. `ColorPickerPopover` is the same picker on its own anchor (`side: 'top'` opens it above a floating bar, as the marks pill's Custom color does).
- `ColorSwatches`: a row of named colors plus Custom color, for drawing tools only (the marks pill, the Sketch palette). `onPicked` fires when a choice is finished: a named color, or the custom picker closing. `ColorSwatch` is one circle.
- `SegmentedControl` (sliding thumb, `tone: 'danger'`) for choices inside content, `ChoiceGrid` for a choice from a list that wraps (sizes, finishes, drives; `stacked` puts an icon over the label) on the same soft track and thumb (`CHOICE_TRACK`, `choiceCellClass` in `choiceStyles.ts` for hand-built strips), `PanelTabs` for a card's views (quiet labels, the current one on a soft pill; content-sized; when they don't fit they scroll sideways (the wheel scrolls too) with a 24px edge fade only while tabs are hidden past it, and the current tab scrolls into view clear of the fade; a tab's `menu`, while it's the current tab, widens its pill on hover as a chevron fades in, and a click anywhere on the pill opens it (a tab that drops its `menu` while it's open closes it, so it never reopens on its own); for optical balance its right padding is 11px, selected or not, and 7px with the chevron, whose glyph carries 3px of air; a tab's `status` puts a 6px dot before its label (`StatusDot`: `live` blue or `problem` red, named in a `Tooltip`, never a green all-clear, §3b-19), and `indicator` takes a live spinner), `Spinner` (the one in-progress mark: a faint ring with a turning arc, 900ms a turn, still under reduced motion; `className` sets its size and colour, `currentColor` draws it; `label={AGENT_WORKING}` names it where the agent is working, otherwise it's hidden from screen readers beside the text it goes with), `Section` (hairline; collapsible with a chevron at the right, styled like the header actions: down when collapsed, up when open; `summary` shows a muted fact on the right of the header only while collapsed, part of the toggle; nest one inside another with `!px-0 !py-0 !border-b-0`), `ModeHeader` (a mode's 44px header in the card that hosts it: its title at 15px semibold, then any `actions` and a primary Done with Esc in its tooltip; Sculpt, Sketch, Import SVG, Print and a running Case), `SectionHeader`
- `TracePlot` (`traces`: `id`, `values`, `tone` `primary` | `muted` | `accent`): lines over time on one shared range, evenly spaced, on a `#262626` rounded field; no axes, ticks or legend, since the row it sits in and the figures beside it say what each line is. Light for what was measured, grey for a reference, the accent for the one that's yours. Each path carries `data-testid="trace-<id>"`; missing samples lift the pen; a trace longer than twice the plot's width is drawn as each column's low and high, so spikes survive; `loading` shimmers. Optional: `playhead` (a sample index, a white vertical line), `limit` (a dashed grey line, kept inside the range), `markers` (sample indices, red vertical lines for failures) and `onSeek` (press or drag maps x to the nearest sample). **Points mode:** a trace with `x` (values in data units) is placed by value on an x range shared by every trace with `x`, instead of by index; `points: true` draws each sample as a 4px round dot (`M x yh0` with round caps, so the stretched viewBox can't squash them). `fromZero` takes 0 into both ranges, and `units` (`{ x, y }`) labels the top of the y axis and the right end of the x axis with their value and unit, in 12px muted text inside the field; those two labels are the only axis marks. Peak torque's torque–speed plots use it (§8b). The calibration replay in Operate (§8k) and the try timeline (§8h) use it.
- `RowActions` (`fill`, `shown`): a row's hover controls, overlaid on its right end on a gradient of the row's `fill` (transparent → opaque over 32px), hidden and unclickable until the row (`group`) is hovered or focused; `shown` keeps them up, e.g. while their menu is open. Position it with `className`, as in Calibrate's rows, Build's notes and comment threads. A lone hover control without a row fill (a Parts tile's +) takes `REVEAL_ON_HOVER`, the same hidden-and-unclickable classes.
- `DisclosureRow` (`open`, `onToggle`, `disabled`): a list row that opens what's under it, the row's own content then a chevron that turns down when open; `disabled` drops the chevron and the click for a row with nothing under it. `className` sets its inset (`px-[7px]` by default). Build's checks, the BOM's groups and Peak torque's joints use it.
- `BrowseRow`: a 52px row that opens a narrower list in a sidebar view (title, a muted meta line, a chevron; `thumb` leads with a picture; `active` draws the highlighted search result's fill): Parts' categories, robot kinds and object categories.
- `DropOverlay` (`icon`, `label`): what a drop will do, while files are dragged over a card that takes them: a dashed accent frame 8px inside the card and a matte pill with the icon and a “Drop to …” label, never a list of the file types the person is already holding. The canvas (“Drop to import”, “Drop to add a reference image”) and the agent panel (“Drop to attach”) use it; a drop zone inside a panel (Import SVG's) takes the same accent border and fill instead.
- `Divider`: full-width hairline that cancels the container's `--pad-x` (§4)
- `MetaLine` (`items`, falsy ones skipped): a line of facts separated by 12px of space, never a glyph (§3b-16). The last item truncates. `SpecText` (`components/PartDetails.tsx`) renders a `SpecValue` list one fact per line.
- `FloatingIsland` + `IslandDivider`, `PopoverMenu` + `MenuItem` (`detail`: muted text on the right; `active`: the keyboard highlight, as in the composer's slash menu) / `MenuLabel` / `MenuDivider` / `MenuBack` (a chevron and the view's name at the top of a menu that has swapped to a sub-list, as in the composer's + → Commands; clicking it returns), `ContextMenu` (at least 240px, or its `minWidth`, as in the chat's 160px message menu; grows to fit its longest label + shortcut, up to 320px)
- `CODE_PANEL_TOKENS` (`codeTokens.ts`): the studio's greys (`--bc-bg`, `--bc-canvas`, `--bc-panel`, `--bc-raised`, `--bc-surface`, `--bc-line`), text (`--bc-ink`, `--bc-ink-2`, `--bc-ink-3`), the accent (`--bc-accent`, `--bc-accent-hover`), `--bc-red`, `--bc-green`, fonts (`--bc-font`, `--bc-mono`), type sizes (`--bc-text` 14px, `--bc-text-control` 13px, `--bc-text-small` 12px), `--bc-control` (32px), radii (`--bc-radius` 12px, `--bc-radius-control` 8px) and spacing (`--bc-gap`, `--bc-inset`), from `THEME_COLORS` and `LAYOUT`. A Case's code panels (§8h) get them as CSS variables, so code the agent writes can match the app without importing anything.
- `CURSORS` (`cursors.ts`): the canvas cursors (§12); `ARROW_PATH` is shared with `AgentCursor`.
- **Icons** are all our own (no icon dependency). Every one draws through `Glyph` (`glyph.tsx`): its strokes go into a mask and one `currentColor` rect is painted through it, so overlapping strokes never double up at translucent colours. Each takes `className`, `style` and `strokeWidth` (2 by default; Plus, Close and the chevrons are drawn at 2.5 through their spec's `weight`, since thin small controls read too light).
  - The UI library (`glyphs/`, about 100: `PlusIcon`, `CloseIcon`, `ChevronDownIcon`, `MoveIcon`, `SettingsIcon`, `UnionIcon`…) is generated from `tools/icons/library.mjs` by `npm run icons` (the sketch editor's tools and constraints, `RectangleIcon`, `ArcIcon`, `HorizontalIcon`, `VerticalIcon`, `ParallelIcon`, `PerpendicularIcon`, `EqualIcon`, `TangentIcon`, `CoincidentIcon`, are its `sketch` group in `tools/icons/sketch.mjs`); edit the drawings there, never the generated files. `node tools/icons/sheet.mjs <out.png>` renders the whole set.
  - View icons (`icons.tsx`): `PartsIcon`, `RobotsIcon`, `ObjectsIcon` (a bottle), `CasesIcon` (an isometric cube: Cases and the Play rail item; filled, the edges are knocked out), `RoutinesIcon` (a flowchart), `LibraryIcon`, `LayersIcon`, each `{ filled?, className? }` (outline idle, filled active); `DriveIcon` (`{ drive }`: a screw head with its solid Hex, Torx, Phillips, Pozidriv or slot recess; one state). Agent feed glyphs (`toolIcons.tsx`, one path each so they stay clean at `white/45`): `ShapeIcon`, `EditIcon`, `DeleteIcon`, `CodeIcon`, `LookIcon`, `CompareIcon`, `CheckIcon`, `SearchIcon`, `WebIcon`, `FileIcon`, `PhotoIcon`, `JointsIcon`, `PoseIcon`, `RunIcon`, `TrainIcon`, `CoachIcon` (a whistle), `ToolIcon`, `ThoughtIcon`. The UI reuses them where the idea is the same (`SearchIcon`, `LookIcon` for show, `DeleteIcon`, `EditIcon` for rename, `PhotoIcon`, `RunIcon` for play, `PoseIcon`). New icons follow the `icon-design` skill.
- `SpecRow` (`components/PartDetails.tsx`): the part page's label-left, value-right row (13px); used by part pages, the Inspector's Product section and `HardwareSpecs`. `SpecRows` is a component's Size and datasheet specs as those rows.
- `SceneTabs` (`src/components`): the scene tab strip (§5a)
- `ExportMenu` (`src/components`): the title bar's Export button and its format menu.
  - `PopoverMenu` anchors to its parent (the trigger's `relative` wrapper) but renders in a portal with fixed positioning, so docked panels with `overflow-hidden` never clip it. It flips to the other side when its preferred side has no room, stays 8px inside the window, and follows the trigger on resize and scroll. While any open dialog doesn't hold its trigger (`behindModal`, shared with `Tooltip`; a confirm stacked over a `Modal` covers that Modal's controls too), clicks and Esc go to the dialog and the popover stays open, so a menu row can ask with `confirmAction` (as the Scenes menu's Delete does) and the list is still there after. That holds for any open popover, not only one whose row opened the dialog.
- `Modal` (portal sheet; `headerActions` sit at the header's right). A sheet that does something takes an `action` (`label`, `onClick`, `disabled`, `tone: 'danger'`, `autoFocus` so Enter runs it, `form` to submit a form), and `Modal` draws its footer: a ghost Cancel (Esc) then the action, the same in every sheet. `footerStart` holds anything else at the footer's left (Import Robot's Choose Folder, a price's Delete Price). That sheet closes with Cancel, Esc or a backdrop click, and has no Close in its header: two controls for one job. Only a sheet without an action (`CodeBlock`'s Expand, Pair Phone) shows Close. `ConfirmDialog` (a small `Modal` with Cancel and a danger action, focused so Enter confirms), `Toast` (with action), `EmptyState`, `NoMatches` (the `EmptyState` every search shows when nothing matches, with an optional action such as Parts' Search All Parts), `Badge` (12px text on an 18px pill)
  - While any modal is open (`isModalOpen()`: an `aria-modal` element in the page), canvas shortcuts don't run and clicks don't dismiss what's under it (the comment card).
- `CodeBlock`: code with syntax colours (`utils/highlight.ts`: OpenSCAD, JavaScript/replicad, Python, shell; Xcode dark palette), Copy and Expand on hover; Expand opens the code in a wide `Modal` with line numbers and Copy. `Markdown` renders fenced code with it.
- `PreviewImage`: the thumbnail inside every `.preview` frame in the app's panels (Parts, its robots and objects, Library, hardware types, Scenes, the part and model heroes). `src` undefined shimmers, `''` stays empty, a URL shows the image, and an image that fails to load leaves the frame empty (`onError` lets a robot tile try its next source). `zoom` scales the image 6% while its `group` is hovered, at the 150ms hover speed (§4). Print plate thumbnails and the landing's robot strip are a plain `<img>`: they draw only once the image exists. Thumbnail hooks (`usePartThumbnail`, `usePartsThumbnail`, `useScenePreview`) return `''` when there's nothing to draw, so the frame never shimmers forever.
- `HoverCard`: rich details on hover (450ms delay; neighbours wait 220ms while warm so you can cross a tile to reach the card's links). `beside="aside"` opens it next to the panel instead of over the grid. It slides in from the panel (`animate-card-in`), is 320px wide, unpadded (content pads itself) and never taller than the window.
  - The Parts card (`CatalogDetails`, components only: hardware opens its page and has no tiles) previews the part page in its words: the hero (no badge), the name, the maker line (`makerSubtitle`) and the description, then the page's Key specs (`keySpecs`: Size across the card, the rest below), then a footer with Buy on Amazon and icon links, shown only when the part has links. Mounting stays on the part page; see [Layout](layout.md) §5.
- `useScrollFade(px?, axis?)`: returns `{ ref, style }` for a scroll container; fades top and bottom (left and right with `axis: 'x'`) only while content is hidden past them.
- Thumbnails (`three/partThumbnails.ts`) render at 480 × 360 with a studio environment map, so metals read on dark tiles; dark parts get more exposure.
- `ImageViewer`: full-window image viewer. Pinch or ⌘-scroll zooms at the pointer, two-finger scroll and drag pan, double-click toggles fit / 100%+, − + 0 keys, ← → and a filmstrip for several images, Esc or a backdrop click closes. Controls float in glass islands.
- Tokens in `theme.ts` (`THEME_COLORS`, `LAYOUT`, `DRAG_REGION`, `NO_DRAG_REGION`) mirror the `@theme` block in `index.css`.
