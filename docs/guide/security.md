# Security

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 0h. Security (mandatory)

The agent reads untrusted pages and files and drives an app that can spawn processes, so treat every input from the renderer, the HTTP bridge, the agent and downloaded assets as hostile. The full checklist, attack surface and accepted risks are in the `security-audit` skill; these rules hold for every change:

- **HTTP bridge:** every `/api/*` middleware is wrapped in `guardBridge` (`electron/bridgeGuard.mjs`: loopback `Host`, same-origin `Origin` and `Sec-Fetch-Site`). Vite plugin middlewares run before Vite's own host check and CORS, so nothing else protects them. A website could otherwise POST `/api/bridge/acp-connect` and run a command.
- **IPC** registers through `trustedIpc` (`electron/appOrigin.mjs`, main frame of the app origin only). Compare origins with `isAppUrl`, never `startsWith`; open only `isExternalWebUrl` links.
- **Ids that become paths** go through `checkedFileId` / `isSafeFileId` (or `safeFileId`) in `electron/backend/constants.mjs`. `library/agent.json` holds the command the app spawns.
- **Outbound fetches the agent controls** use `publicFetch` and `readCapped` (`electron/publicFetch.mjs`): public addresses only, every redirect re-checked, bodies capped. The renderer fetches agent URLs over https only.
- **Agent CLI downloads** (§0i) fetch only `https://registry.npmjs.org/` tarballs named in the build's manifest, refuse redirects, and install only when the sha512 matches the lockfile's `integrity`.
- **CAD files the agent downloads** (`electron/cadImport/`) are hostile: fetched by `publicFetch` with a 200 MB cap, parsed only in a forked process with `env: {}`; archives are capped at 600 MB unpacked and their entry names are never used as paths. Library ids go through `checkedFileId`. Links must be https. Page text from a link check is only searched for the part number, never shown to the agent as instructions. Open gap: the converter still runs under Node's permission model, which only a Node 25+ parent applies (Electron's Node is 24) and which isn't a boundary for hostile input anyway. Moving it into the kernel sandbox needs `cadImport/meshopt.mjs` and `partGlb.mjs` (shared with the parts pipeline) off `Buffer` first.
- **The CAD kernel** (agent-written OpenSCAD, and replicad run through `new Function`) runs only in a Chromium sandbox: a module Worker in a hidden `BrowserWindow` (`electron/cad-kernel/sandbox/`) with `sandbox: true`, no Node, context isolation, its own in-memory session (`basecase-kernel-sandbox`) and its own scheme (`basecase-kernel://kernel`).
  - The session cancels every request that isn't to that scheme (`webRequest`), denies every permission, download and device, and the protocol serves only `dist/kernel/` (bundle files by extension, no traversal, `bundleFile`) plus `/library.json`, BOSL2 and the robotics library read by the main process from `vendor/`.
  - CSP is default-deny: the page gets `'self'` scripts, `'wasm-unsafe-eval'` and `connect-src 'self'`; the worker, where agent code runs, gets `'unsafe-eval'` and `'wasm-unsafe-eval'` with `connect-src 'none'` and `worker-src 'none'`. The worker fetches nothing: the page compiles the WASM modules and hands them over with the libraries. Navigation, new windows and webviews are refused.
  - A Worker that ran replicad code is replaced before the next job, so no job inherits another's globals. Results come back as JSON bytes the main process never parses, matched to the job id, at most 64 MB.
  - The page talks to the main process only through its preload's four calls, on its own `webContents.ipc` behind `trustedIpc(…, KERNEL_ORIGIN)`; the app's IPC refuses it, and it refuses the app.
  - The MCP server (a separate Node process) never compiles: `cad-kernel/client.mjs` sends `kernel_render` / `kernel_audit` / `kernel_warm` over the token bridge, which is behind `guardBridge` too.
  - A sandbox that can't start answers every job with an error; nothing in the app falls back to Node. The Node host (`cad-kernel/nodeHost/`) is for tests, the bench and `tools/` only: the Vite middleware uses it only with `BASECASE_NODE_KERNEL=1`, and the packaged app doesn't ship it (`package.json` `build.files`).
  - `e2e/app/kernelSandbox.app.test.ts` runs agent-code probes (files, fetch, XHR, WebSocket, EventSource, beacons, `import()` from `file:` and `http:`, `process`, `require`, service workers, windows, other origins, the bridge) in the worker and the page against a local server that must see nothing; the canary runs the same probes on the Node host and must catch them.
- **Generated HTML** escapes every value (coerce numbers); the guide viewer strips scripts, handlers, links and non-image URLs. No `dangerouslySetInnerHTML`.
- **No `shell: true`**, no string `exec` with interpolated input, no TLS verification off outside the Bambu LAN connector.
- Every security fix gets a test that feeds it the exploit input (`electron/security.test.mjs`).
