## 8f. Printing: printers, plates, slicing and sending

Stage 5 of the loop (§1). The plan, findings and what's still unverified: [docs/Print plan.md](../../docs/Print%20plan.md). Nothing about a printer is hard-coded: the P1S is one catalog entry.

- **Printer catalog** (`src/data/printerCatalog.ts`, generated; types and helpers in `data/printers.ts`): 103 printers from two slicers' bundled machine profiles. Bambu Studio's (`bambulab/BambuStudio` at tag `v02.09.01.70`) give 93; OrcaSlicer's (`OrcaSlicer/OrcaSlicer` at `v2.5.0`) add the makers listed beside it in `tools/printers/import.mjs` (Prusa today: CORE One, CORE One L, their HF versions, MK4, MK4S, MK4S HF, MK3.5, MINI IS and XL), and Bambu Studio stays the source for any printer both have (the MINI and MK3S). Multi-tool printers (MMU, INDX, the XL 5T) stay out; the XL is its single-tool configuration. Each entry has its bed polygon, height, keep-out zones, nozzles, default plate type, `source` (the slicer and version it came from) and, for the 0.4 mm nozzle, the machine, default process, process presets by layer height and a filament preset per material (Prusa's FLEX counts as TPU). The importer (`tools/printers/catalog.mjs`) resolves `inherits` within a maker, reads presets in subfolders, and matches processes and filaments to the machine by `compatible_printers`, or by `compatible_printers_condition` when the list is empty (`condition.mjs` evaluates the `=~`, `!~`, `==`, `and`, `or` forms Prusa's profiles use). Regenerate with `node tools/printers/import.mjs`: it sparse-clones `resources/profiles` of both repos at the pinned tags into the system temp folder and rewrites the file; bump the tags there to update. Never edit the generated file by hand. Custom printers take a build volume.
- **My printers** (`library/printers.json`, `electron/print/printers.mjs`): app-wide, one default. On first launch the list is seeded from the printer selected in Bambu Studio (`BambuStudio.conf`), sending through Bambu Studio. Access codes and API keys are encrypted with `safeStorage` in `library/agent-config/printer-keys.json` (`AgentKeys` with `file`), never in the scene. A scene's `project.printer` resolves with `resolvePrinter` (a My printers id, a catalog id, or the default printer).
- **Plates** (`src/print/`): the analysis worker returns a printer-independent `PrintShape` per shape (poses: 6 axes plus up to 6 flat faces the part rests on, each with its rotation, footprint, overhang, support and contact). `choosePose` picks one for the bed (`bed.ts`: keep-outs, 90° turn, diagonal fallback); `pack.ts` packs per material with MaxRects around the keep-outs; `buildPrintPlan` returns plates with a matrix per item (part frame → 3MF bed frame, Z up) and a hash per plate. User choices live on the part (`ScenePart.print`: `down` face, `plate`, `at`, `turned`, `copies`, `skip`), so they undo like any edit.
- **3MF** (`print/threeMf.ts`, run in the analysis worker): one file per material, plates laid out on Bambu's plate grid (plate i at column × width × 1.2, row × −depth × 1.2, columns = ⌈√n⌉ rounded as Bambu does), plain 3MF core, names kept. Export ▸ 3MF Plates downloads them.
- **Slicing** (`electron/print/`: `slicers.mjs` finds Bambu Studio, OrcaSlicer, PrusaSlicer in `/Applications` on macOS and in Program Files or `%LOCALAPPDATA%\Programs` on Windows (`bambu-studio.exe`, `orca-slicer.exe`, `prusa-slicer-console.exe`, profiles in `resources\profiles`); `openFile` in `jobs.mjs` opens files with `open -a` or the slicer's exe; `slice.mjs`, `jobs.mjs`): each printer slices with the slicer its profiles came from (`slicerOrder` in `data/printers.ts`, carried in the job as `slicers`; `slicerFor` in `slicers.mjs` takes the first one installed): Bambu printers try Bambu Studio then OrcaSlicer, other Bambu Studio entries OrcaSlicer then Bambu Studio, and OrcaSlicer entries only OrcaSlicer. PrusaSlicer isn't a fallback for them: its presets are INI bundles with other names (“Original Prusa CORE One…”), so Orca's names don't map onto them. Sending a plate with no connection opens it in that same slicer. The CLI runs headless per material with **flattened** profiles (the CLI doesn't follow `inherits` for loaded files and falls back to a 200 × 200 × 100 plate), `--arrange 0`, infill and the printer's default plate type (`curr_bed_type`) written into the process. Results come from `result.json` and the sliced 3MF: time, grams, supports, warnings and the plate thumbnail per plate, cached per material by plate hash in `library/prints/<scene>/`. The CLI can't take per-object filaments with 3MF input and crashes on edited Bambu projects, so materials are separate jobs. `electron/print/slice.test.mjs` slices for real when Bambu Studio is installed.
- **Sending** (`electron/print/index.mjs`, connectors in `electron/print/connectors/`): Bambu Studio (default for Bambu printers: opens the sliced plates, where Print uses the user's own sign-in), Bambu Connect (URL scheme), Bambu LAN (Developer Mode: FTPS upload + MQTT `project_file`, live status, AMS trays), Moonraker, PrusaLink, OctoPrint (plain G-code pulled from the sliced 3MF). Find on Network reads Bambu SSDP and mDNS (`dns-sd` on macOS; on Windows a small `node:dgram` client, `connectors/mdns.mjs`, that sends one-shot queries from an ephemeral port so it never binds 5353). **Only the user starts a print**: Print Plate N opens a Start Print sheet (plate, material and AMS slot, Clear the bed); the agent's `slice_plates` never sends.
- **Print mode** (⌘P, File ▸ Print, Build ▸ Lay Out Plates, Lay Out Plates in the Build tab's Printing section, ⌘K): the canvas shows one plate (`three/plates/plateView.ts`, its own WebGL canvas while open; the scene viewport pauses) with the bed, its keep-outs and the parts in print orientation (shared geometry). Drag to move (saved as `at`), F Lay on Face, R Turn 90°, ←/→ plates, Esc closes. R and the panel's Turn 90° are one action (`printing.turnPart`, from `turnedPrint` in `print/plan.ts`): the part turns where it sits, saving its spot as `at` with `turned`, since a part without `at` is packed loose and the packer picks its own turn. The Print panel replaces the inspector and holds everything about printing; the Build tab shows only the plate count and total time (§8b). The panel: Printer (with Skip N printed parts once something is printed), the selected part (Lay on Face, Turn 90°, Plate, Copies, Don't print), the plate (thumbnail when sliced, its state, warnings, Send / Print Plate N, Open in Bambu Studio, Mark Printed / Failed) and **Parts** (`PrintedSection`, collapsed with its count: per-part size, time, plate and issues, parts with issues first, copies as “2 ×” before the name; a click selects the part on its plate), with Done (Esc) in its header. With no saved printer the plate's primary button is Add Printer, which opens Settings ▸ Printers (the web demo, which can't save printers, shows none); the section is called Parts, not Printed parts, because Skip N printed parts already uses “printed” for parts that came off the printer. Slicing every plate at once is ⌘K ▸ Slice Plates; Send slices a plate that isn't. Either way a progress toast with Stop follows the slice wherever you are and turns into the result or the error; the plate section shows the progress with Stop too, and keeps the error. The bottom bar is the only plate list (each plate's number and material) and holds Auto Arrange; it has no close button, since Done, Esc and ⌘P already close.
- **Prints tracker** (`print/tracker.ts`, `project.prints`): a record per plate sent (parts with their shape keys, printer, state from live status or marked by hand). A part counts as printed while its shape is unchanged, and Skip N printed parts (on by default) leaves those parts off the plates, so editing one bracket after printing gives a plate with just that bracket.
