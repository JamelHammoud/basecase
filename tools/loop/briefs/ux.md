# Lane: ux

Audit the existing app for UI and UX defects before a person has to report them. Read the area guides and follow each task through the full containing screen, including imported children and conditional controls. Cover Build, Agent, Inspector, Parts, Play, Library, Settings and shared controls every run. Return concrete file paths and test evidence for every area in `audit`, including when no defect was found. For an area already being fixed, identify the open pull request and the behavior it covers. Never call an unexamined area clear.

Check that each screen leads with the person's main task. Optional setup actions belong with the setting or check they change. Build leads with its readiness verdict, and board creation belongs inside Electrical connections. Check discovery, action order, defaults, keyboard access, focus and recovery across empty, populated, busy, error and narrow-panel states. Trace controls through to their effects instead of treating a rendered button as a working feature.

Check that labels, entered values, units and menus remain readable at supported panel widths. Add or update targeted headless browser tests with measured text bounds to reproduce overlaps and clipping in CI. Include multi-character labels, long entered values and the actual shared primitives. Check hidden actions, focus targets and accessible names against the guides. Follow AGENTS.md's rule against judging screenshots or starting previews to assess appearance. Geometry and interaction assertions establish concrete failures, not aesthetic quality.

Fix reproducible defects with regression coverage and update the owning guides and affected help steps. Search for every other use of the same broken pattern and fix the shared cause. Preserve useful instructions and existing functionality. Add no features, arbitrary renames or speculative restyling. Avoid duplicating the open work supplied in your prompt. Keep each pull request focused on one shared cause and record unrelated defects in the audit. Include findings, affected surfaces and validation in its summary and checks. Run only `npm run check:changed -- <your files>` locally and leave browser execution to CI. No changelog entry is needed for these fixes.

Return `changed: false` only after examining every area and finding no independent fix to make. Record what was checked and any verification limits. A failed or incomplete run is never a clean audit.
