# Printing

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 8f. Printing: printers, plates, slicing and sending

Stage 5 of the loop (§1). The plan, findings and what's still unverified: [docs/Print plan.md](../../docs/Print%20plan.md). Nothing about a printer is hard-coded: the P1S is one catalog entry.

- **Printer catalog** (`src/data/printerCatalog.ts`, generated; types and helpers in `data/printers.ts`): 103 printers from two slicers' bundled machine profiles. Bambu Studio's (`bambulab/BambuStudio` at tag `v02.09.01.70`) give 93; OrcaSlicer's (`OrcaSlicer/OrcaSlicer` at `v2.5.0`) add the makers listed beside it in `tools/printers/import.mjs` (Prusa today: CORE One, CORE One L, their HF versions, MK4, MK4S, MK4S HF, MK3.5, MINI IS and XL), and Bambu Studio stays the source for any printer both have (the MINI and MK3S). Multi-tool printers (MMU, INDX, the XL 5T) stay out; the XL is its single-tool configuration. Each entry has its bed polygon, height, keep-out zones, nozzles, default plate type, `source` (the slicer and version it came from) and, for the 0.4 mm nozzle, the machine, default process, process presets by layer height and a filament preset per material (Prusa's FLEX counts as TPU). The importer (`tools/printers/catalog.mjs`) resolves `inherits` within a maker, reads presets in subfolders, and matches processes and filaments to the machine by `compatible_printers`, or by `compatible_printers_condition` when the list is empty (`condition.mjs` evaluates the `=~`, `!~`, `==`, `and`, `or` forms Prusa's profiles use). Regenerate with `node tools/printers/import.mjs`: it sparse-clones `resources/profiles` of both repos at the pinned tags into the system temp folder and rewrites the file; bump the tags there to update. Never edit the generated file by hand. Custom printers take a build volume.
- **My printers** (`library/printers.json`, `electron/print/printers.mjs`): app-wide, one default. On first launch the list is seeded from the printer selected in Bambu Studio (`BambuStudio.conf`), sending through Bambu Studio. Access codes and API keys are encrypted with `safeStorage` in `library/agent-config/printer-keys.json` (`AgentKeys` with `file`), never in the scene. A scene's `project.printer` resolves with `resolvePrinter` (a My printers id, a catalog id, or the default printer).
- **Plates** (`src/print/`): the analysis worker returns a printer-independent `PrintShape` per shape (poses: 6 axes plus up to 6 flat faces the part rests on, each with its rotation, footprint, overhang, support and contact). `choosePose` picks one for the bed (`bed.ts`: keep-outs, 90° turn, diagonal fallback); `pack.ts` packs per material with MaxRects around the keep-outs, scanning free rectangles once for both orientations through `packSpot.ts` and allocating only the selected spot. Diagonal bed fitting (`bedProjection.ts`) prepares keep-out polygons once per fit and shares each polygon’s own axis projections across comparisons. Projections are calculated on first use, preserve the 0.000001 tolerance and end with the fit. Printer selection, fleet eligibility and Merge use this same bed-fit path; `buildPrintPlan` returns plates with a matrix per item (part frame → 3MF bed frame, Z up) and a hash per plate. User choices live on the part (`ScenePart.print`: `down` face, `plate`, `at`, `turned`, `copies`, `skip`), so they undo like any edit. **Plates follow the build order**: each part's `firstStep` is the index of the first guide step that uses it (`guideStepParts` in `guide/guideSteps.ts`): the steps the build guide record saved (`BuildGuideRecord.stepParts`) while their fingerprint matches the scene, otherwise `buildGuidePlan` on the approximate scene, the planner the guide and Merge use. Every report builder reads the whole scene for it (`PrintContext.scene`), so skipping printed parts doesn't renumber steps. Within a material the packer takes loose parts by step (after parts pinned to a plate), then by area; parts no step uses start at the last plate the stepped parts reached, so they never push an early step back. Plates are then numbered across materials by their earliest step (`Plate.step`), ties in material order; with no steps at all the packing is the old area-first one. Placed parts (`at`) stay put, and hashes depend only on what's on a plate, so an unchanged scene gives byte-identical plates.
- **Printer obstacles** (`tools/printers/obstacles.mjs`, `print/bed.ts`): the pinned [OrcaSlicer 2.5.0 schema](https://github.com/OrcaSlicer/OrcaSlicer/blob/v2.5.0/src/libslic3r/PrintConfig.cpp#L1063) stores `bed_exclude_volumes` as `XxY` polygon points, with optional `ZMIN..ZMAX;` prefixes and `|` or newline separators. Import follows machine inheritance and preserves each polygon and height range. Only shared volumes are supported. Active toolhead-offset or per-extruder volumes, malformed polygons, ranges or clearances return an unsupported fit result. The conservative envelope reserves every obstacle's bounding rectangle for the whole print height, expanded on every side by the larger of `extruder_clearance_radius` and `extruder_clearance_dist_to_rod`. The toolhead's `extruder_clearance_height_to_rod` is retained, but does not relax the envelope for low clips or elevated docks. This can refuse placements a slicer could accept. Selected process presets reserve brim width plus object gap at bed edges and around obstacles. Automatic brims, including profiles without an explicit brim type, reserve the pinned [Orca brim generator](https://github.com/OrcaSlicer/OrcaSlicer/blob/v2.5.0/src/libslic3r/Brim.cpp)'s 18 mm upper bound plus object gap, because automatic width ignores the configured brim width. Explicit no-brim presets reserve none. Default-process brim settings apply when no matching process is selected. Import leaves profiles without obstacle volumes unchanged. Regenerating the current catalog produces identical entries because none of its supported machine profiles supplies these volumes.
- **Obstacle consistency**: automatic packing, 90° turns, diagonal fitting, saved manual positions, Print dragging, fleet fitting, Checks and exported matrices share the bed envelope. Boundary contact is accepted within the existing 0.000001 mm tolerance. A refused drag restores the original placement. A saved unsafe position or turn fails fit and leaves the part off exported plates until Auto Arrange clears its placement. Auto Arrange includes the active material and off-plate parts of every material. When no plates remain, it clears placement for every reported part. Plate hashes, readiness fingerprints, fleet identity and Merge invalidate when obstacle geometry, height metadata, toolhead clearance or selected brim changes. This checks placement envelopes, not every slicer travel move. Fast importer tests cover profile parsing and inheritance. `src/print/obstacles.test.ts` covers automatic and fixed placement, rotated extents, brim clearance, unsupported geometry, exported transforms and hash invalidation. `e2e/printPlacement.e2e.test.ts` opens Print with its shortcut, saves a clear drag, refuses a drop into the P1S bed exclusion and recovers unsafe saved positions with Auto Arrange, both with no plates and with another material still on a plate. It uses one box and the existing printer catalog. `e2e/print.e2e.test.ts` retains Print shortcut, panel and fleet coverage.
- **Sheet parts** (`ScenePart.sheet`, `utils/bom.ts`): aluminum 6061, carbon fiber and acrylic leave print-shape analysis, filament estimates, service print quotes and printer plates. The legacy CNC Aluminum and Laser-Cut Acrylic/Carbon tags follow the same rule. They remain in the scene and in the BOM’s Sheet section, grouped by material and stock thickness (§8b).
- **Orientation scoring** (`three/printability.ts`): the six axis poses and additional resting faces share one triangle pass for normals, areas and centroids. Each pose retains its own bed height, contact, overhang and support totals. The scorer keeps one triangle workspace, one support ray per batch and one accumulator per candidate, without storing a triangle cache. The support ray copies each centroid and direction before applying the 0.001 mm offset. Wall-thickness sampling owns a separate ray, and later batches allocate fresh workspaces. `analysis/shapeReports.ts` batches uncached requested faces through the same scorer, retaining rounded cache keys, the first direction for each key and request order. Single manual faces and fit coupons use a one-candidate batch. Angle limits, the 0.3 mm contact threshold, support-ray offset and candidate order stay unchanged.
- **Orientation feeds strength** (§8b): layers bond more weakly than a line of plastic, so the face a part prints on decides how strong it is. Strength in Checks grades a part at its chosen face (`print.down`, or the pick above) and at every other candidate, and its Fix sets the strongest face. Best Face in Print mode returns to the pick above, which only weighs support and contact.
- **3MF** (`print/threeMf.ts`, run in the analysis worker): one file per material, plates laid out on Bambu's plate grid (plate i at column × width × 1.2, row × −depth × 1.2, columns = ⌈√n⌉ rounded as Bambu does), plain 3MF core, names kept. Export ▸ 3MF Plates downloads them. Open in Bambu Studio uses the same writer’s project mode when the current print scope has more than one material. `projectJobSpec` keeps the plan’s global plate numbers, names, matrices and copy names, assigns one-based filament indices and writes one unsliced archive in the analysis worker. `Metadata/model_settings.config` carries object names, extruders and plate instance membership. `Metadata/project_settings.config` carries the printer and process selection, bed, nozzle, infill, filament preset names, types and colors. Loaded AMS trays from the saved printer’s status order the matching materials by slot, with external spool 254 excluded, then append the remaining materials in plan order. Tray colors lose their alpha byte, and materials without a tray use `#EEEEEE`. Project ZIP entries have a fixed 1980 timestamp for deterministic bytes. Plate mode keeps its previous bytes. The project uses `Application=BambuStudio-02.00.00.00` because [Bambu’s importer](https://github.com/bambulab/BambuStudio/blob/v02.09.01.70/src/libslic3r/Format/bbs_3mf.cpp) refuses project settings unless this metadata starts with `BambuStudio-` and parses as a version. Every filament has a `filament_is_support` entry, required by the CLI’s project loader. `electron/print/project.test.mjs` loads and exports the archive with an installed Bambu Studio and verifies the returned assignments and plates. Before opening with an installed slicer, `electron/print/projectThread.mjs` resolves inherited machine, process and filament profiles through the existing profile reader and embeds their actual settings, including one value per filament. Preset names alone leave the importer using generic defaults. The project also records the infill, bed, nozzle and color overrides in `different_settings_to_system`, so the GUI keeps them when matching installed presets. Archive inflation, settings resolution and compression run in a worker thread, with a 512 MiB compressed and expanded limit, at most 10,000 entries, at most 1 MiB of project settings and 16 filament presets. Model entries remain unchanged, and the project opens without a CLI rewrite. Single-material Open, Export ▸ 3MF Plates, slicing and Send keep their per-material path.
- **Slicing** (`electron/print/`: `slicers.mjs` finds Bambu Studio, OrcaSlicer, PrusaSlicer in `/Applications` on macOS and in Program Files or `%LOCALAPPDATA%\Programs` on Windows (`bambu-studio.exe`, `orca-slicer.exe`, `prusa-slicer-console.exe`, profiles in `resources\profiles`); `openFile` in `jobs.mjs` opens files with `open -a` or the slicer's exe; `slice.mjs`, `jobs.mjs`): each printer slices with the slicer its profiles came from (`slicerOrder` in `data/printers.ts`, carried in the job as `slicers`; `slicerFor` in `slicers.mjs` takes the first one installed): Bambu printers try Bambu Studio then OrcaSlicer, other Bambu Studio entries OrcaSlicer then Bambu Studio, and OrcaSlicer entries only OrcaSlicer. PrusaSlicer isn't a fallback for them: its presets are INI bundles with other names (“Original Prusa CORE One…”), so Orca's names don't map onto them. Sending a plate with no connection opens it in that same slicer. The CLI runs headless per material with **flattened** profiles (the CLI doesn't follow `inherits` for loaded files and falls back to a 200 × 200 × 100 plate), `--arrange 0`, infill and the printer's default plate type (`curr_bed_type`) written into the process. Results come from `result.json` and the sliced 3MF: time, grams, supports, warnings and the plate thumbnail per plate, cached per material by plate hash in `library/prints/<scene>/`. The slicing CLI can't take per-object filaments with 3MF input and crashes on edited Bambu projects, so slicing keeps materials in separate jobs. Multi-material Open hands the unsliced project directly to the slicer’s GUI. `electron/print/slice.test.mjs` slices for real when Bambu Studio is installed.
- **Slice lookups** (`print/slices.ts`): `sliceLookup` indexes each current slice list by hash and plate number once. Print mode, the Build plate summary and fleet sending share the lookup through `usePrintJob`. Build-time estimates use the same index with finite, nonnegative duration validation. Duplicate keys retain the first accepted record, and changed slices rebuild the index. Label freshness still comes from `currentSlices`. `slices.test.ts` checks duplicate and missing keys, zero and nonfinite durations, stale labels, replacement records and source preservation. Its 300- and 600-plate fixtures reduce saved plate-number reads from 45,150 and 180,300 to 300 and 600. These are operation counts without timing assertions or a claim about complete printing time.
- **Build time budget** (§8b): Checks uses the same `printReport` estimates and plate hashes as Print mode. A matching sliced plate supplies its seconds instead of its estimated hours, leaving unsliced and off-plate parts estimated. Both Checks and `verify_design` read `job.slices`, filtered by `currentSlices` against the current label key, as Print mode does. Changes to plate placement or rotation, nozzle, bed geometry and saved guide steps invalidate readiness too. Only the count in My printers divides the print share, with at least one counted. Printer assignment, availability, delivery and service lead times are not part of that estimate. Assembly and servo setup are added by `utils/engineeringTime.ts`.
- **Sending** (`electron/print/index.mjs`, connectors in `electron/print/connectors/`): Bambu Studio (default for Bambu printers: opens the sliced plates, where Print uses the user's own sign-in), Bambu Connect (URL scheme), Bambu LAN (Developer Mode: FTPS upload + MQTT `project_file`, live status, AMS trays), Moonraker, PrusaLink, OctoPrint (plain G-code pulled from the sliced 3MF). Find on Network reads Bambu SSDP and mDNS (`dns-sd` on macOS; on Windows a small `node:dgram` client, `connectors/mdns.mjs`, that sends one-shot queries from an ephemeral port so it never binds 5353). **Only the user starts a print**: Print Plate N opens a Start Print sheet: the plate's time and grams, one line that names the material with what to load or the AMS slot it prints from, and Clear the bed; the agent's `slice_plates` never sends.
- **Print mode** (⌘P, and Print in the File menu, the Build tab's Printing section and ⌘K: one name wherever it opens): the canvas shows one plate (`three/plates/plateView.ts`, its own WebGL canvas while open; the scene viewport pauses) with the bed, its keep-outs and the parts in print orientation (shared geometry). Drag to move (saved as `at`), F Lay on Face, R Turn 90°, ←/→ plates, Esc closes. R and the panel's Turn 90° are one action (`printing.turnPart`, from `turnedPrint` in `print/plan.ts`): the part turns where it sits, saving its spot as `at` with `turned`, since a part without `at` is packed loose and the packer picks its own turn. The Print panel replaces the inspector and holds everything about printing; the Build tab shows only the plate count and total time (§8b). The panel: Print Fit Test beside Done in its header (below), Printer (with Label parts, and Skip N printed parts once something is printed), the selected part (Lay on Face, Turn 90°, Plate, Copies, Don't print, Don't label), the plate (thumbnail when sliced, its state, warnings, Send / Print Plate N, Open in Bambu Studio, Mark Printed / Failed) and **Parts** (`PrintedSection`, collapsed with its count: per-part size, time, plate and issues, parts with issues first, copies as “2 ×” before the name; a click selects the part on its plate), with Done (Esc) in its header. With no saved printer the plate's primary button is Add Printer, which opens Settings ▸ Printers (the web demo, which can't save printers, shows none); the section is called Parts, not Printed parts, because Skip N printed parts already uses “printed” for parts that came off the printer. Slicing every plate at once is ⌘K ▸ Slice Plates; Send slices a plate that isn't. Either way a progress toast with Stop follows the slice wherever you are and turns into the result or the error; the plate section shows the progress with Stop too, and keeps the error. The bottom bar is the only plate list (each plate's number, material and, with Build Along's icon, the guide step it's first needed at, counted as Build Along counts) and holds Auto Arrange; it has no close button, since Done, Esc and ⌘P already close.
- Named print buttons show only their shortcut in tooltips: Esc on Done, F on Lay on Face and R on Turn 90°.
- **Fit test** (`print/fitTest.ts`, `three/analysis/fitCoupons.ts`, `workspace/useFitTest.ts`): Print Fit Test (in the Print panel's header and ⌘K, offered while the scene has a printed part and a fit) plates small coupons cut from the design, so a tight pocket shows up in a short print, not after the full plate. Fits are grouped by kind and spec (`fitKey`): a heat insert by its size, length and outer diameter, a servo or motor pocket by catalog component, a bearing seat by bearing type and size, a screw clearance by size. For the first instance of each group with a host, the analysis worker (task `fitCoupons`, rest pose) finds the printed part that holds it (its surface within 0.5 mm of the bought part's box, or the box's centre inside it; the largest box overlap wins) and intersects that host with the bought part's own box plus a 4 mm wall (`FIT_WALL_MM`, three-bvh-csg). Host selection retains the largest qualifying overlap during one scan, checking a candidate’s mesh only when its overlap can beat the current host. Equal overlaps keep the first host in task order. Each coupon keeps its host's chosen print pose (`down` from the design's plan) and goes through the same `reportFromShapes` → `buildPrintPlan` path as any part, so the plate packs, slices and sends as usual; its 3MF is written from the coupons' own triangles (`useFitTest`'s `threeMf`), and its slices go to their own job (`<scene>-fit-test`), so the design's cached slices stay. The plate is temporary: the coupons are `sculpt_mesh` parts that exist only while it's open, never in the scene; you can't move them, Auto Arrange and Mark Printed are hidden, and sending one records no print. The panel's header reads Print Fit Test, and Done or Esc returns to the design's plates.
- **Merge** (`print/merge/`, `workspace/useMerges.ts`, `print/MergeSection.tsx`): while Print mode is open, the analysis worker plans which printed parts could print as one. It runs inside the `assembly` task (`AssemblyGeometryInput.merges`, `mergeInput` builds it on the main thread), after the assembly geometry, on the same placed solids. Candidates are visible printed parts not set to Don't print; a pair is joined when a screw chain (`clampedBy`: its stack, a printed or catalog part it threads into, or the host of its insert) clamps only candidates of one rigid link (`buildRig`'s owner, or none) and one material, and their meshes are within 0.5 mm. Connected groups use the shared iterative `componentRoot` lookup and append members without copying each growing group. Each connected group passes three checks, in order: the removal plan with the group as one part (`mergedGeometry` folds the members' moves, renames them in chains and drivers, and drops the joining hardware) has no part that came out alone but now only comes out sealed in a unit with it (`seals`), and nothing newly stuck (`stuck`); then the union, members' triangles in world space minus faces lying on another member (0.05 mm), fits the bed in some pose (`choosePose`) with no more than 2 cm³ of support beyond the members printed apart (`NEW_SUPPORT_MM3`). A group that fails tries its connected subsets, largest first and in id order (64 tries at most), and names each part left out with the reason it fails when added back. Subsets use the shared lazy `utils/combinations.ts` traversal, retaining one index array and copying only yielded candidates without changing search order or the try limit. Planning stops taking new groups after 10 s. The kept part has the most joint references, then the largest box; the joining hardware is every screw whose clamped parts are all members, with its inserts, nuts and washers. Steps saved come from the guide planner (`buildGuidePlan` on the approximate scene, members replaced by their union box), so the press-in step of removed inserts counts too. Each group is a row in the Print panel's Merge section, with what it saves (parts, screws, steps), its left-out parts and **Merge**; ⌘K lists Merge ⟨names⟩ for each row while Print mode is open. Merge plans again on the current scene, unions the members through the editable boolean path (`booleanPart`, the kept part's id and material, operands stay editable) and removes the joining hardware in one `commitParts`, so one undo restores everything. The BOM, Checks, plates and the guide follow from the scene. On the 81-part quadruped fixture (`merge.fixtures.ts`) the worker task takes about 0.6 s on an M-series Mac, 0.2 s of it planning; `mergePlan.perf.test.ts` holds it under 2 s, run on demand with `npm run perf:booleans`.
- **Made by a Service** (`electron/print/services/`, `src/print/serviceQuotes.ts`, `workspace/useServiceQuotes.ts`; desktop only): the Printer menu's last choice before Add Printer, for people with no printer. It needs a Slant 3D API key in Settings ▸ Accounts (`print-service-keys.json` beside the other keys in `library/agent-config/`, sealed with `safeStorage`, never in the scene); with none, choosing it opens that pane, as Add Printer opens Printers. Choosing it sets `project.madeBy`, and choosing a printer clears it. While it's chosen and the Build tab or Print mode is open, every printed part without a current quote is quoted 1.5 s after the scene settles: the analysis worker writes its STL in the pose the plates give it (`posedStl`, task `partStls`; a part on no plate stands Z up as it sits in the scene), and the main process uploads each one through Slant 3D's V2 API (`https://slant3dapi.com/v2/api`, spec at `/v2/api/openapi.json`): `POST /files/direct-upload`, a `PUT` of the STL to the address it returns, `POST /files/confirm-upload`, then `POST /files/<id>/estimate` with the filament and `quantity` set to the part's copies, so two copies upload once. The platform is the account's first (one named Basecase is made when there's none), and the filament is the first available black filament of the part's material (PLA or PETG) from `GET /filaments`, else the first of any color. Slant 3D prints PLA and PETG only, so an ABS, ASA or TPU part is listed as “Slant 3D doesn't print ABS. Set its material to PLA or PETG.” with no request. Its estimate takes no infill (it prints at its own settings), so infill doesn't requote; a part's shape, chosen face, material and copies do (`quoteKey`). A part the service refuses (one too large for its build volume, say) is listed with Slant 3D's reply, not priced. The estimate has no lead time. `useServiceQuotes` runs one round at a time, of at most 200 parts (`QUOTES_PER_ROUND`, the main process's `MAX_SHAPES` cap); when a round ends, the next one asks for whatever is still without a current quote, so the rest of a large scene and a part edited during the round go next. One part's failure (an unreadable reply, a failed upload) skips only that part, and the round keeps every price it got; a failure every part would share (a refused key, a timeout or lost connection, the service down) stops the round there. When any part of a round goes unanswered, quoting waits 60 s (`RETRY_MS`) and then asks again, so the errors end on “Basecase asks again in a minute”, and a key fixed in Settings ▸ Accounts is used on that round; choosing Made by a Service again asks at once. An error shows as a toast once, and the same error again stays quiet. The plates, slicing and Checks stay as they are, so a printability blocker keeps its row. Quotes land in the BOM's Printed parts section (§8b). Slant 3D was picked because its V2 API publishes an OpenAPI spec with a per-file estimate endpoint, priced from the uploaded STL. `electron/print/services/slant3d.test.mjs` runs against a recorded fake service (`testService.mjs`), which e2e also serves through `BASECASE_PRINT_SERVICE_URL`.
- **Labels** (`print/labels/`, `workspace/usePlateWriter.ts`, `three/analysis/plateFiles.ts`): each printed part gets its build guide letter debossed on a face nobody sees once the robot is built, in the plate's mesh only; the scene, Checks, the BOM, shape keys and plate hashes never change. Label parts under Printer in the Print panel (`project.labelParts`, on unless turned off) and Don't label on a selected part (`PartPrint.noLabel`) decide which parts get one. The letters are the guide's own: `usePlateWriter` asks `useBuildGuide.currentPlan` for the plan (the one Build Along reads; an out-of-date guide is made first) and `partLetters` maps each printed item's parts to its label, so the PDF, Build Along and the parts agree. Writing plates with letters snapshots every visible solid at rest, and the analysis worker's `plateFiles` picks a face per part (`pickLabel`): the flat faces (connected coplanar triangles, largest first, 16 at most) that don't face the bed (normal · down ≤ 0.7, down read from the plate item's matrix), fit the letters (`fitLabel`: cap height 4–10 mm, strokes 0.8–1.4 mm, a 0.8 mm wall to every edge of the face, so a label is shrunk or skipped, never clipped), keep 1.2 mm of plastic behind the label, have no sample within 1.5 mm of another part (the guide's contact distance), and let no ray out from any sample in 96 directions (hidden). Label fitting tries the centroid before building its 81-point fallback grid, then checks each sorted grid center only when the search reaches it. A full-size fit stops further center checks, preserving centroid priority, grid order, orientation ties and height trials. All labeled plate files share this search. Label fitting prepares boundary origins and directions once per face in `labelBoundary.ts`, sharing one clipping range across both orientations and every size trial. Preparation uses double precision, preserves touching-edge rejection and ends with the fit. Contact and visibility checks share each candidate face’s 40 seeded samples and label-grid points after one transform to world space. `labelSamples.ts` selects each seeded triangle with the shared cumulative-area binary lookup in `utils/surfaceSampleIndex.ts`, preserving the first matching area boundary and sample coordinates. Edge midpoints join only the contact check, and samples live only for that face evaluation. Coplanar plane buckets accumulate triangle areas during their first geometry pass in `labelFaces.ts`, so the minimum-area prefilter needs no second measurement pass. Connected faces still receive their own area check after grouping, preserving disconnected-face rejection and candidate order. Coplanar face components use the same path-compressing lookup as Merge, with triangle lists built by appending. The first that clears gets the letter, centred, 0.4 mm deep: strokes of the built-in single-stroke font (`labelFont.ts`, A–Z) as prisms, subtracted with Manifold (`manifoldRun`, which says whether the kernel or which operand failed). A part with no such face, or a mesh Manifold can't take, prints plain, and its row in Parts says why in amber; when the Manifold kernel itself won't load, writing the plates fails with an error instead, since no part's mesh is at fault. Slices carry a labels key (`labelsKey`: the guide fingerprint and the Don't label parts) in the job and the slice record, so a plate sliced before its letters could change is sliced again (`freshSlice`, `groupHash` in `electron/print/jobs.mjs`). The key in the job is the one the plates were written with (`lettersToWrite`): when the guide plan can't be made (Stop on the guide card, a failed guide, another scene opening), the plates are written plain and keyed empty, so they're sliced again once the guide is made. Fit test plates are never labeled. Labeling the 81-part quadruped fixture's plates adds about 0.05 s in the worker on an M-series Mac (none of its 13 printed parts has a hidden face), and the lidded tray fixture's letter about 0.03 s; `partLabels.perf.test.ts` holds the quadruped under 2 s, run on demand with `npm run perf:booleans`.
- **Every printer you own** (`print/fleet.ts`, `workspace/usePrintFleet.ts`, `print/PrinterFleet.tsx`): `usePrintStatus` polls every My printers entry with a live connection (not Bambu Studio) while Print mode is open or a print is sending, plus any printer with a plate out, and moves each printer's open record from its own status. With two or more such printers, the Printer section lists them, each with its state, and an idle one gets **Start Next**: the lowest-numbered plate that isn't sent, printing or printed (`nextPlate`) among the plates offered to it. A plate is offered to a printer whose bed holds its footprint and height without a turn (`spotOn`; the scene printer's own bed always does) and whose loaded filament, when the connector reports it (Bambu's AMS and external trays), starts with the plate's material. Start Next opens the same Start Print sheet; nothing starts on its own, and Start Next waits while a plate is slicing or sending, so two printers pressed in turn get different plates. A printer with the scene printer's bed and nozzle sends from the scene's own slices; any other moves the plate onto its bed (`plateOnBed`), slices it with its own profile in its own job (`<scene>-<printer id>`), then sends through its connector. Hidden in the web demo and in a fit test.
- **Prints tracker** (`print/tracker.ts`, `project.prints`): a record per plate sent (parts with their shape keys, printer, state from live status or marked by hand). A part counts as printed while its shape is unchanged, and Skip N printed parts (on by default) leaves those parts off the plates, so editing one bracket after printing gives a plate with just that bracket. `plateStatusLookup` sorts the history once per status batch and indexes the newest record by plate hash and each pending replacement by part id. Print mode, manual plate marking, fleet Start Next and the printing test hook share the lookup from `usePrinting`. Timestamp ties retain source order, and a newer pending replacement overrides a matching plate record only until the part is printed again. The lookup is rebuilt from current records, without a persistent cache (§0f). Queries visit only the plate’s items, preserving record identity and cancelled states. [Measurements and limits](../notes/performance-printing.md#plate-statuses-share-prepared-print-history).

- **Repair plates** (§8b): a valid printed repair records a `reprint` event in `project.prints`, preserving the old records and invalidating only that part's printed key. It survives save and reload. A later successful print clears the pending replacement. Print at Build Along's swap step scopes the existing report, packer, writer and send path to one copy of that part (`repairPrintParts`). The scoped copy ignores saved skip, copies and fixed plate placement, retains its print face and label choice, and disables merge suggestions. Face, rotation, placement and label edits apply to temporary repair settings. Copies and skip controls stay hidden, and closing Print discards these edits. No saved part settings change. The report stays empty until the matching scoped worker result returns, so an old full-scene plate cannot be sent during recalculation. Closing Print, opening normal Print or changing scenes clears the scope. Nothing starts a printer automatically.

### Plates in a manufacturing kit

Export ▸ Kit uses `printReportOf`, `jobSpec`, `lettersToWrite` and the viewport's worker-backed `printThreeMf`. The fresh guide supplies assembly order and printed labels. Parts marked printed remain in the full kit. A skipped or missing output stops export. Per-material 3MF references retain plate numbers and copy counts. Extra copies get unassigned packing demand without inventing assembly instances. BOM filament quantities account for all print copies and support material. Sheet parts use the existing DXF exporter and remain outside printed plates. Kits contain geometry, not sliced G-code.

Reconciliation, provenance serialization, sheet writing and compression run in the kit worker. Plate buffers transfer to it and the compressed buffer transfers back. Browser worker failure refuses compression on the interaction thread. Source geometry is bounded before preparation, and expanded archive contents are capped at 256 MB. [Measurements and limits](../notes/performance-printing.md#manufacturing-kit-composition) include the illustrated-guide boundary.

Guide visibility probes retain a separate small ID render target. They no longer discard full-page normal, ID, color and depth buffers between guide drawings. The three drawing textures share one multiple-attachment render target and depth buffer, so each part is drawn once for normal, ID and color output. Both drawing and visibility targets are disposed with the guide renderer. Composite drawing uses fixed neighbor directions and omits the second radius’s diagonal samples, which nearest-neighbor filtering maps onto the first radius’s diagonal texels. The twelve retained samples preserve the original order and strongest-edge choice. `guide/render/guideStage.test.ts` runs real worker WebGL drawing and probes, checking PNG byte equality against the previous three-pass renderer and shader on rotated geometry and ghosted overlaps from three views, repeatable visibility counts and no page-target disposals between equal-sized drawings. The same test checks fewer geometry draw calls and refusal of a failed shader. Kit guides use a disposable worker rather than retaining these targets after export. Resolution and view selection remain unchanged.
