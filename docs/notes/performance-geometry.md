# Mesh preparation performance

Implementation: [Mesh preparation](../guide/canvas.md#performance-mesh-preparation). Shared requirements: [Performance](../guide/performance.md).

## Edged lathes reuse profile rings

Rounded and chamfered cylinder and tube builds previously constructed four rotated vertices per quad, across 48 quads per profile span. Two rings now hold 98 reusable vertex tuples per build. Profiles with 32 and 64 spans previously allocated 6,144 and 12,288 vertex tuples. Their sine and cosine calls fall from 12,288 and 24,576 per build to zero after 98 calls during module initialization. The final triangle output and normal generation are unchanged.

`src/three/partMesh/edgedLathe.test.ts` compares exact triangle arrays with the former calculation for 46 profiles in both open and closed forms. Cases include axis endpoints, repeated points, tiny and negative radii, signed zero, empty inputs, single points and later edits. The 32- and 64-span cases verify no per-build sine or cosine calls. Existing `edgedGeometry.test.ts` checks complete rounded and chamfered cylinders and tubes alongside other basic shapes. These are structural allocation counts and tested operation counts, not wall-clock measurements or complete mesh-build speedup claims. No workflow, visible state or browser coverage changes.

## CAD crease adjacency uses direct lookups

The whole-app search found one CAD crease adjacency gatherer, `three/partMesh/creaseEdges.ts`, shared by packed geometry-worker requests and fallback part construction. Every complete triangle previously allocated a corner array, a key array, a mapped adjacency array and its filtered copy. The gatherer now reads three edge lists directly and reuses one triangle workspace. Normal vectors remain independent per adjacent face. Matching sides still append separately when rounded corners coincide, retaining duplicate adjacency and degenerate-face behavior.

On November 16, 2026, a scratch comparison on macOS arm64 with Node 26.13.0 matched complete outputs against the preceding implementation for 60 transformed box, sphere and torus cases, with ordinary and packed inputs. Across 65,280 visited triangles, source-derived temporary-array counts fall from 261,120 to zero. A subdivided box probe recorded 84 adjacent-face normal calculations using one triangle instance instead of 84. These are allocation counts and exact-output comparisons, without wall-clock measurements or a claim about complete CAD build latency. The comparison and logs are `scratch/crease-adjacency.test.ts`, `scratch/crease-adjacency.log` and `scratch/crease-adjacency-results.jsonl`. The initial probe failed because its baseline evaluator received TypeScript syntax. Transpiling the baseline corrected the probe without changing app code or test budgets.

Existing `creaseEdges.test.ts` covers threshold folds, rounded coordinates, repeated and non-manifold segments, degeneracy, incomplete inputs, coordinate-read counts, later edits, packed worker results and fallback mesh lines. No timeout, retry or quarantine changes apply.

## Booleans cut in the geometry worker

For two 50,000-triangle meshes (`booleans.perf.test.ts`) that is about 2 ms to hand off and 3 ms to take the reply, while the cut (welding, Manifold) takes about 180 ms in the worker; it used to run on the main thread in three-bvh-csg. The test fails if any main-thread step reaches 16 ms.

## STL transforms stream one facet at a time

Scene export and posed print-service meshes previously retained 36 bytes of transformed coordinates per triangle alongside the final STL. Both now retain one 36-byte triangle workspace, independent of mesh size. At 30,000 and 60,000 triangles, transformed-coordinate storage falls from 1,080,000 and 2,160,000 bytes to 36 bytes. The final STL still takes 84 bytes plus 50 bytes per triangle. Scene export still retains its source-array references and one matrix and vector. These are structural storage counts, not measured process-memory peaks.

`src/three/analysis/sceneStl.test.ts` compares complete files against the former transform-and-encode path across 80 generated meshes and subsequent edits. Coverage includes offset typed-array views, repeated instances, rotations, translations, reflections, collapsed scales, projective scene transforms, empty inputs, degenerate facets, nonfinite and incomplete posed inputs, and scene facets spanning incomplete mesh boundaries. Existing `analysis.test.ts` checks worker export and Z-up placement, and `posedStl.test.ts` checks off-plate placement. The untransformed `binaryStl` API retains double-precision normal calculation for Robot Package callers.

Review reproduced a scene-export mismatch with meshes containing six and three coordinates: the header declared one facet, but neither mesh wrote a complete facet and the output stayed zero-filled. The scene writer now carries the partial triangle across instances and bounds writes by the combined facet count. Regression cases also cover empty meshes, incomplete vertices and a truncated combined tail. Complete meshes retain the facet loop, selected by one mesh-length scan per export. The coordinate workspace remains 36 bytes.

A local posed replay on shared macOS arm64 hardware with Node 26.13.0 used 21 alternating five-call batches after five warmup batches. At 30,000 triangles, median posed write time changed from 1.98 ms to 1.94 ms. At 60,000 triangles, posed writing changed from 4.00 ms to 3.68 ms.

A review replay of the corrected scene writer on the same platform and Node version used one sinusoidal triangle soup with a reflected, rotated and translated affine transform. Across 21 interleaved five-call batches after five warmup batches, median scene write time changed from 1.55 ms to 1.49 ms at 30,000 triangles and from 2.43 ms to 2.36 ms at 60,000 triangles. Complete files matched the former buffered writer at both sizes. These replays measure transforms and byte encoding alone, exclude worker handoff and file saving, and have no CI timing assertions. Other work shared the machine, so these timings do not establish a complete-export speedup. No UI state, workflow or browser coverage changes.

The final output still occupies 10,800 and 21,600 bytes. These are structural storage and copy counts, not process-memory measurements or wall-clock speedup claims.

## Sculpt welding avoids preliminary buffer clones

Repository search found one `weldAndNormalizeGeometry`, called by both part-conversion paths and all four clay presets. Other welding paths already construct geometry wrappers or generate new buffers, so they do not have this preliminary whole-geometry clone. The wrapper retains every attribute except UVs and normals, preserving custom-attribute seam decisions and morph inputs during welding. No source buffers are mutated.

For an indexed 10-by-10-segment box, Three.js supplies 726 vertices and 3,600 indices. Removing the preliminary clone avoids copying 8,712 bytes of positions, 8,712 bytes of normals, 5,808 bytes of UVs and 7,200 bytes of indices, totaling 30,432 bytes per conversion. Welding still performs its own internal cloning and remapping. These are buffer-size counts, without process-memory or complete conversion timing claims.

`src/three/sculptWeld.test.ts` compares exact normalized positions and indices with the preceding cloned implementation for indexed boxes and spheres, expanded cylinders, planar and empty meshes, and later translated, scaled and reflected inputs. It also checks interleaved custom seams, morph inputs, source preservation, independent results and clone calls. The box fixture retains one internal position and index clone while preliminary position, index, normal and UV clones disappear. No workflow, visible state or browser coverage changes, so help articles and screenshots stay current. No timeout, retry or quarantine changes apply.

Changed-file validation passed formatting, lint, docs, site copy for 291 pages, types and all 655 tests across 102 related files. The first run caught an optional `indices` type error in the new source-preservation test. Correcting that assertion and rerunning changed-file validation passed. A translated triangle with mixed morph offsets returned a first vertex of `[0.2333, 0.2857, 0.5]` instead of the preceding implementation's `[-0.4, -0.3571, -0.2]`. Before the fix, the relative case failed while the other four welding cases passed. Failure output is in `scratch/review-sculpt-relative-before.log`.

## Shape deformation prepares one bend radius per mesh

Repository search found one bend implementation in `three/sculptDeformers.ts`, shared through `sculptEngine.ts` by `partMesh/context.ts` and `partMesh/customModel.ts`. It previously checked the bend angle and divided height by that angle for every vertex. The shared path now checks the threshold once and retains the radius for that call. A bent mesh with 10,000 vertices therefore needs one radius division instead of 10,000. Per-vertex angle calculation, trigonometry, transform order and normal recomputation stay unchanged. This is a source-derived operation count, without a measured latency claim.

A scratch parity comparison on November 16, 2026 used the preceding implementation from Git, transpiled with the installed TypeScript compiler. It checked exact positions and normals for boxes, spheres and zero-height planes, translated inputs, positive and negative bends, inactive thresholds, NaN and infinity, both alone and with Round, Taper and Twist. All 132 cases and 12,848 vertices matched using `Object.is`, including NaN and signed zero. The probe and log are `scratch/sculpt-bend-parity.test.ts` and `scratch/sculpt-bend-parity.log`. Its first attempt could not import an uninstalled transpiler, before any comparisons ran. Using the installed compiler resolved the probe setup.

Existing `sculptEngine.test.ts` covers taper and inactive deformation thresholds. `partMesh/edgedGeometry.test.ts` exercises combined deformation. No tests, timeouts, retries or quarantine entries change. The bend parity comparison is session evidence, rather than a new permanent test. The internal preparation change alters no displayed geometry, action, label or workflow, so help articles and screenshots remain current.
