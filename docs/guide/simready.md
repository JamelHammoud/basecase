## 8e. SimReady objects and robots

File downloads use the shared `eachLimited` cursor with six active tasks at most, without a copied pending queue. Cached files still count toward completed-file and byte progress. `electron/simready/assets.test.mjs` checks the concurrency limit, cache reuse, downloaded bytes, progress and listing refusals before downloads.

Tree pagination accepts only the `https://huggingface.co` origin. Listing requests use manual redirect handling and refuse every non-OK response, including redirects from the first request or a later page. Each listing entry must have a string path and a finite, nonnegative numeric size. Selected paths pass `insideDir` before any file download starts. Responses use `readCapped` before creating directories or writing files, with the smaller of the listed size and the 200 MiB file limit. Both listed totals and actual downloaded or reused bytes stay within 600 MiB per package. Understated sizes are refused even below the file limit. The fake-fetch tests cover accepted pagination, off-origin links, listing redirect refusal, malformed entries, traversal and oversized declared or streamed responses without writing the refused file. [Download boundary evidence and limits](../notes/node.md#simready-download-boundaries) record the reproduction.

NVIDIA's [SimReady Central](https://huggingface.co/spaces/nvidia/simready-central) indexes about 3,600 OpenUSD assets that makers host in their own Hugging Face datasets: props (NVIDIA's ~2,500, ForgeCAD, Palatial, LG, Vertiv) and robots and grippers (Franka, UR, FANUC, Comau, Standard Bots, Robotiq, OnRobot, AgiBot, Menlo). Most NVIDIA props and the makers' arms and grippers carry a MuJoCo physics variant: masses, convex colliders, physics materials, joints with limits, actuator force ranges.

- **Nothing is bulk-downloaded.** The renderer searches the Space's public API directly (`src/simready/search.ts`: `POST /search`, hybrid text + SigLIP2 vector query, `filter_url_regexp` by catalog dataset for the `objects`, `robots` and `all` shelves, 40 per page by `offset`; thumbnails from `/images`). CORS echoes any origin. Parts (§5) uses two: an object category's view searches `objects` live, and Parts' own search asks `all` only when Enter is pressed, listing the results in a SimReady section after the local matches; the agent's tools pick `objects` or `robots`. `useSimReadySearch` fetches only once the debounced query has caught up with the typed one, so no request goes out for a stale query. If the Space is down, the views say “Couldn’t reach SimReady Central.” with Search Again.
- **Catalog boundary:** `electron/simready/catalog.mjs` holds the 19 allowed namespace/dataset pairs for search and downloads. Search filters and checks its results against this list. Both the main process and portable scene decoder require an HTTPS Hugging Face URL at a pinned 40-character commit in that list. Scene visual cache keys must match the URL, with a named body and 16 finite matrix entries.
- **Insert = download one package, convert, import.** `electron/simready/` (`SimReady` in `index.mjs`, IPC `simready:fetch` / `simready:file`, HTTP `/simready-fetch` / `/simready-file`): lists the package's files at its pinned commit through the Hugging Face tree API, skips `source_assets/`, `.thumbs/`, `.metadata/` and non-albedo textures (normal, ORM, roughness…), caps a package at 600 MB, downloads into `library/simready/<ns>--<dataset>--<package>--<sha12>/files/`, converts, then deletes the raw files and keeps `model/`. Converted models are reused until `CONVERTER_VERSION` changes.
- **The converter** (`convert.py` + `frames.py`, `meshes.py`, `looks.py`, `physics.py`, `glb.py`) runs through uv with pinned `usd-core`, numpy and Pillow (`pyproject.toml`, `uv.lock`, env in `library/simready-env`), like the trainer. It selects the MuJoCo variant when the asset has one, reads rigid bodies (mass from the body or its colliders, else density × volume), joints as a tree from the base (loop-closing joints left out), limits, drive or `MjcActuator` force limits, velocity limits and friction, converts to meters with Z up, and writes `model.json` plus one geometry-only GLB per body (`meshes/<n>.glb`) and one `visual.glb` for the asset: a node per body, a primitive per material, UVs and each albedo texture once (JPEG, at most 1024 px). Materials are read from UsdPreviewSurface, OmniPBR / OmniSurface MDL inputs and OpenPBR-style names, per geometry subset; a texture that's authored but missing never falls back to the material's white tint.
- **Import** goes through the robot importer (`Source` kind `converted`, `utils/robotImport/simready.ts` → `Model`), so links become `mesh` parts and joints posable joints. `simready/loadAsset.ts` adds `simready` (url, name, maker, license) to every part, `physics: { dynamic, friction }` to objects with no moving joints (dynamic when the maker gave a mass), names single-body objects after the asset, and `mesh.visual` (`{ key, node, matrix }`) pointing at the body's node in `visual.glb`.
- **Textures:** `three/simreadyVisuals.ts` loads an asset's `visual.glb` once from the local cache. Rendering never downloads a package. Search insertion still downloads before importing. An uncached saved part keeps its collision mesh and dominant colour until the person selects Download Textures in the Inspector or command palette. The action downloads and converts one catalog package, disables duplicate requests with a Spinner and offers the same action after failure. Its cache update refreshes every link using that package and bumps a version the viewport adds to its mesh version. `partMesh/simreadyVisual.ts` draws the textured pieces in the part's frame; the plain mesh stays as an invisible stand-in for picking, shadows, measuring and the sim. Until the visual loads, and in thumbnails, the part shows its dominant colour (by surface area). Setting a colour by hand drops the texture.
- **Licences:** shown per asset (most are CC-BY 4.0; OnRobot BSD-3-Clause, FANUC Apache-2.0, UR its own). The Details card links to the asset on Hugging Face.

### Local Fleet facilities

`localFacility.mjs` and `localPackage.py` reuse `converter.mjs`, `convert.py`, `frames.py` and the same pinned usd-core environment for Fleet facility exports. The local path accepts USD, USDA, USDC or USDZ, with at most 256 files and 32 MiB of source data. The runtime lives in the user's Basecase cache, or `FLEET_USD_ENV_DIRECTORY`. Uploaded packages live in a fresh temporary directory and are removed after conversion. Nested USDZ dependencies require unpacking before upload.

Before composing a stage, the local validator reads each Sdf layer and checks every external layer dependency and authored asset value, including inactive variants and time samples. Paths must resolve to supplied package files. Absolute paths, URLs, package paths, expression paths, value clips and paths escaping the package are refused. USDZ entries have the same path, count and expanded-size checks. Case collisions, trailing dots or spaces and Windows device names are refused before files are written. Local references and sublayers resolve within the supplied package. Missing dependencies fail closed. The converter never connects to Nucleus. The catalog download path keeps its existing behavior.

Facility conversion applies complete world transforms before the stage's meters-per-unit metric and up-axis conversion. It writes world-space geometry, bypassing robot body grouping and floor levelling. [OpenUSD's units contract](https://openusd.org/dev/api/group___usd_geom_linear_units__group.html) supplies 0.01 meters per unit when no metric is authored. Nonpositive or nonfinite metrics are refused. Source metadata records the authored/default distinction and original axis. Referenced assets with different metrics still require authored corrective transforms, as OpenUSD specifies.

The shared process runner prepares the pinned environment with uv, then launches its Python executable directly with the remaining five-minute total deadline. Windows uses the environment's Python executable without a shell or signal names. NumPy's BLAS worker count is one. Converted facility output must fit 32 MiB and keeps the converter's 1.5-million-triangle ceiling. Fleet's mesh reader then applies its tighter 200,000-triangle ceiling. These are byte, geometry, time and JavaScript-worker limits, not an operating-system sandbox. Local conversion also limits Linux address space and Windows process memory to 3 GiB. macOS has no OS memory ceiling.

`localFacility.test.mjs` exercises real centimeter USD, Z-up USDZ, the unauthored metric, transformed elevations, local sublayers and hostile layer and texture references. It also probes the Linux and Windows memory ceiling. The whole file is quarantined only on Windows through 30 November 2026 under #1487 after intermittent setup and cleanup failures. Linux and macOS remain active, and Windows retains the Fleet USD browser walkthrough without the fast hostile-package and memory-limit coverage. [Setup evidence and restoration conditions](../notes/fleet.md#windows-local-usd-test-setup) record this gap. [Fleet evidence](../notes/fleet.md#facility-placement-and-imports) records its acceptance matrix and measurements.

### Visual grouping

`three/simreadyVisuals.ts` appends each transformed mesh to one call-local list per top-level body name. The completed map enters the asset cache only after parsing. Piece order, nested world transforms, material identity and shared-geometry ownership stay unchanged. It avoids copying the growing body list for every material primitive. `simreadyVisuals.test.ts` covers 300 and 600 pieces, nested transforms, separate bodies, missing nodes, source preservation and cached reads. It checks one map insertion per body. The loader is controlled in this test, so real GLB decoding and texture downloads remain outside its coverage. [Operation counts and limits](../notes/performance-geometry.md#simready-visuals-append-to-one-body-list).

### Catalog download consent coverage

The Inspector and command palette consume `useSimReadyVisualStatus` directly. Its primitive store snapshot keeps loading and failure states visible to the React Compiler. Querying an unseen visual starts only its local cache read, so the download action cannot be enabled before that lookup starts.

The browser consent test requires no console errors before download. After its deliberate HTTP 503 response, it requires exactly Chrome's resource-error diagnostic for the download URL. The same walkthrough checks loading, failure feedback, restored action availability and no automatic package retry.

`electron/simready/assets.test.mjs` refuses another namespace and an unlisted dataset in an allowed namespace before download or conversion. `src/simready/search.test.ts` checks the matching search filter. `src/utils/sceneFile.test.ts` checks hostile saved URLs, cache-key mismatches, damaged transforms and valid round trips. `src/three/simreadyVisuals.test.ts` checks local-only cache misses, an explicit download, failure without automatic retries, shared-link deduplication and cached textured rendering. `e2e/simreadyConsent.e2e.test.ts` drops a portable scene through the file entry point and clicks the Inspector action. Browser execution runs in CI. [Boundary evidence and remaining limits](../notes/node.md#simready-catalog-download-consent).
