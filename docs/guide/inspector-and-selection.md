# Inspector, selection, drag and drop, mode panels

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

Sketch face outlines use `electron/cad-kernel/pairKey.mjs` for undirected projected edges (§0f). Lexical endpoint order and the pipe separator stay unchanged, without sorting a temporary pair for each triangle edge.

## 7. Inspector (Figma UI3 style)

- Sections are separated by full-width hairline dividers, never boxed cards. Section titles are sentence case and 13px semibold.
- **Notes** (`NotesSection`) is one section for the scene and for a part: a text area with no placeholder, collapsed while empty and open when it has text. `Section` reads `defaultOpen` only on mount, so `InspectTab` keys the Inspector by `sceneId` and `PartInspector` keys Notes by part id: loading a scene into the open tab or picking another part opens Notes again when they hold text. Notes hold only what someone wrote or something the screen doesn't show: a catalog part's and a hardware part's mounting notes, and the screw a hardware cutout is for. A part made in Sketch, Sculpt or Import SVG starts with empty notes, so Notes starts collapsed.
- Every Inspect view and mode panel scrolls with `useScrollFade`, like Parts: an edge fades only while there's more to scroll past it.
- **No selection:** Notes for the scene (saved with it to `ai-reference/` and matched by Search scenes; Copy as Markdown puts it under Design Intent and leaves that line out when it's empty) and Comments (just the title and + when there are none). Scene stats live in Layers: the header shows parts and cutouts, and a footer shows the overall size.
- **Part selected:**
  - Inline-renamable name, then Duplicate / Save to Library / Delete.
  - Hardware shows the same `HardwareConfigurator` sections as Parts (type tiles, drive, size, length, finish) in place of Size and Shape. Specs and Holes come before Notes, collapsed; Holes carries + (Add clearance hole) in its header. Length typing and scrubbing are live; release commits one undo step. The color follows the finish unless it was set by hand.
  - No Solid · Cutout · Guide control: the part type is set from the right-click menu (one part or several).
  - Size W/H/D (+ wall T), Position X/Y/Z (Floor, Stack and Center actions), Rotation X/Y/Z with a strip of 90° turns (`QuarterTurns`, the same strip as a multi-selection's).
  - **Shape** (Fillet or Chamfer and its size, Taper, Bend, Twist): collapsible, open only when non-zero; Reset shape clears all of them.
    - **Edges** (`EdgesField`, no label of its own) shows on a box, cube, cylinder, tube, hex prism or wedge (`EDGE_KINDS` in `utils/partEdges.ts`): **Fillet** or **Chamfer**, then a size in mm, stored as `edges: { kind, mm }`. The size is clamped to 98% of the largest the shape allows: half its smallest side, half the tube wall, or the hex's or wedge's inradius (`edgeLimitMm`). The shape keeps its size: the edges round or bevel inward.
    - The builders make exact geometry, with no vertex deformer (`partMesh/edgedGeometry.ts`). A box, hex prism or wedge is its outline inset by the size and grown back by a sphere (fillet) or a double pyramid (chamfer), in layers, so every edge and corner is cut. A cylinder or tube is a lathed profile with its rims rounded or beveled; an oval cylinder is a round one scaled along its depth, so its rim's edge size scales with depth ÷ width. Arcs step at most 11.25°, so a 3 mm fillet on a 40 × 20 × 10 mm box is within 0.2% of its true volume. Results are cached by their parameters and cost about 1 ms uncached. Taper, Bend and Twist still apply on top.
    - Everything that reads the built mesh follows: STL, 3MF and plates, printability, mass, booleans (an edged operand stays editable) and the MJCF hull. STEP falls back to the mesh for an edged part, and a world item with edges uses its hull instead of an MJCF box or cylinder.
    - **Round** (`deformers.roundness`, a 0–100% pull toward an ellipsoid) shows only on a part that already has it, until it's set to 0, so old scenes render as before.
  - **Dimensions** (agent-made OpenSCAD parts, after Size; hidden in the web demo): one row per top-level numeric assignment the code makes once (`wall = 2;`), named as the code names it, with min, step and max from a Customizer comment on the same line (`// [1.2:0.4:4]`, `// [min:max]` or `// [max]`, which starts at 0). Size still scales the mesh; Dimensions change the design. Enter or blur sends the part id and the new number over `cad:tune` (`useCadTune.ts`); the main process rewrites that one literal in the stored code and compiles it in the kernel pool (§9, §0h). The result replaces the part through `applySpec`, keeping the code origin where it was, and `followMates` moves what's mated to it, all as one undo step (`withTunedPart` in `agent/cadTune.ts`). A compile error, or a result that fails any of the part's `cad.expect` requirements, keeps the old part and shows the reason in an error toast. Edits to one part run in order; a result whose part changed meanwhile (the agent rewrote it) is dropped. While a tune runs, its field shows the number sent; any change to the part's code (the tune landing, an undo, the agent) drops that, so the field always shows what the code says, including after ⌘Z (`dimensionEdits.ts`). replicad parts get no Dimensions: once `mirror` or `fasten` wraps their code in a function, their constants aren't at the top level any more.
  - Collapsible sections keep their title where a plain section's sits and put the chevron at the far right, after any header actions.
  - A code dimension edit on a sheet returns the part to printing in the same undo step. The compiled source replaces the previous geometry at its native dimensions and clears the previous sheet transform. Agent CAD updates that retain an explicit sheet setting measure the new source and reapply stock thickness to those native dimensions.
  - **Manufacturing** appears for a flat, constant-thickness solid, measured by `measureParts` in the analysis worker after the viewport's meshes are ready. `useSheetProfile` drops a result if the selected part changed while it ran. Choose Cut from Sheet, then 6061 aluminum, Carbon fiber plate or Acrylic and a stock thickness. `applySheet` stores `sheet: { material, thicknessMm }`, snaps to the nearest stock thickness and changes the actual geometry in one edit, so one Undo restores the printed part. The shared `sheetOf` also reads older CNC aluminum and laser-cut material tags. A saved sheet, including a legacy CNC or laser-cut tag, whose geometry stops qualifying keeps its Manufacturing selector so it can return to 3D Print, with material and thickness disabled until it qualifies again.
    - Size and Manufacturing share that one worker profile. A Size field is disabled when its axis has a component along the sheet normal, keeping the physical thickness under Manufacturing's stock selector. For an axis-aligned sheet, the two in-plane size fields remain editable. A tilted sheet can disable more axes. While the profile is loading, assigned sheets disable all three size fields. Shape edits clear the sheet setting and return the part to printing in the same undoable edit, preserving `sheetTransform` and its physical geometry. A Scale gizmo resize also returns the part to printing when any dimension changes. Translation and rotation keep sheet metadata when their dimension values are unchanged, and the Inspector’s permitted in-plane Size fields keep the sheet setting.
    - `e2e/sheet.e2e.test.ts` checks a plate's conversion, the Sheet BOM line, printing exclusion, DXF download and Undo, plus a Shape edit returning the sheet to printing with Undo restoring it. `src/utils/sheetManufacturing.test.ts` builds and measures an indexed pocketed mesh, checks that its profile is rejected, and keeps its legacy CNC source blocker without a Sheet BOM line. `src/sheet/detectSheet.test.ts` also rejects pockets, open faces and nonfinite data.
  - Appearance (`ColorField` + Material for a Solid without a sheet setting: Printed PLA / PETG, Printed TPU or Off-the-shelf, from `MATERIALS` in `inspector/types.ts`; a tag outside that list shows as Printed PLA / PETG, as the BOM reads it), comments on this part, Notes (sent to the agent), then Product (maker · part number, specs, mounting, model source, links) for real components. Sheet material is shown only in Manufacturing. Older CNC aluminum and laser-cut tags remain readable through `sheetOf`, but new sheets enter through the measured Manufacturing control.
- **Several parts selected (`MultiInspector`), like a multi-selection in Figma:**
  - Title: the group name (renamed in place, one undo step on Enter or blur), or “N parts”. Under it, the part count and the selection's overall size (`39 × 50 × 39 mm`). Group/Ungroup, Duplicate, Mirror (a menu of Side, Front and Top, below), Save to Library and Delete sit beside it.
  - **Align:** one icon strip per axis (min · center · max) with Spread beside it (`AlignBar`; Spread shows from 3 parts).
  - **Position:** X/Y/Z of the selection's bounds center. Typing, scrubbing and math move every unlocked part together (`handleMoveSelection` takes an absolute target computed from the latest parts, so Enter + blur can't move it twice). Drop to floor and Center on origin in the header run the same edits as ⌘K and the right-click menu (`dropToGround` and `centerOnOrigin` in `workspace/usePartEdits.ts`); Center on Origin moves the bounds center to X 0, Z 0 and leaves the height alone.
  - **Rotation:** the single part's `QuarterTurns` strip; X / Y / Z 90° turns the selection as one piece about its center (`handleRotateSelection`).
  - **Combine:** Union / Subtract / Intersect on one strip; Subtract's tooltip names the part it keeps.
  - **Appearance:** `ColorField` and Material (only when every selected part is a Solid without a sheet setting), each showing “Mixed” when the parts differ.
  - Strips (`StripGroup` + `StripButton` in `AlignBar.tsx`) are the pattern for a row of equal actions: a 32px soft track with 2px inset cells, never a grid of text buttons or tall tiles.
- **`NumberInput`:**
  - Drag the label to scrub (Shift ×10, ⌥ ×0.1). ↑/↓ steps, Enter commits, Esc reverts.
  - Hovering a one-letter label shows what it stands for (W: Width (X)). A field with its name beside it (Wall thickness, Copies, Infill) has no tooltip.
  - Accepts math (`40/2`).
- **Live vs. committed edits:** scrubbing, slider drags and typing call `onChange(value, live=true)`. Those skip undo history until release or blur, which commits one undo step (`commitParts(updater, live)` in `App.tsx`).

## 7a. Selection, Groups & Booleans

An ordinary scene box referenced by `project.electronicsBoard.partId` uses the existing Size, Position and Rotation edits. The board frame is its rigid transform, with width and depth as the rectangular outline and height as thickness. Board processing refuses deformed, rounded, sheet-transformed or replaced host geometry instead of interpreting those edits as a supported outline. The Board section edits component side, height limits and edge clearance. Mounting holes and Keepouts edit their local constraints. Add Hole creates its linked M3 screw and standoff, and deleting that hole confirms removal of its owned hardware. Missing hardware is not recreated by an unrelated board edit. Deleting a keepout also asks first. A section per placed product edits local X and Z, quarter-turn rotation and Locked. Auto Arrange preserves locks and adds supported new endpoints. Placement deletion confirms and retains the ordinary source module. Hole and keepout additions use unique identities, with a maximum of 128 each. Board edits use the scene history and move existing module geometry with their placement. Import Board brings back a supported routed KiCad source without changing placements or moving modules. Fabrication records its process source and minimum clearance, track width and drill diameter before or after routing. Routing holds the separately declared conductor, via and stackup values. Route Board uses the local desktop router and commits only after reconciliation and native validation. These fields use ordinary scene history and preserve scene part references and poses, including detached modules. Only definition and placement edits reconcile mounting hardware and module poses. [Board coverage](build.md#board-placement-records) records the current scope.

- **Selection is an ordered list** (`selectedIds` in `App.tsx`). The first id is the primary, and Subtract keeps that part.
- Group expansion (`utils/selection.ts`) collects selected group ids in one scene pass, then appends missing members in scene order. Additions, toggles and inside-group detection (`workspace/selection.ts`) use membership sets. Canvas clicks, marquee selection and Layers reuse these helpers, preserving primary order without repeated membership scans.
- **Canvas:**
  - Click a part to select it, or its whole group. Clicking again keeps the group selected.
  - Double-click or ⌘-click a grouped part to drill into just that part, or a boolean to drill into the operand under the pointer. Once inside a group (some but not all of its members selected), a single click selects another member.
  - Shift-click works like Figma (`clickSelection` in `workspace/selection.ts`): it toggles what a plain click would pick. From outside a group it adds or removes the whole group; inside one it adds or removes just that member, so members of one group and other groups mix freely. ⇧⌘-click toggles exactly the part under the pointer. Clicking empty space clears the selection.
  - Shift-drag draws a blue selection box and adds every unlocked, visible part it touches, plus their groups. Hit testing uses each part’s real silhouette (projected vertices + a 7×7 ray grid), not its bounding box. It runs in the capture phase and turns OrbitControls off for that drag, so Shift-drag never pans. Shift-scroll still pans.
  - Only primary clicks change selection; right-click never does.
  - Locked parts ignore clicks, like Figma: a click or double-click passes through to the part behind (`raycastUnlocked` in `three/viewport/picking.ts`), and right-click opens the canvas menu, not the part's. ⌘-click (and ⇧⌘-click) still selects a locked part, as does its row in Layers. Measure, Annotate and Mark still land on them.
- **Layers:**
  - A plain click selects that row; Shift/⌘-click toggles exactly that row (a part row never expands to its group; a group row toggles all its members).
  - Group rows are collapsible, renamed by double-click or Rename (right-click or ⌘K with the whole group selected, §11), and select every member.
- **Mirror** (right-click ▸ Mirror ▸ Side / Front / Top, ⌘K Mirror, the multi-selection Inspector) copies the selection across one of the three scene planes, named after the views. The plane passes through the selection's centre, except Side for parts of a robot that leave its body out: that one passes through the centre of the robot's body (the parts no joint moves), or x = 0 when the parts are framed to a skeleton. The last plane picked is remembered until the app quits (`mirror/plane.ts`), and ⌘K uses it. The copies are selected, named after their source with left and right, front and rear or top and bottom swapped (else “⟨name⟩ (Mirror)”), put in a new group the same way, and keep `mirrorOf`. Parts and twin joints land as one undo step. The maths is `src/mirror/`, shared with the agent's `mirror_parts` (§9):
  - Basic shapes are placed as the same shape, turned about a local axis they're symmetric about, so a wedge, cone, pyramid or dome lands as its true mirror image; a twist turns the other way. Catalog parts are the same part, placed by datum (`mirrorDatum.ts`), never a flipped mesh. CAD, mesh, sculpted and custom-model parts mirror their geometry, with the winding reversed. A sheet’s affine transform is conjugated by that same local reflection (`F × T × F`), preserving stock thickness and its reflected face. A boolean mirrors its operands and recomputes.
  - Catalog datum scoring groups ports by exact kind and thread once per call. All three candidate planes reuse those groups without filtering the full port list per reflected port or collecting distance arrays. Port order, output-centered offsets, the 0.5 mm score tie and local-axis alignment stay unchanged. The same scorer serves every Mirror entry point and `mirror_parts`, and later calls read edited ports afresh.
  - Mates follow to the port that lands where the mirrored port would (within 1 mm), on the copy or on an unmirrored target; a mate with no such port is dropped.
  - Mate ports, catalog datum planes and symmetric shape axes select their winner without sorting candidates. Equal distances or alignments keep the first candidate in source order. Datum planes still choose alignment only within 0.5 mm of the lowest score, and a shape keeps the requested axis when it is symmetric about that axis.
  - A joint whose children are all mirrored gets a twin: parents and actuators map to their copies (an unmirrored parent, like the body, stays), the origin is reflected, and the range is kept. A hinge's axis is reflected and reversed, so the same angle moves the twin the mirror way; a slider's axis is only reflected.
  - Framed parts (§9) land on the paired skeleton joint (`alignToSkeleton`) when the plane is the skeleton's; on any other plane they lose their frame.
- **Moving several parts:** the gizmo attaches to a pivot at the selection’s center. Move, rotate and scale apply to every unlocked part and commit as one undo step.
- **Lighten:** the one-part right-click menu and ⌘K offer Lighten for a visible, unlocked printed solid (`workspace/lighten.ts`, `canLighten`). `LightenSheet` asks for Target mass as a percentage of the original, starting at 50%, and puts Min. wall under Expert, starting at 1.5 mm. The shared `applyLighten` action collects the part's load cases and mounting regions, then sends optimization to the analysis worker (§8b). A successful result replaces the part's shape as one undo step, keeping its id, placement, name, color and material. Old mesh, sketch, derived mass and CAD audit data are cleared. A retained affine sheet frame stays with its ports, and the worker removes that frame from the returned mesh before replacement. The spinner and the sheet’s busy state mark a running calculation. A refusal leaves the part in place and shows its reason in the sheet. Closing the sheet or changing the scene while a run is pending prevents that result from landing.
- **Groups:** stored on each part as `group: { id, name }`, so they’re undoable and saved with the scene. Groups are flat (no nesting). ⌘G groups, ⇧⌘G ungroups.
- **Booleans** (`src/booleans/`) stay editable:
  - With 2+ parts, Union, Subtract (from the primary) and Intersect replace them with one `boolean` part. With one part, Subtract uses every visible Cutout that overlaps it, and makes the same kind of part.
  - The result keeps the base part's id, name and print material (joints, marks and comments on it stay attached). `boolean: { op, operands }` holds the parts it was made from, base first, each a whole `ScenePart` in world coordinates with its own id; the base takes a fresh id. They're not in the top-level parts list, so Checks, the BOM, printing, plates, STL and the MJCF see only the result.
  - The result's mesh is derived: it lives in `mesh` like an imported mesh (drawn by the same builder, measured the same way) with `boolean.hash`, the operands' hash it was cut from (`hash.ts`), and `boolean.frame`, the result's position, rotation and size at that moment. Scenes save it, so loading never cuts again; a part whose hash no longer matches is cut again on load.
  - The cut runs in the geometry worker (`csg.ts`, op `boolean`) with `manifold-3d`; when Manifold refuses an operand's mesh (open component pieces), the whole cut falls back to three-bvh-csg in the same worker. The main thread never runs CSG. Results are cached by hash (`evaluate.ts`, last 64). Mesh operands and nested boolean results compose `sheetTransform` before their source-mesh scale, so a stock thickness edit reaches the cut and operand picking. A nested boolean operand’s cache key includes its dimensions and affine transform, so changing its thickness invalidates the enclosing cut.
  - `commitParts` lifts every operand into the list the updater sees and folds the edits back (`editWithOperands` in `operands.ts`), so every edit by id (gizmo, Inspector, agent ops, ⌫) reaches an operand. Deleting the base, or all tools but one, dissolves the boolean into what's left. Moving, turning or resizing the result carries its operands with it (`syncFrames` in `frames.ts`); a move alone keeps the hash, since operand positions are hashed relative to the base.
  - After a commit, `useBooleanResults` cuts every stale boolean (innermost first) and writes the result into the present and every undo and redo state whose hash matches (`patchEveryState`), so an operand edit is one undo step and undo shows the old cut at once. Each distinct parts array is patched once per update, including the live-edit base. Snapshots sharing an input array share its patched array too. The cache lasts only for that update, so later results are read afresh. An edit that empties the result leaves an empty mesh until the next edit; making a boolean from parts that don't overlap changes nothing and says “Those parts don’t overlap”.
  - Drilling in works like a group (`drillTarget` in `picking.ts`): double-click or ⌘-click the result to select the operand whose surface is under the pointer (the closest of each operand's hits to the result's hit); once inside, a plain click picks another operand. A selected operand draws as a ghost over the result (cutouts in their own red, solids in translucent blue, `drilledOperands`), which the gizmo moves like any part. Layers lists operands under the result (§5).
  - Duplicate and paste give operands fresh ids (`freshOperandIds`). STEP export rebuilds a boolean exactly from its operands when every one can be built exactly (`exactSolid`), and from its mesh otherwise. Old scenes keep their `sculpt_mesh` booleans, which render and export as before (one saved with a `csg` recipe still exports exactly while it keeps the size it was made at).
- **Wrap Robot:** with exactly one visible imported mesh (`mesh.file`) and parts of exactly one jointed robot selected (`wrapTarget`), the several-parts menu starts with Wrap Robot, and ⌘K lists it under Selection. It turns the mesh into one hollow shell per link that clears every joint's range (§8c, `src/wrap/`): a progress toast shows while the wrap worker runs, the canvas stays live, and the shells come back selected, with the mesh hidden. One undo restores the mesh, the robot's joints and its parts. The fit is a starting point: resize a shell with Size like any part.
- **Align (`AlignBar`):**
  - One icon strip per axis: X Left·Center·Right, Y Bottom·Middle·Top, Z Back·Center·Front, with Spread beside each once 3 or more parts are selected (below that the strip takes the row). The right-click Align submenu and the multi-selection Inspector show the same strip; a click in the submenu closes the menu.
  - Several parts align to their shared bounds; one part aligns to the origin (Bottom = floor).
  - Align and Spread filter unlocked parts through one selection id set (`unlockedSelection` in `utils/selection.ts`), so a large selection never adds an array membership scan per scene part. Unselected and locked parts keep their object identity.
  - Bounds include each part's rotation and affine sheet transform (`halfExtents` and `partBounds` in `utils/selection.ts`, checked against three.js `Box3`), so align, spread, drop to floor and the sizes in Layers and the Inspector stay right for rotated parts. Placement of affine sheets keeps full precision at the transformed anchor. Align and Spread keep that precision across a mixed selection, so rounded positions cannot move a face off its target or make the gaps unequal.
  - One table names every action, `ALIGN_AXES` in `components/alignActions.ts`: the strip's tooltips and ⌘K read their labels from it, so both say Align Left … Align Front, Align Center (X), Align Middle, Align Center (Z) and Spread Along X, Y and Z, with each action's own icon. With one part the tooltips say where it goes instead: Left to origin, Bottom to floor.
- **Joining two parts:** with exactly two parts selected, Add Hinge and Add Slider (right-click or ⌘K) make the first part the parent and the second the child of a new joint. The axis comes from a shaft in a bore shared by the two parts, or from a round face you click on either one; the selection order is what decides which part moves (§8c).
- **Drop to Floor (F):** loose parts each drop to the floor; when every selected part is grouped, the selection lands as one piece.

## 7a-2. Drag and Drop

- **Draggable onto the canvas:** Parts tiles, Shapes menu tiles, Library model tiles, robot tiles and rows, and SimReady tiles (all in Parts). They use `PART_DRAG_TYPE` / `MODEL_DRAG_TYPE` / `ROBOT_DRAG_TYPE` (`{ url, name }`, imported on drop) / `SIMREADY_DRAG_TYPE` (`{ url, name, maker, license }`) from `src/data/dnd.ts`, and the tile’s preview is the drag image.
- **Where it lands:** at the drop point, snapped to the grid step. Dropping on a part stacks it on that surface; otherwise it sits on the floor.
- **Snapping by ports** (§12): a Parts tile, or a Library model that inserts as one part, snaps onto a compatible port within reach of the drop point, with the same dots as a gizmo drag and the mate recorded. The browser hides drag data until the drop, so tiles start their drag with `setSceneDrag` (`data/dnd.ts`), which also keeps the payload for `dragover`; `workspace/dropPreview.ts` builds the part that would land and `previewSnap` on the viewport handle solves and draws it. ⌘ (Ctrl on Windows) drops without snapping. Articulated parts (grippers, hands) and multi-part Library models land as before.
- **Shapes menu:** fades out (stays mounted) while dragging, then closes on drag end. Removing the drag source would cancel the drag.
- **Import** (File ▸ Import, ⌘K, the canvas menu at the clicked point, and Library ▸ New Model) opens one file picker for every type below, and most files dropped on the canvas take the same route at the drop point. Dropped GLB, glTF and OBJ files instead open New Case as captured worlds, with an optional SPZ or PLY splat. Their accompanying folders supply linked textures and buffers, keeping each relative path. RoomPlan JSON files open individually through the world reader, while other dropped files keep their own routes. Scene, robot, recording, motion and SVG drops take their existing route even alongside JSON or mesh resources. The file picker still imports meshes as parts: `routeImports` (`workspace/importRoute.ts`, pure) sorts files by extension, case-insensitively (a file with no known extension but an `image/*` type other than SVG counts as an image, the same test the drop overlay uses for “Drop to add a reference image”), and `useFileImport` hands each kind to its flow. Meshes and CAD become parts; an SVG opens the Import SVG panel (§8) with the file loaded (`openCreator('svg', file)`); a `.urdf`, `.mjcf`, `.xml` or `.zip` (a Robot Package is a zip), and any dropped folder, imports as a robot at once (§8c), at the drop point, and opens the Import Robot sheet only to choose among several robots, except that a zip or folder holding a LeRobot dataset or a rosbag2 recording imports as tries instead (`dataSourceOf` reads only the zip's entry names; §8h, Imported tries); a `.mcap` imports as a try; a `.bvh` opens the retarget sheet for the selected robot (§8c), or “Add joints to retarget motion onto” without one; images become reference images (§7b); a `.basecase` opens in a new tab (§5a). Only the first SVG and the first BVH open; any others, and any other file, get one “Couldn’t import ⟨files⟩” toast. Import Robot stays its own command because it also takes links; a Hugging Face dataset link that holds a LeRobot dataset imports as tries there, and any other link, or a dataset repo without `meta/info.json`, imports as a robot. `__studio.pickFiles` hands the next picker files in tests.
- **Mesh files** (STL, 3MF, OBJ, PLY, FBX, GLB / glTF, DAE) are inserted as one `mesh` part each, standing on the drop point (`workspace/meshImport.ts`). Units and axes follow each format's convention: STL, 3MF and PLY are millimetres with Z up; OBJ millimetres with Y up; GLB, glTF and DAE metres; FBX centimetres times its unit scale. A model under 1 mm across is read as metres. Meshes are welded, never simplified, so prints keep every triangle. `mesh.file` marks an imported mesh, and only those print (`isPrinted`); robot links and SimReady meshes don't. Parsing runs in the geometry worker except 3MF and DAE, which need `DOMParser`. FBX textures are skipped (`NoTextures`), since the worker has no `document`.
- **CAD files** (STEP, STP, IGES, IGS) take the same import path on desktop: drop or Import. They never parse in the renderer or in Node: `platformBridge.openCadFile` hands the bytes to the main process (`cad:open`, or `/cad-open` over the dev bridge), which sends them to the same sandboxed converter as `import_maker_cad` (§8a, §0h) in its bodies mode. OpenCascade reads the units from the file header, so every body arrives in millimetres at true size, Y up. Each body becomes its own `mesh` part (`workspace/cadImport.ts`), named from the file's product names (else “⟨file⟩ 2”), coloured with the face colour covering most of it, and grouped under the file name when there's more than one; the whole file stands on the drop point. Placement scans each axis through `utils/centerSizeRange.ts`, shared with robot insertion, without temporary coordinate arrays. Bounds use the unrounded body centers and sizes before individual parts are rounded. The converter simplifies a file past 200,000 triangles in total and refuses one with more than 1,000 bodies. A file it can't read gets the same single “Couldn’t import ⟨file⟩” toast as a broken mesh. The web demo keeps meshes only (`IS_WEB_DEMO`).
- **STEP export** goes the other way: Export ▸ STEP in the title bar, or Export STEP in ⌘K, writes `⟨scene⟩.step` for Fusion, Onshape, SolidWorks and other CAD tools (`workspace/useStepExport.ts`, desktop only, `IS_WEB_DEMO`). It takes the parts STL takes (visible solids, no reference images, `isStepBody`) as they're modelled, never as posed; with none of those in the scene the menu item is disabled and the ⌘K command is hidden. `stepJob` (`workspace/stepExport.ts`) loads catalog meshes, then gives each part one body named after it, with its colour, placed at its position and rotation in millimetres, Z up like STL, inside a sub-assembly named after its group. A replicad part goes as its code, a sheet with an affine thickness transform goes as its current mesh so the exported thickness matches the scene, a basic shape as an exact solid (`exactSolid`, `workspace/stepSolids.ts`: box, cube, cylinder, tube and torus always; sphere, cone, capsule and dome when round, and a dome or capsule only when its ends are at least as tall as they are wide, since OpenCascade's reader loses the curved face of a revolved arc of a wide ellipse), and a Union, Subtract or Intersect result as the boolean of its operands while it keeps the size it was made at; everything else (catalog parts, hardware, imports, OpenSCAD, sculpted and deformed parts, wedges, pyramids and hex prisms, whose flat faces the kernel merges back, and a replicad part resized unevenly) goes as its mesh, which the kernel turns into a faceted solid. Code and booleans also carry their mesh, used if the exact build fails. The kernel builds the file in its sandbox (`platformBridge.exportStep`, `cad:export-step` or `/cad-export-step`; §9, §0h). “Exporting STEP…” shows while it runs (a second click meanwhile does nothing) and goes away on a clean export; “Exported STEP without ⟨n⟩ parts” replaces it when a part had no geometry or failed both ways, and a failed export shows the kernel's error (on desktop without Electron's “Error invoking remote method” prefix, stripped by `errorMessage`, §3b-9). If no part ends up with geometry, the progress toast just closes.
- While files are dragged, the canvas shows `DropOverlay` (§14), reading “Drop to add a reference image” for images alone (SVG excepted), “Drop to import” otherwise.

## 7b. Reference Images

- **Adding:** ⌘V anywhere outside a text field, drop image files on the canvas (at the drop point), “Add Reference Image” in ⌘K or the canvas's right-click menu.

The Layers row shows the photo as its glyph.

## 8. Mode Panels (Sculpt, Sketch, Import SVG)

Sketch's square solve and rectangular rank calculation share the dense pivot scan in `utils/matrixScans.ts` with calibration and skill solvers. Rank supplies its current row independently of the column, preserving skipped-column behavior and first-row tie selection.

There's no Shape tab. These panels appear in place of the Inspector only while they apply (`SculptAndDrawStudio`), under `ModeHeader`: the title, then Done. Esc leaves them too (`leaveStudio` in `useToolMode`), after it has dropped the Sketch plane's field, shape, selection and tool, one per press (§11). It never discards work: a new sketch with drawn entities or path points, or a loaded SVG, reports itself unsaved (`studioUnsaved`, set by `SculptAndDrawStudio`), and Esc then stops there; only Done leaves it. A sketch reopened from a part edits the scene, so Esc leaves it.

- **Sculpt:** a stroke on an affine sheet bakes its current transformed mesh relative to the original dimensions, then clears the sheet setting and affine matrix when committed. The sculpted mesh retains its actual size and position and returns to printing without applying the thickness transform twice. Existing baked edges and deformers are cleared with it. Shown while the Sculpt tool (C) is on. The tool is hidden unless Settings ▸ Canvas ▸ Tools ▸ Sculpt is on; when it's off, C, the toolbar button, the ⌘K entry and the Shortcuts rows (Sculpt, Sculpt inverted) are all gone, and turning it off mid-sculpt switches back to Move. Existing sculpted parts still render and export. Brushes, Size/Strength sliders, Mirror X/Z, Subdivide (only while one sculpted part is selected), Add clay presets. The panel doesn't explain the gestures: ⌥-drag inverts the brush, listed under Shortcuts. Done, or Esc, switches back to Move.
- **Sketch:** opened from Shapes ▸ Sketch, ⌘K or right-click. Extrude / Revolve / Path, the Line, Rectangle, Circle and Arc tools, Snap to grid and Clear, the sketch plane, then Output (T, Add). Output asks for no name or color: the part lands selected as Sketch (or the SVG's name, when Edit in Sketch handed it over) in the default gray, and the Inspector renames and recolors it.
  - **Model** (`src/utils/sketch/`, framework-free): a sketch is points, lines, circles and arcs plus constraints (coincident, horizontal, vertical, parallel, perpendicular, equal, tangent) and dimensions (length, radius, angle, distance), all in millimetres. `solveSketch` is our own damped least-norm Newton solver on the residuals, with a numeric Jacobian: deterministic, synchronous, so a drag re-solves every pointer move. A set whose Jacobian has fewer independent rows than equations, or that doesn't converge, is reported as `over` and never applied, so an over-constrained edit is refused (the plane's ring flashes red) and the sketch keeps its last solved state. A dragged point is weighted stiff, and a changed dimension holds its line's first point (a circle's centre), so the rest of the shape moves around it. PlaneGCS (FreeCAD's solver, as the `@salusoft89/planegcs` WASM build) was the alternative; it needs an async WASM load and is far larger than the dozen constraint kinds Sketch uses.
  - **Solve preparation:** each `solveSketch` call builds its entity lookup and arc list once, alongside the variable layout. Newton iterations, damping candidates and numeric Jacobian probes reuse them while reading each probe's current coordinates and radii. Preparation belongs to that call, so a later edit rebuilds it from the changed sketch. `residualPlan.ts` records each residual term’s point and radius reads during preparation. Numeric Jacobian columns probe only terms that read that variable, retaining both coordinates for every point dependency. Newton steps and the final rank check share this plan. Nonfinite residuals retain full probing, as do columns with a nonfinite probe step. `residualPlan.test.ts` compares every derivative with the dense calculation across mixed geometry and every constraint kind, including fixed points, degenerate geometry, missing references and nonfinite inputs. It also checks independent dimensions, source preservation and later edits. Each Newton iteration also prepares its weighted Jacobian products once for every damping trial (`leastNorm.ts`). Diagonal terms are accumulated after damping in their original order, preserving floating-point results. Gaussian elimination consumes the fresh damping matrix on each trial without cloning its rows. `solveSquareInPlace` mutates only that owned matrix and copies the residual vector. Prepared products and caller inputs remain unchanged. `solver.scale.test.ts` bounds entity traversal across small and large mixed sketches and checks arc geometry, circle dimensions, dragged points and a subsequent edit.
  - **Plane** (`SketchCanvas`): an SVG in millimetres, y up. Pinch zooms about the pointer and two-finger scroll pans. The grid step follows the zoom, and snapping uses a step about 1/80 of the view.
  - **Drawing infers** coincident (a point within 9px snaps onto it and reuses it), horizontal and vertical (within 9px of the last point's row or column) like Figma and Shapr3D. Each inference shows as a glyph by the pointer (`CoincidentIcon`, `HorizontalIcon`, `VerticalIcon`) and becomes a constraint when the click lands. A rectangle is four lines with horizontals and verticals. Lines chain until one ends on an existing point.
  - **Typed lengths:** with a shape started, typing a number opens fields by the shape: length, then Tab to the angle for a line; width, then Tab to the height for a rectangle; diameter for a circle. Enter places the shape with those dimensions.
  - **Editing:** with no tool (click the active tool or press Esc), clicking a segment selects it and shows its dimension; constrained dimensions are always shown. Clicking a dimension (or typing a number, or Enter, with one segment selected) edits it. Dragging a point re-solves live and commits on release. Selecting one line, or two entities with ⇧, shows a strip of the constraints that fit (`applicableConstraints`); constraints show as glyphs beside their entities, and clicking a glyph selects it so ⌫ removes it. Each edit is one undo step: a new sketch keeps its own history; a reopened one edits the part, so every edit is a scene undo step.
  - **Drawing, picking and marks:** each `SketchEntities` render and each `hitTest`, `dimensionLabels` and `constraintGlyphs` query shares one `pointLookup` from `utils/sketch/lookup.ts` across its entity paths, radii, measurements and anchors. The lookup builds on its first coordinate read, so point picks and queries without marks skip it. It belongs to the query and rebuilds after edits. Duplicate point ids retain their last coordinates, missing points fall back to the origin, and paths, picking order and mark positions stay unchanged. `sketchShapes.test.ts` and `sketchMarks.test.ts` check mixed geometry, all dimension and glyph kinds, stacking, source preservation, edits, independent results and point-id reads. On 300- and 600-circle fixtures, picking and dimension queries reduce point-id reads from 180,000 and 720,000 to 300 and 600. Two-target glyph queries reduce those reads from 360,000 and 1,440,000 to 300 and 600. Drawing reduces those reads from 90,300 and 360,600 to 600 and 1,200, including its separate fill-profile lookup. Scratch comparisons matched 12,000 complete mark and picking results across 600 seeded mixed sketches and their edits, plus 400 complete SVG renders across 200 seeded mixed sketches and their edits. These are traversal counts, without timing assertions or a claim about complete Sketch rendering time. Entity searches remain unchanged.
  - **Deletion cleanup:** `removeItems` checks selected entity ids in one traversal, protecting reference lines by their first matching entity. It stops that lookup when every selected id has matched. Point retention collects discarded ids during the same pass, without searching the retained point list. Fixed and still-used points remain, and constraints on discarded ids are removed. The function keeps source order and object references without changing the source sketch. New sketches and reopened parts share this path, and each call reads current geometry.
  - **On a face:** clicking a part on the canvas remembers the face under the pointer; Sketch with that part still selected opens on that face (`faceOf` in `utils/sketch/face.ts` gathers the coplanar triangles of `partTriangles`, its plane and its outline). The face's edges are dashed reference lines with fixed points: they can be snapped to and constrained against but not deleted. With no face, Sketch opens on the ground plane.
  - **Output:** the profile (`sketchProfile`: the largest closed loop, with the loops inside it as holes; circles are loops) becomes one `custom_model` part with a `contour_extrude` node (or `lathe` for Revolve) sized exactly to the profile, standing on the plane (`sketchSolid` in `utils/sketch/placement.ts`). A negative T cuts: the part is a Cutout sunk into the face, for Subtract. Revolve spins the outline around the sketch's vertical axis and stands the result on the plane.
  - **Profile selection:** each call measures every loop's absolute area once, rejecting areas at or below 0.000001 mm² and NaN. The largest accepted area is retained during that pass, with the first loop winning ties. Hole containment and source order stay unchanged. The Sketch panel, new solids and edits to existing solids share this path, and every edit measures its current loops afresh.
  - **Profile tracing:** `sketchLoops` appends incident edges to endpoint lists and advances one cursor per endpoint through unused edges. Consumed edges never become available again, so each incident record is examined at most once. Shared-vertex branches retain source order, including edges consumed by open chains. Preview fills, profile selection and solid edits use this traversal. Lists, cursors and used ids belong to one call and rebuild after each edit.
  - **Path** (a new sketch only, the third mode beside Extrude and Revolve): designs a four-bar by the path its coupler point traces. Click points on the plane, or drag a stroke, which is resampled to 12 points by arc length (`useSketchPath`); drag a point to move it, ⌫ removes the last one and the eraser clears them. Every one of those edits, Clear included, is a step in the points' own history (`usePathHistory`, held by the panel), so ⌘Z and ⇧⌘Z undo and redo points and never touch the hidden Extrude/Revolve sketch. The line tools and Output hide. With 5 to 12 points, `synthesizeFourBar` (`utils/linkage.ts`) runs in the linkage worker (`src/linkage/linkage.worker.ts`) 250 ms after the last change. Up to three linkages draw over the plane (`SketchPathLayer`), each tracing its curve and sweeping its crank back and forth as SVG `<animate>` frames, so nothing runs a render loop; the view frames them when they arrive. A row per linkage below the plane shows its largest path error in mm; hovering one draws it in the accent. When nothing fits, the plane's ring turns red. Clicking a row inserts that linkage on the sketch's plane (`insertLinkage` in `useSketchSession`, `linkageParts`, §8c), selects it and closes the panel, as one undo step.
  - **Solver** (`utils/linkage.ts`, `linkageFit.ts`, `linkageKinematics.ts`, framework-free): a multi-start Levenberg–Marquardt fit of the coupler point to the points, 36 starts per crank direction from a fixed seed, so the same points give the same linkages. The unknowns are the crank pivot, the ground's direction, the four link lengths (as logs), the coupler point, the first crank angle and a positive step to each next point, so the points are visited in order within one turn. Each start is a random crank-rocker scaled onto the points by a similarity fit; a start whose cost is still 100 times the best so far after 25 iterations is dropped. Penalties keep the crank the shortest link and the linkage Grashof, with links of 10 to 300 mm. The path error at a point is its distance to the curve the coupler traces over the sweep. A linkage is kept when it's a crank-rocker with a transmission angle of at least 15° and a largest error within 10% of the path's span (at least 1 mm). Ranking: largest error in 0.25 mm steps, then a transmission angle of at least 30°, then how far the curve strays from the drawn polyline plus 0.02 × the linkage's size, so compact linkages that follow the drawing win ties. 5 to 12 points take 0.1 to 0.5 s on an M-series Mac, too long for one frame, hence the worker.
  - **Editable afterwards:** the sketch, mode, T and the profile's anchor are stored on the part (`ScenePart.sketch`). Double-clicking the part reopens its sketch; each change re-extrudes it in place (`partPlane` finds the plane again from the part's pose, so a moved part keeps its sketch), and Output then holds only T.
- **Import SVG:** opened from Shapes ▾, or by Import or a drop with an SVG, which loads it. Drop zone (Choose or drop an SVG, lit blue while a file is over it), samples, Paste Code, then Output: the preview with its shape count (and hole count when there are holes), then the Output fields (W, T, Bevel). The part takes the file's name and the default gray, like a sketch, and the Inspector renames and recolors it. “Edit in Sketch”, beside the preview, hands the outline to Sketch as lines at W wide.
- Adding a part from Sketch or SVG closes the panel and shows the new part in the Inspector.
- Both end in one Add button. To keep the result, use Save to Library on the new part (the bookmark in its Inspector header, or right-click); the model it saves inserts that same part again.
- Combine lives in the multi-selection Inspector, the right-click menu and ⌘K; nothing floats over the canvas for a multi-selection.

- **Boolean drill picking accumulates surface gaps directly.** `booleans/picking.ts` scans every intersection and retains the nearest operand without gap lists or ranking records. One intersection array is cleared before each probe and reused throughout the call. Entry and exit faces both count, equal gaps retain the first operand, and misses return no operand. Double-click, command-click and selection within nested booleans share this picker. `picking.test.ts` covers cut surfaces, drill gating, entry and exit distances, ties, misses and fresh geometry after edits. [Evidence](../notes/performance-selection.md#boolean-drill-picking-accumulates-surface-gaps-directly).

- **Align retains measured bounds throughout each command.** `utils/selection.ts` measures each unlocked selected part once and reuses its bounds for the shared target and position update. The target scans only the requested axis. Single-part origin alignment, rotated and affine sheet bounds, rounding and locked-part exclusion stay unchanged. The Inspector, right-click menu and command palette share this path. `selectionAlignment.test.ts` covers all axes and anchors with rotated and affine parts, later edits, untouched references and bounded dimension reads. [Evidence](../notes/performance-selection.md#align-retains-measured-bounds).

- **Align and Spread index the selection once.** `utils/selection.ts` filters unlocked parts through an id set shared by both commands. Align applies positions through retained bounds keyed by the selected part objects. Membership work is linear in scene and selection size, with Spread also sorting the selected parts by position. The Inspector, right-click menu and command palette use these same helpers.

- **Selecting groups uses membership sets.** `expandToGroups` scans the scene twice, collecting selected group ids and then their missing members. Ordered additions, group toggles and drill-in detection also use sets, keeping membership work linear in scene and selection size. [Evidence](../notes/performance-selection.md#selecting-groups-uses-membership-sets).

### Sketch support references

The Sketch support browser walkthrough uses a local scene save/read fixture, so Open Scene File can retrieve its imported record through ordinary scene loading. It retains the new-tab, saved-reference, mesh-span and authored-point assertions.

A sketch made on a unique, axis-aligned rectangular face stores an optional versioned support reference in `PartSketch.support`. It records the supporting part id, local normal and face frame, canonical corner ids and a geometry fingerprint. Canonical corners keep reference-point identities independent of triangle order. Existing sketches without a support reference keep their previous placement and editing behavior.

The supported face has four straight boundary edges and one plane for its signed local normal. Rigid translation and rotation, thickness changes and rectangular outline resizing can resolve that face again. Split boundaries, holes in the supporting face, competing parallel surfaces, booleans as supports, sculpted sources, deformers and affine sheet transforms are outside this subset. Boolean operands retain their own source identities, so a cutout can refer to the original operand without referring to the enclosing Subtract result.

Face capture and dependent rebuilding use the geometry worker. Rebuilding updates fixed reference corners, runs the existing constraint solver and creates the solid through `sketchSolid`. Authored coordinates remain in millimeters. Constraints to reference points or edges continue to use those identities when the reference geometry changes. A failed reference, solve or profile keeps the last solid and produces a Sketch blocker in Checks. Double-clicking a supported sketch exposes Select Face, which returns to ordinary canvas picking to replace its support reference.

`useSketchSupportResults` applies completed results only to the exact document parts array submitted for preparation. Successful results replace the current edit without adding a history entry. Undo and redo therefore retain the source and its completed descendant update together. One request runs at a time, with only the latest intervening parts array retained for the next request. The resolver limits the support graph to 128 bound parts, 16 dependency levels, 512 sketch items per rebuild and 16 MiB of counted triangle coordinates.

`supportDesigns.integration.test.ts` covers ten generated CAD assemblies: rover deck and battery pocket, arm pedestal and mounting holes, quadruped hip bracket, hexapod body and electronics standoffs, pan-tilt camera mount, gripper jaw pad, sensor enclosure lid, wheel hub flange, linkage ground plate and appliance service opening. It uses real face projection, constraint solving, worker preparation, mesh volume and hole ray intersections, BOM purchasing identities and Checks inputs. It also covers chained sketches, actual scene serialization and portable-file reopening, duplication, clipboard copies and ordinary agent replacement commits. `supportFailures.integration.test.ts` includes a real Subtract pocket, split and competing planes, malformed records, duplicate identities, nonfinite transforms, payload limits and a seventeen-level chain. Existing resolver tests retain retriangulation, unsatisfiable constraints, cycles, unbound sketches and last-valid-geometry coverage. Document and queue tests cover complete history, stale completion and cancellation. `e2e/sketchSupport.e2e.test.ts` declares the ordinary canvas, Inspector, undo/redo, scene-file and explicit replacement walkthroughs for Linux and Windows CI. [Evidence and limits](../notes/testing-build.md#sketch-support-regeneration).

Saved support fingerprints are not accepted as proof of a current solve. Each newly loaded record requires worker validation. Successful results are remembered only in a weak map keyed by the immutable record and its source fingerprint. Source edits, reopened Sketch edits and scene reopening therefore share regeneration. Malformed geometry references are rejected before any freshness shortcut. Reference entity ids and their fixed corner endpoints are validated as well as finite authored geometry and dimensions.

Worker jobs use a 2 MiB input-value budget, with 512 KiB per source geometry record before fingerprint serialization. Source preparation is limited to boxes, generated CAD meshes and bounded custom-model nodes. Custom models have at most 16 nodes, 512 contour/profile points per node and 64 lathe segments. The worker counts mesh coordinates before allocating the exported triangle soup. No rendered-edge jobs are deferred from preparation. These are bounded software input and allocation controls, not a claim that every accepted source is manufacturable.

Duplicate and clipboard copies remap a feature's support when the support is copied with it, including embedded boolean operands. Copying only the feature makes an independent sketch at the copied pose. Select Face is also in the command palette for a selected supported sketch. Escape cancels selection, and a scene change or intervening edit invalidates its captured document identity. Unsupported replacement faces report an error and keep the prior reference and solid.

Worker completions apply only the regenerated pose, dimensions, role, custom nodes and sketch record. Document metadata, notes, visibility and locks stay on the original part, rather than taking the worker payload's preparation defaults. `sketchSupportResults.test.ts` exercises this through `prepareSupportJob` and a cloned worker payload. Mirror clears the support reference on its reflected copy, including boolean operands, so regeneration cannot return it to the original face. `supportDesigns.integration.test.ts` checks that the mirrored solid stays independent after a source edit. Both the person’s Mirror command and the agent use `mirrorPart`.

Sketch solid creation normalizes the exterior and hole loops to opposite winding before extrusion. The production mounting-hole test checks actual mesh volume, rather than accepting a profile record as proof that the hole has correct surfaces. Editing a supported sketch clears a prior resolution attempt so corrected constraints can retry. An open supported outline keeps its previous geometry and its profile finding.

The Sketch constraint strip offers Distance for a point and a line, or two distinct points with a nonzero distance. It initializes from the existing distance residual without moving the geometry. Clicking its numeric label edits the same stored constraint through the existing solver. This exposes point-to-reference-edge offsets without another solver or feature-history surface. RulerIcon is reused from the design system. `distanceConstraint.test.ts` drives that selection action and edits a measured offset to 8 mm. The browser walkthrough authors the same offset before resizing the deck width. Canvas picks retain a source fingerprint, and a changed source requires another pick before starting a supported Sketch. A point outside the chosen face or off its plane cannot create a support reference.
