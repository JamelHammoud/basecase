# Simulate and train

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 8d. Simulate & Train (MuJoCo)

Servo population spreads use `utils/gaussian.ts` to transform parameter covariance into dynamics covariance. Each covariance-row product is prepared once per output row, preserving the previous summation order without assuming symmetry. For the six dynamics terms and seven servo parameters, covariance-entry reads fall from 1,764 to 294. At twelve output rows they fall from 7,056 to 588. `gaussian.test.ts` checks exact arithmetic against the previous transform across 160 generated rectangular inputs, frozen inputs, later edits, nonfinite values and complete fitted servo spreads. These are operation counts, not complete training timings. The app still supplies no populations by default (§8k).

MJCF body generation groups owned part ids once through `utils/kinematicsMembers.ts`, after `adoptEmbeddedParts` finishes. Every joint body reads only its group's ids and applies the existing solid-part filter. Child lists append into their existing arrays. Body order, names, geometry order and fixed-joint numbering stay unchanged. Weight and engineering checks share the owned-part grouping through `reality/bodyLayout.ts` (§8k). `mjcfMembers.test.ts` compares complete models with scan-based membership across fixture robots and edited visibility, roles, fixed joints, source order and embedded-part placement.

Contact-replay capture fixtures use `electron/cad-kernel/pairKey.mjs` for unordered body names, preserving their null separator and lexical order without sorting each contact pair (§0f). The final contact list remains sorted.

Drive input declarations and defaults live in `src/sim/inputRegistry.ts`. The Case parser reads them without importing live input handlers. `inputSources.ts` registers those handlers and declares additional source ids through the same registry. `inputSources.test.ts` checks declaration parity, Case validation and an additional source reaching the drive.

Each simulation worker subscribes only to its workspace’s simulated and operator camera inference. Recorded playback results stay in that workspace’s playback console and never reach live Routine facts. `subscribeLiveSceneVision` supplies this boundary and `src/cameras/sceneVision.test.ts` checks opposing detections in two scenes.

Depth eyes and simulated LiDARs share reusable world-ray buffers in `src/sim/eyes.ts`, described in [Cameras](cameras.md). Buffers belong to each compact sensor and refresh from the current pose on every cast. LiDAR hit callbacks write directly into their slot's existing point buffer. Published scan snapshots keep independent copies.

Quaternion vector rotation in `src/sim/quat.ts` evaluates `q * [0, v] * conjugate(q)` with scalar intermediates, preserving multiplication order and non-unit quaternion behavior. All callers avoid the four temporary quaternion arrays. `rotate` returns a fresh result by default, or fills the supplied output array from a vector at the supplied offset. Recorded scan reconstruction uses that output across rays. `quat.test.ts` checks exact product parity, nonfinite values, signed zero, typed-array views, offsets, independent results and aliased output storage.

LiDAR scheduling in `src/sim/scanner.ts` visits slots directly without allocating a due-sensor list on each physics tick. It updates kinematics once before the first due sensor, casts in source order and increments the scan version once per tick with a scan. Idle ticks perform no kinematics. Each sensor keeps its own deadline, including the existing 1e-9-second tolerance and reset after time moves backwards. Live simulation, headless runs and recording share this scheduler. `rayCasting.test.ts` checks mixed scan rates, deadline boundaries, repeated timestamps, nonfinite times and rewinds against the previous scheduling rule. Its 311- and 611-tick fixtures allocate zero filtered lists, down from one per tick. These are operation counts without timing assertions or a claim about complete simulation time.

Robot Computer installation reuses the Robot Package worker's joint-map generation. `robotJointMapJob` can request a fresh model for manufacturing-kit snapshots instead of reusing simulation metadata. It prepares only the model's joints and robots, scene parts and project calibrations. `exportRobotJointMap` strips embedded CAD and mesh payloads before sending that input to the worker, and returns the map without measuring geometry, loading policy files or generating a ZIP. The installer derives the daemon's `calibration.json` from that checked map. Full package export reuses the same metadata input before adding its meshes, measurements and policies in `src/workspace/robotPackageExport.ts`.

Stages 3 and 4 of the robotics loop (§1); milestones in [docs/Robotics loop.md](../../docs/Robotics%20loop.md). The **Simulate** tab (right panel, shown while the scene has parts) runs the scene's robots under MuJoCo physics and trains policies for them. It also holds Study (§8b) for scenes with or without joints. Physics needs movable joints.

- **One formulation, one model, one oracle.** MuJoCo's formulation runs everywhere: the live sim (`@mujoco/mujoco`, DeepMind's official WebAssembly build), Forge's own batched physics for training (§8g), and C MuJoCo as the unforked oracle, all from the same generated MJCF at the **same pinned version**. Forge may train on a cheaper profile of the model, but a result counts only after replay on the reference model in C. Never add a physics engine with a different formulation.
  - **Pinned at 4.0.0.** The trainer takes `mujoco-core` (4.0 split the Python package into `mujoco-core`, the bindings and C library with only `numpy`; `mujoco-studio`; and `mujoco`, which installs both): `train.py` and `verify/` need nothing from Studio, and `rollout` is in core. 4.0 needs Python 3.11 or newer.
  - **Updating MuJoCo:** `node tools/sim/update-mujoco.mjs [version]` (latest when omitted) bumps `package.json`, `electron/trainer/pyproject.toml` + `uv.lock` and Forge's `VERSION` (`forge-mujoco/build/fetch.rs`, which `tools/forge/stage.mjs` reads too) together, then runs `node tools/sim/smoke.mjs`, which fails if the three pins differ or the WASM and Python engines differ in version or in result. Never bump one side alone. Then read the release notes against what `mjcf.ts` generates and what `forge-ir` accepts (a new enable flag or model feature must be refused until Forge implements it), rebuild Forge (it fetches the new C library), and rerun every gate that touches physics: `s0-foundation`, `s1-f1-native-trainer`, `s1-f1b-sysid-rewardlang`, `s1-f2-learner`, `s1-f3-simd-engine`, `s1-f4-metal`, `s2-m1-first-case`, `s3-servo-models`, `s3a-motor-kit`, `s4-routines-core`, `s4b-routines-flow` and `s5b-daemon-app`. The `s3a-motor-kit` run retrains the Kit on the new version; refresh `src/routines/kit/` from it (`node tools/routines/kitLibrary.mjs quad-servo:velocity-tracking quad-servo:settle-to-neutral`), so the committed policies record the version they were trained on. We consume upstream releases; we don't fork MuJoCo's C code.
  - **What 4.0 changed for us:** nothing in the generated models. Its breaking changes are in tendons (sidesite), flexes, the removed cable plugin and `composite`, RK4 with ball or free joints, height fields, cameras and skins; we generate none of those. The fixes that touch our features don't apply either: implicit actuator derivatives are now skipped under a saturated joint or tendon `actuatorfrcrange`, and we clamp with the actuator's `forcerange` (already skipped before 4.0); accelerometers on static bodies (we have no sensors); pair `solref` mixing (no explicit pairs); `boundinertia` now also bounds non-positive-definite inertias that used to fail to compile (we set it, so a degenerate hull now loads instead of erroring). Native CCD's numerics changed, which can move hull-to-hull contacts (robot against scenery or SimReady objects) at rounding level; plane contacts don't use it.
- **The scene is the source of truth.** `src/sim/mjcf.ts` (`buildMjcf`) writes the MJCF from the scene; never hand-edit or store a model file as truth. Fix the design, and the model follows.
  - Bodies: one per joint (`buildRig`), holding the parts that joint moves, under a root body with the robot's base. `src/sim/morphology.ts` classifies each robot as fixed, legged, wheeled or wheel-legged from its joint tree, names and catalog parts; anything but fixed floats (free joint), and `MjcfInput.fixedBase` overrides it. Continuous wheel joints get `velocity` actuators, and `SimJoint.actuator` maps joints to actuators, so never assume the two share an index. Parts with `physics.dynamic` (SimReady objects, §8e) get a free body per group, with their own mass and friction (`priority="1"`, because MuJoCo otherwise takes the higher of two friction values and the 0.9 default would hide anything lower), and collide with robots, scenery and each other. Every other solid part is fixed scenery, except one whose mesh starts sunk at least 2 mm into a robot part's mesh on every axis (bounds of the placed meshes, not the listed size, since a catalog part keeps its own mesh) and is smaller than that robot (a speaker or sensor placed on it but not grouped with it): it rides on that part's body and adds its mass (`mjcfEmbedded.ts`). A part that only rests on the robot, or encloses it, stays scenery.
  - Body frames keep the world's orientation at rest (origin = the joint's pivot), so sim poses map back to parts without rest rotations. `mjcfFrames.ts` shares the conversion between full maps (`simDeltas`, `worldDeltas`) and individual reads (`simDelta`, `worldDelta`). Individual reads find the last body owning the requested id and transform only it, matching map overwrite order without retaining a cache. End-effector stats, steering, probes, dataset hand paths, mat paths and the agent's operate report use individual reads. Rendering and whole-world facts retain full maps.
  - Frames: scene mm Y-up → MuJoCo m Z-up as `(x, −z, y) / 1000` (the agent frame). The robot faces −Y.
  - **Sketch four-bars close physically.** Existing `loop` records (§8c) emit passive coupler and rocker hinges plus one MuJoCo connect equality at their shared C port. The crank retains its real catalog actuator, limits and measured fit. Malformed, impossible or singular initial configurations refuse simulation rather than welding the bars. Imported assembly constraints remain outside this representation.
  - Geoms: the convex hull of each part's mesh (hull vertices only, `maxhullvert` 96, `inertia="convex"`), mass from `partMasses` (§8b), inertia from the hull. Sheet thickness transforms are included in the local mesh triangles. World items with a `sheetTransform` use that transformed hull instead of the original primitive dimensions. Robot geoms collide with other robots, the floor, scenery and dynamic objects. Geoms within one robot never collide because their rest-pose hulls overlap. Exact self-collision stays with the mesh sweeps in `three/interference.ts`.
  - **Measured bodies** (`src/reality/bodyModel.ts`, §8k): after emitting the preset model, `buildMjcf` applies each robot's active Measured version from `project.bodyCalibrations`. `MjcfInput.bodyFits` overrides a saved fit for candidate replay. `applyBodyFit` and `applyBodyFits` scale the actual geom masses, so MuJoCo derives matching inertia, and add each terminal payload as a 1 mm noncontact sphere. `SimModel.bodyPayloads` carries each terminal body's payload position in its local MuJoCo frame. The position is the farthest transformed part bounding-box corner from the pivot, with part-id and corner-order tie breaking (`bodyLayout.ts`). Fitting and playback call the same transform. Floor friction scales static contact surfaces with `priority="1"`, including scanned floors. The floor belongs to the world: the newest active version's `recordedAt` selects its scale once, with robot-key order breaking equal or absent timestamps. Explicit candidate overrides take precedence. Every robot's fingerprint includes that effective floor scale, and rollback restores the next active version's floor or the preset. A fit's `bodyKeys` map emitted body names to `joint:<raw joint id>` or `root:<robot key>` and remap it after unrelated robots change scene numbering. Fingerprints use those stable keys too. Robot Package URDF inertials use the same measured weights and centroids as Checks. Export keeps a terminal payload separate from its carrier part, with the same 1 mm sphere inertia and the parallel-axis shift about the combined link centroid, rather than spreading that mass over the carrier’s bounding box. URDF inertia components keep nine significant digits, independent of the six-decimal length formatter. An identity fit preserves the model exactly. A saved fit whose links no longer belong to that robot, or whose payload link is no longer terminal, is skipped by both MJCF and Checks. Explicit candidate fits instead reject those inputs. Removing the active version restores preset physics and its fingerprint.
  - **Measured servos** (every servo on a revolute joint has an `ActuatorSpec.fit`, §8a; `src/sim/servoModel.ts`, `mjcfServo.ts`): BAM's voltage P law, at the variant's `atVolts`. `kp` = kt / R × firmware P × error gain × V; `kv="0"` set explicitly (the firmware runs D 0, and `dampratio` resolves only at compile time, so randomized armature or mass would leave a stale `kv`); joint damping = viscous + kt²/R (back-EMF); armature from the fit; force range ±kt × max duty × V / R. Damping sits on the joint, outside the force clamp, so a saturated servo still loses torque with speed, as a voltage-limited motor does. `frictionloss` = M6 base friction + `load_friction_external` × the weight moment beyond the joint (`holdingLoad`), a static stand-in for BAM's load-dependent friction. The servo's command delay uses MuJoCo's native actuator delay (`delay`, `nsample` = ⌈delay / timestep⌉ + 2, linear interpolation). These joints read `dynamics: 'measured'`. A joint with a calibration (`MjcfInput.servoFits`, set by `calibratedInput`, §8k) uses its fitted `ServoFit` and volts in place of the catalog's. Given populations (`calibratedInput`'s third argument; the app passes none yet), a joint with none whose servo has a population runs on the population's median instead, with `nsample` long enough for the slowest delay its spread draws, and the model carries the spread (`SimModel.servoSpreads`) for training and Arena to draw from (§8k, §8i). `MjcfInput.servoVolts` rates every catalog servo at one supply voltage instead (`ratedAt` in `mjcfEffort.ts`: `ratingAt`'s stall and rated torque, interpolated along the variant's `curve` and capped at its top voltage, as the Servo torque check rates it, and `atVolts` set to that voltage for the measured law). Study and classroom grading set it (§8h); everything else runs each servo at its catalog `atVolts`.
  - **Estimated servos** (no fit, or no servo): range from `RobotJoint`, force limit from the servos' stall torque (`actuatorOf`), else the published `effortNm`, else an estimate from the weight the joint holds. `kp` reaches full torque about 10° off target, `dampratio` 1, armature from the torque. Checks' Torque estimates row (§8b) and the agent's sim report count these (`effortSource: 'estimate'`, `dynamics: 'estimated'`). Checks' Servo models row counts every joint without a Measured calibration (§8k), catalog fits included.
  - **Not modelled:** the STS3215 firmware's target rate limit (BAM's `max_velocity`, 5.1 rad/s), current limits, Stribeck and motor-side load friction, supply sag and backlash. The gate shows the rate limit is the largest remaining gap on steps (a light-load step is 21 mrad RMS off BAM, against 22 for a fitted first-order-plus-delay); adding it means a per-substep target ramp in the engine, `train.py` and Forge alike.
  - **Delay history:** a delayed actuator reads past controls, and MuJoCo starts that history at zero, which would yank every joint toward 0 at reset. `SimEngine.reset` and `respawn` fill it with each joint's current position (`primeCtrlHistory` → `mj_initCtrlHistory`), and `train.py` does the same with `ctrlDefault` before saving its start state (`mjSTATE_FULLPHYSICS` includes the history, so every episode reset restores it). Anything else that resets a model with delays must do the same.
  - **Proof:** gate `s3-servo-models` (§0k) runs plant-bam's nominal STS3215 at 7.4 V and XL330 at 5 V on four pendulum loads through a step, a 0.2–5 Hz chirp, a multisine and a hold against gravity (`verify/servo/bam-reference/`), and requires the sim's RMS error to beat half the teleport baseline and a first-order-plus-delay filter fitted to the same BAM trajectory, on every run. It also checks no fixture robot is kicked at reset and that WASM matches C MuJoCo with delays.
  - The start state is the pose on the canvas, lifted to just above the floor.
- **Simulating never edits parts.** Like posing (§8c), the sim only moves what the canvas shows (`Viewport3D.setPose`). Ending it, or editing parts or joints while it runs, returns the canvas to the posed model.
- **Grasping** needs no contact settings of its own: a gripper's sliding jaws get the estimated position actuators (full force 5 mm off target), and with the default friction (0.9) and `condim` 3 the fixture arm's 5 N fingers lift and carry Pick Up a Block's 21 g cube (§8h).
- **More than one robot** (a Case's slots, §8h): every robot goes into one model, in one worker. Robots from other tabs arrive with every part and joint id prefixed by their slot (`b.arm3`), so the writer needs no special case: bodies, geoms and meshes are named from those ids and joints and actuators by index (`j9_b_arm3`), and `slots.test.ts` checks two copies of one arm compile with no repeated name. Collision membership follows `Rig.robots`, including each robot's adopted embedded parts. `mjcfContacts.ts` reserves bit 0 for world contacts and assigns each robot one of the other 31 bits. Each robot accepts the other robot bits, excluding its own. The single-robot model keeps its original `contype="1" conaffinity="0"` masks. Above 31 robots, the first 30 keep separate bits and the remaining robots share bit 31 with contact enabled, plus body exclusions within each shared-bit robot. Only these oversized models need exclusions, which Forge currently refuses (§8g). Fingerprints normalize these scene-dependent masks, so adding or reordering another robot does not change a robot's fingerprint. `mjcfContacts.test.ts` compiles the masks in WASM and checks actual contacts, self exclusions, markers and the 31-bit boundary. A drive for several robots is one `TeamSetup`: each member is a robot's own drive (arm, rover or legs), its `tick` merges their targets, a command's `slot` picks the member, and `SimStats.effectors` lists each member's hand. The live worker also takes a `script` (commands with times, played against sim time), which is how a try runs the other slots' reference while you drive the first. `slots.test.ts` requires the two-arm physical reference to finish faster than its simulated duration.
- **Contact parity:** `node tools/sim/contactParity.mjs` compares generated 1-, 2-, 31- and 33-robot contact models against pinned C MuJoCo, including signed masks, overflow exclusions and a delayed-actuator replay. `--handoff` generates the physical handoff and five failure variants, captures the integration state and every 2 ms control, replays those controls in C, and scores the native body poses and contacts with the same Case contract. Contact graphs must match at every 50 Hz sample and replay state drift must stay below 1e-6, the existing native parity rollout tolerance. `--out scratch/contact-parity.json` saves the native samples and verdicts. Extra JSON files can supply captured replays through `src/sim/fixtures/contactReplay.ts`. Samples start at step 0, then every 10 substeps, matching `Recorder`.
- **World items** (§8h) come in through `MjcfInput.world` (`src/sim/mjcfWorld.ts`): bodies with no parts, posed by `worldDeltas`; markers don't collide. Terrain (§8h, Terrain) is only static boxes, a ramp a box turned about x, so the writer has no height field and nothing changes in the MJCF for it.
  - Imported worlds use the V-HACD pieces registered with their asset (§8h, Captured and generated worlds), rather than one convex hull of the whole room. `importedWorldItems` turns those pieces into hidden static world items with `convexVertices` in studio millimetres. `mjcfWorld.ts` writes each piece directly as a separate convex mesh, converting `(x, y, z)` to MuJoCo's `(x, -z, y) / 1000`, without rebuilding its triangles. A room's table gap and doorways therefore remain open in the physics model. Static imported hulls replace the implicit infinite floor, so holes and space below the imported floor remain open too. Ordinary Cases and RoomPlan worlds keep the implicit floor.
  - Recorded scan worlds use the same imported asset and static mesh path. Their worker merges only adjacent occupied cells into exact convex cuboids, with a hard 64-piece limit. No global convex hull or lossy decomposition can fill an observed corridor or table gap. Depth and point-cloud floors and stairs come from observed surface cells. A planar scan's floor and 1 m extrusion are estimates recorded in provenance and labeled in New Case (§8h).
  - `caseWorldItems` adds the pieces for headless runs and live tries. Case check jobs transfer only collider items, independent of the robot-model cache. Visual meshes, textures and splats never enter the simulation worker. The recorded model embeds its collision geometry in the MJCF, so Multiply uses the same colliders as the original try.
- **Off the main thread.** `src/sim/sim.worker.ts` runs `SimEngine` (`src/sim/engine.ts`, no DOM, so it also runs in Node) in real time × speed and posts body poses per frame, with each joint's target, position and actuator force (`jointStates`, three numbers per joint in `SimModel.joints` order, in rad or m; the target is the actuator's control for position joints, the joint position otherwise). `SimEngine.contactPairs` reads active MuJoCo contacts into deduplicated pairs of `SimModel.bodies` indices, caching the contact wrapper once per read and freeing it afterward. `Recorder` stores those pairs at 50 Hz for replayed grip evidence, and the live worker transfers the current pairs for live probes. `WorldMoves` refreshes MuJoCo forward state after pose, visibility and reset changes, so live probes and a recording’s first frame cannot retain contacts from before an object moved or disappeared. Color-only edits leave physics state alone. `worldMoves.test.ts` checks these transitions for dynamic and mocap objects without stepping time. Seeking transfers a copy of the saved frame's contact pairs, with an empty array for recordings without evidence, rather than contacts recomputed by `mj_forward`. `simRecording.test.ts` exercises the worker's load, scrub and seek messages for saved, empty and legacy evidence. A connected emulated robot follows the targets from Test up (§8k), and a running Case's signals read all three (§8h). `Simulation.run()` steps a fresh model headless in its own worker (for agent checks) without touching the live one. `Simulation.runRoutine()` loads the scene and sends a `routine` message: the live worker then steps a Routine's L1 run (§8j) in place of free stepping and posts its new trace events with each frame.
- **Controllers:** Hold pose, an animation's keyframes (does the walk cycle really walk? A dynamic move on legs usually falls this way; train it as a move instead, §8i), a trained policy (a move's policy also reads a clock, `PolicySpec.clock`, counted in control steps from when the controller starts), a skill (Try in the Train section), Drive (live commands by robot class or through a ready Walk, §8h), a route (`route.ts`: timed base travel followed by feedback, through a velocity policy or a rover's wheels, §8i), or Limp (zero force range, so only passive joint damping and friction remain). Push (`src/sim/push.ts`) shoves the robot in a random horizontal direction for 0.15 s: with half its weight, or twice it on wheels (`pushShare`), since a rover's held wheels grip far harder than half its weight. The fixture rovers move 20–30 cm and stay upright, and a crouched quadruped stays standing (`push.test.ts`).
- **Policy output bindings** (`engine.ts`, `policyStep.ts`): direct policies and policy-driven routes retain actuator addresses in policy order when the controller starts. Physics substeps write through those addresses without searching the model's joint list. Passive joints are skipped, and reset, respawn or controller replacement prepares fresh bindings. Observation addresses and output addresses come from the same joint selection.
- **Scheduled inputs** (`simRun.ts`, `utils/timelineCursor.ts`): worker scripts and headless commands use `commandTimeline`. Headless pushes and requested frames use the same cursor. Each schedule is copied and stably sorted once, then consumed without moving its remaining entries. Headless runs still apply pushes before commands and capture requested frames before stepping. Commands and pushes at the run's end stay unapplied, and any pending frame requests produce one final frame.
- **Route sampling** (`route.ts`): timed route keys are ascending. `routeAt` uses `utils/timeIndex.ts` to find the first key strictly after the requested time, keeping the following span's velocity at an exact key and holding after the last key.
- **Motor Kit starts and turns** (§8i, §8j): the desktop, installed-policy and browser Kit select and accept candidates through the same `trainKitEntry` path. Before a Velocity candidate can replace a ready skill, the Routine prover checks starts from the actual Settle controller, both turns in place, stops and starts from sampled turning phases. Walk and Turn start after the actual Settle controller before their phases are sampled. Reverse jobs also check reverse starts. Routines keeps each pair's movement verdict separate from isolated Arena evidence and refuses Run for a failed required pair. Changing physics, actuators or either controller invalidates the affected proof. Training reuses the existing continuation schedule and feeds a failed stance's joint positions and height back into its next stage. The live predecessor, including its momentum, is exercised during validation. The training reset does not replay its velocity or controller memory. Validation time and candidate count are reported separately from total time to readiness. Arena bars, seed counts and training-minute budgets stay unchanged.
- **Physics settings** (`src/sim/livePhysics.ts`, the worker's `physics` request, `Simulation.setPhysics`): scale the live sim's friction, link masses and servo force limits and delay its controls, the way `ArenaWorld` does for one Arena try (§8i). Both use `ControlDelay` (`src/sim/controlDelay.ts`) to wrap `mj_step`, reusing a ring of control snapshots after startup. Until the delay fills, it holds the first command. Applying settings or attaching a model clears the ring. The worker keeps the model's own values to restore. Clicking a Stress finding sets them (§8i), and Try or a snapshot clears them. Loading a model starts from none. Each frame carries what the model holds now, measured against those values (`physics`: friction and strength as ratios, mass as the ratio of all link masses, delay in ms), and `__studio.simState().physics` reads it.
- **Faults** (`src/sim/faults.ts`, `SimEngine.setFault`, the worker's `fault` request): while the sim runs, Fault ▸ Limp, Weak, Stuck, Laggy or Clear on a Peak torque row or a canvas part moved by a joint (§11) fails that one servo in place. Faults are keyed by the joint's actuator, never its index.
  - Limp zeroes the actuator's force range and Weak halves it; Stuck holds its target where the joint is (zero speed for a wheel) at full range; Laggy holds each command back 60 ms (`LAG_S`). Clear restores the saved range exactly.
  - The Limp controller goes through the same save-and-restore (`ActuatorFaults.setLimpAll`), so a faulted joint stays faulted when the controller leaves Limp, and a Limp robot comes back with its faults.
  - Laggy is a delay line in the engine, filled with the current command on its first step and again after Reset or respawn, so the joint never jumps. It isn't MuJoCo's actuator delay: that history is sized at compile time to the servo's own delay, and enlarging it would change the actuator XML and with it every policy's fingerprint.
  - Faults last through Reset and respawn (a broken servo stays broken) and end when the sim stops. An active fault shows as a badge on the joint's Peak torque row, which stays listed at any torque.
  - The quad fixture crouched on Hold sinks and leans when one knee goes limp, and the hexapod stays up on five legs (`engine.test.ts`). A Case's own fault list, randomised faults in seeded runs and fault-aware training aren't built.
- **Grab and fling:** while a simulation is loaded, the Move and Rotate gizmos grab instead of edit (`Viewport3D` `onGrab`; parts never change). The dragged part's body is pulled toward the gizmo on a critically damped spring scaled by its robot's mass, with gravity compensated (`SimEngine.grab`, like MuJoCo's viewer perturbation), so a slow drag lifts or turns the robot and a quick release flings it. A multi-selection grabs its first part, and its gizmo follows the robot.
- **The tab** (`SimulatePanel.tsx`, sections in `components/simulate/`): the run controls, then the open Case and Try (§8h), Study (§8b), Control (controller, Push, and Drive without a Case; while driving, the controller reads Drive whatever drives the joints, and picking another stops driving, as Esc does, so a Case's try ends; it's disabled only during the fall check, which says “Checking it stays up” under it), Train, then Results. It shows what a run did and what to do next; findings about the model belong to Checks (§8b), and a connected robot's telemetry to Operate (§8k).
- **Results:** the latest run first: per robot "Standing" or "Fell at 2.4 s" (tilt over 60° or the root below 45% of its start height), tilt and distance moved; Peak torque lists faulted joints first, then the hardest-working (peak / limit, time at the limit); a click selects the joint's link and a right-click offers Fault ▸. With a Case open, its tries, Export Dataset and Publish to Hugging Face follow (§8h): the hand-off to training off the Mac, as LeRobot v3.0 that `lerobot-train` loads with no conversion, beside v2.1 for GR00T.
- **Seeded Case inspection** (§8h): `Simulation.start` accepts the replay job's model so a seed with jittered world bodies fits its recording. The timeline keeps the previous world, guest robots and loaded model across seed and saved-try switches and restores them on close, including whether the sim was off, paused or playing. Seed replay effort arrays are calculated in the Case worker with that seed’s randomized physics, transferred with the recording and reused by `scrub` after its model-fit check. Changing worlds or stopping cancels pending model builds and loads. Load replies carry their request id so a superseded ready message cannot start the next replay. The ordinary start still builds from the scene.
- **Scrubbing a recording** (the try timeline, §8h): `scrub` hands the live worker a recording and halts free stepping; the worker checks it fits the loaded model (`fitsRecording`: same `nq`, `nv`, `nu`) and replies with two `Float32Array`s of actuator force per joint, transferred (`recordedEfforts`, `src/sim/recordedFrames.ts`): `peaks`, for the timeline's lanes, and `forces`, for the console's `joint.*.effort` during playback (§8h). Each frame's peak is the largest force over the 20 ms that led to it, and its force is the one after the last substep, which is what the live frame reads: the worker sets the previous frame's qpos, qvel and ctrl, primes any delay history from the recorded ctrl, and re-steps the physics substeps with the frame's ctrl, so a transient between 50 Hz frames isn't missed and the peak matches the live Peak torque. `seek` sets one frame's qpos, qvel and ctrl, calls `mj_forward`, posts the frame's poses and replies `sought` with the qpos it set. Play and pause are the page's: it seeks frame by frame on `requestAnimationFrame` only while playing. The worker keeps the recording until `scrub(null)`, a new model or `dispose`, so the live Play runs on from the frame shown and the next seek goes back into the recording. There's no play-only replay timer.

A crash reads as a crash rather than a stop. A Kit or move run that ends without a skill says why on its row (§8i). Train on a taught skill sends its words to the agent again. In the web demo it lists only the Kit, trained in the tab, and shows only on a browser that can train there (§8i). Trained policies close the section (below).

Stop saves what it learned. The policy is checkpointed every minute, then evaluated in a clean 8 s run.

- **Walk trace** (`walkSim` in `src/agent/agentPeak.ts`, `TorqueRecorder` in `src/utils/peakTorque.ts`, `servoAmps.ts`): with `trace: true` the run records, per joint and 25 ms window, the mean torque the joint asks for (absolute and signed), its mean speed, the mean square of the force it delivers, and, for joints given an amp model (`currents`), the mean current. Current comes from the delivered torque: a servo with a measured model draws |τ| ÷ kt plus its idle amps; any other goes from `idleA` to `stallA` in proportion to |τ| over its stall torque at the supply voltage (`ratingAt`), with 0.15 A idle and 2 A stall when the catalog has none. A joint with several servos splits τ evenly between them. `walkPower` sums the joints per window into the servo bus and returns its average and peak, and each joint's, after the first second; the Build checks turn that into pack amps and runtime (§8b).
  - Current aggregation reads each post-settle sample once, keeping running sums and peaks per joint and for the bus. It never copies current traces or builds an array of bus samples. The bus uses the common span of the nonempty joint traces. Each joint's readings include its own remaining windows when traces differ in length. Empty traces stay out of the result. `servoAmps.test.ts` covers settling boundaries, simultaneous bus peaks, unequal traces and long recordings.

- **Stale models** (`src/sim/policyFreshness.ts`, `isStalePolicy`): a policy is stale when it was trained on an older sim or on a different model of its robot.

Scene-wide numbering (`j3_`, `m5_`, `root_1`) is dropped, so scenery, world items, other robots, the canvas pose and moving the robot don't change it; a resized link, a mass, a servo or a new active calibration (`calibratedInput`, §8k) do, and rolling a calibration back restores the old one. `trainingJob` stamps it on the job, and the trainer copies it to the record.

Version 1: measured servo models. Version 2: collision membership per robot, enabling contacts between robots while preserving self-collision suppression.

The sim engine casts the eyes in `stepPolicy` (`policyStep.ts`).

## Performance: simulation

- **LiDAR specification patterns are prepared once.** `sim/lidar.ts` shares six fixed, non-global patterns across range, scan rate, sample rate, point rate and field-of-view reads. Field of view and angular resolution use the same degree-prefix pattern. Matching retains no cursor state, while every call reads current specification rows and returns its own result. [Evidence](../notes/performance-simulation.md#lidar-specification-patterns-are-prepared-once).

- **LiDAR setup rejects unrelated parts before preparation.** `sim/lidar.ts` checks the catalog group before reading specification rows, then requires a usable LiDAR spec before searching body membership. MJCF generation shares this path for live and headless simulation. Valid sensors retain first-body ownership, source order, ray generation and the four-scan limit. [Evidence](../notes/performance-simulation.md#lidar-setup-rejects-unrelated-parts).

- **Link mass centroids accumulate in one pass.** `utils/robotImport/urdfLinks.ts` sums link mass and three weighted coordinates together before the separate inertia pass. Robot Package and headless URDF exports share it. Payload order, per-coordinate addition order, minimum mass and inertia floors stay unchanged. Existing Robot Package, ROS package and body calibration tests retain export coverage. [Parity evidence](../notes/performance-motion.md#mass-centroids-accumulate-in-one-pass).

Measurements and limits: [Simulation performance evidence](../notes/performance-simulation.md).

- **Robot exports index joint identities once per operation.** `utils/robotImport/jointIndex.ts` retains the first joint for each id. URDF writing indexes model and scene joints, joint-map generation indexes model joints, and policy packaging shares one model index across every policy. Missing-joint fallbacks, file contents and joint order stay unchanged. Indices end with each call, so edits rebuild them. Empty policy lists build no index. Desktop and headless package exports share these writers, and Robot Computer installation shares joint-map generation. [Evidence](../notes/performance-simulation.md#robot-exports-index-joint-identities).

- **Simulated sensors reuse world-ray and hit buffers.** `sim/eyes.ts` retains world-space origin and direction arrays per compact sensor, shared by policy depth eyes and LiDAR scans in live and headless simulation. Sensor setup reads direction components directly into the compact list, without slicing a temporary array for each ray. It preserves source pixel indices and skips only all-zero directions. `compactEye.test.ts` checks parity with the previous compactor across empty, camera-sized, LiDAR-sized and oversized grids, nonfinite components, signed zero and independent setup storage. Every cast refreshes the current body pose and reads nine rotation coefficients, without rebuilding arrays or a rotation closure. `sim/scanner.ts` writes hit points during the callback, removing a second hit traversal, one pair array and one coordinate array per hit. Borrowed ray buffers stay inside the cast's synchronous consumers. Published scans remain independent copies. [Evidence](../notes/performance-simulation.md#simulated-sensors-reuse-world-ray-and-hit-buffers).

- **Single-body pose reads transform only their owner.** `sim/mjcfFrames.ts` shares body conversion between full maps and targeted `simDelta` and `worldDelta` reads. Steering, distance probes, end-effector stats, dataset hand paths, recorded mat paths and the agent's operate report no longer build complete maps to read one id. Targeted reads search current membership backwards to preserve last-body ownership, without caching poses or model topology. Each call returns its own matrix. [Evidence](../notes/performance-simulation.md#single-body-pose-reads-transform-only-their-owner).

- **Policy playback retains actuator addresses.** `sim/engine.ts` resolves each policy output's actuator when its controller starts, alongside its observation addresses. Direct policies and policy-driven routes reuse these addresses on every physics substep. Controller replacement, reset and respawn rebuild the bindings. Passive joints still receive no policy writes, and outputs retain policy order even when model joints are reordered or actuator indices differ. [Evidence](../notes/performance-simulation.md#policy-playback-retains-actuator-addresses).

- **Physics latency reuses control snapshots.** `sim/controlDelay.ts` shares one `mj_step` wrapper between live physics settings and Arena. A delay of N steps retains at most N + 1 control arrays, then overwrites them in place without shifting history. Startup holds the first command, and resetting the delay clears its history. The separate per-actuator Laggy fault already reuses its scalar ring. [Evidence](../notes/performance-simulation.md#physics-latency-reuses-control-snapshots).

- **Fixed simulation schedules advance by cursor.** `utils/timelineCursor.ts` copies and stably sorts a schedule once, then visits each due entry once without shifting the remaining array. It retains the next deadline between ticks, reads each sorted entry’s time once during delivery, releases consumed references and empties the array when finished. Event times are fixed for the cursor’s lifetime. Worker scripts, headless commands, pushes and requested frames, Case references and world events, fit checks and recorded reference fixtures share it. Equal-time entries keep their source order and the due boundary keeps its 1 ns tolerance. [Evidence](../notes/performance-simulation.md#fixed-simulation-schedules-advance-by-cursor).

- **Wheel mixing writes directly into its output.** `sim/wheelSpeeds.ts` shares the differential-wheel calculation between manual rover driving and route playback. It fills records without temporary entry arrays. Manual ticks return independent snapshots. Each `RouteRunner` keeps a private record and overwrites its wheel speeds on every tick before writing actuator controls. Records have no prototype so every joint id is an own key. Duplicate ids retain the last wheel's speed, and missing or passive actuators receive no writes. [Evidence](../notes/performance-simulation.md#wheel-mixing-writes-directly-into-its-output).

### Passive world joints

Case world bodies can form passive hinge and slide trees. `mjcfWorld.ts` emits each child in its parent's translated rest frame, with geometry rotations and joint pivots converted independently. Hinge ranges convert degrees to radians, slides convert millimeters to meters, and axis directions rotate to MuJoCo's Z-up frame without length scaling. Joint damping and frictionloss use SI units. Fixture stops use `solreflimit="0.004 1"` so sustained contact does not inherit the default soft stop response. These joints have no actuators, gain, holding torque or entries in `SimModel.joints`. Fixed children and locked joints remain welded to their parent or the world. Rigid world emission retains its existing free, fixed and mocap behavior. A specified surface friction of zero is emitted explicitly.

The Recorder already stores the complete qpos, qvel and body poses, so fixture motion needs no new recording format. Robot actuator counts and robot recording address lists stay unchanged. Cases expose signed fixture travel from relative body poses through their existing facts, contracts and console probes. See [Cases](cases.md#passive-lid-and-drawer-fixtures) for bounds and units.

## Passive robot joint channels

`mjcfPassive.ts` writes passive hinges and sliders without an actuator or estimated motor resistance. `SimModel.joints` and `SimRobot.joints` retain every physical joint. A passive `SimJoint` has actuator index -1, zero effort and passive effort source and dynamics. Its position drive tag is inert without an actuator. Physical resistance uses the declaration's SI damping and frictionloss, defaulting to zero. Powered output and actuator order remain unchanged for legacy robots.

Hold, animation, policy, route, faults and live drive already guard actuator indices. `poseJoints` excludes passive declarations from live commands. ## Closed Sketch linkages

`mjcfLoops.ts` validates each existing coupler/rocker pair against its driver, shared parent, scene-space axes, link dimensions and authored C ports. Frame and port checks allow 0.05 mm for the insertion pipeline's rounded coordinates. A normalized transmission sine below 0.0001 refuses the initial configuration. Missing partners, incompatible declarations and missing catalog actuator variants use the normal simulation error path. New Sketch and agent insertions select the STS3215 C001 variant. Earlier scenes with an unspecified variant must select one before simulation.

Only generated simulation joints become passive hinges. The scene's fixed `loop` declarations and analytic CAD posing stay intact. The passive hinges have no motor, armature, estimated friction or holding torque. Resistance can be declared on their scene joints. The constraint anchor comes from the authored shared pin, converted into the coupler body's rest frame. Models with closures use solver tolerance 1e-12 to keep floating contact replays within the existing native parity bar. Other models retain the default solver tolerance. Root translation, tilted planes, reversed plane handedness and repeated mechanisms use the same emission. Geometry, catalog mass, printed mass, inertia calculation, contact masks and servo fitting keep their existing paths.

`SimJoint.loop` retains the derivation for reset. `loopInitial.ts` clamps the crank and recomputes both passive values, including Arena resets, without accepting independent noisy passive angles. Models without loops return their original pose directly. Recordings retain every physical coordinate and only actual control channels. Policy observation addresses remain joint-based and control writes remain actuator-based. Existing policies containing passive entries keep their established ignored-output behavior. New jobs and environments name only powered actions.

Equality XML participates in robot fingerprints and the existing compiled physics hash. The closure solver tolerance participates in every robot's fingerprint because it applies to the whole model. Adding or removing the last closure therefore invalidates training evidence for other robots in that scene too. Models without closures keep their previous fingerprints. WASM simulation and native training consume the same MJCF. Native PPO keeps its floating-base requirement. Fixed mechanisms can play target animations and use the existing fixed-base solver and demonstration paths. No Arena threshold or ready-skill installation path changes.
