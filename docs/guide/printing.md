## 8f. Printing: printers, plates, slicing and sending

Stage 5 of the loop (§1). The plan, findings and what's still unverified: [docs/Print plan.md](../../docs/Print%20plan.md). Nothing about a printer is hard-coded: the P1S is one catalog entry.

- **Printer catalog** (`src/data/printerCatalog.ts`, generated; types and helpers in `data/printers.ts`): 92 printers from the machine profiles Bambu Studio ships (`Resources/profiles/<Maker>/machine`, inheritance resolved): bed polygon, height, keep-out zones, nozzles, default plate type and, for the 0.4 mm nozzle, the machine, default process, process presets by layer height and a filament preset per material. Regenerate with `node tools/printers/import.mjs [--app /path/BambuStudio.app]` when Bambu Studio updates; never edit the file by hand. Custom printers take a build volume.
- **My printers** (`library/printers.json`, `electron/print/printers.mjs`): app-wide, one default. On first launch the list is seeded from the printer selected in Bambu Studio (`BambuStudio.conf`), sending through Bambu Studio. Access codes and API keys are encrypted with `safeStorage` in `library/agent-config/printer-keys.json` (`AgentKeys` with `file`), never in the scene. A scene's `project.printer` resolves with `resolvePrinter` (a My printers id, a catalog id, or the default printer).
- **Plates** (`src/print/`): the analysis worker returns a printer-independent `PrintShape` per shape (poses: 6 axes plus up to 6 flat faces the part rests on, each with its rotation, footprint, overhang, support and contact). `choosePose` picks one for the bed (`bed.ts`: keep-outs, 90° turn, diagonal fallback); `pack.ts` packs per material with MaxRects around the keep-outs; `buildPrintPlan` returns plates with a matrix per item (part frame → 3MF bed frame, Z up) and a hash per plate. User choices live on the part (`ScenePart.print`: `down` face, `plate`, `at`, `turned`, `copies`, `skip`), so they undo like any edit.
- **3MF** (`print/threeMf.ts`, run in the analysis worker): one file per material, plates laid out on Bambu's plate grid (plate i at column × width × 1.2, row × −depth × 1.2, columns = ⌈√n⌉ rounded as Bambu does), plain 3MF core, names kept. Export ▸ 3MF Plates downloads them.
- **Slicing** (`electron/print/`: `slicers.mjs` finds Bambu Studio, OrcaSlicer, PrusaSlicer in `/Applications` on macOS and in Program Files or `%LOCALAPPDATA%\Programs` on Windows (`bambu-studio.exe`, `orca-slicer.exe`, `prusa-slicer-console.exe`, profiles in `resources\profiles`); `openFile` in `jobs.mjs` opens files with `open -a` or the slicer's exe; `slice.mjs`, `jobs.mjs`): the CLI runs headless per material with **flattened** profiles (the CLI doesn't follow `inherits` for loaded files and falls back to a 200 × 200 × 100 plate), `--arrange 0`, infill and the printer's default plate type (`curr_bed_type`) written into the process. Results come from `result.json` and the sliced 3MF: time, grams, supports, warnings and the plate thumbnail per plate, cached per material by plate hash in `library/prints/<scene>/`. The CLI can't take per-object filaments with 3MF input and crashes on edited Bambu projects, so materials are separate jobs. `electron/print/slice.test.mjs` slices for real when Bambu Studio is installed.
- **Sending** (`electron/print/index.mjs`, connectors in `electron/print/connectors/`): Bambu Studio (default for Bambu printers: opens the sliced plates, where Print uses the user's own sign-in), Bambu Connect (URL scheme), Bambu LAN (Developer Mode: FTPS upload + MQTT `project_file`, live status, AMS trays), Moonraker, PrusaLink, OctoPrint (plain G-code pulled from the sliced 3MF). Find on Network reads Bambu SSDP and mDNS (`dns-sd` on macOS; on Windows a small `node:dgram` client, `connectors/mdns.mjs`, that sends one-shot queries from an ephemeral port so it never binds 5353). **Only the user starts a print**: Print Plate N opens a Start Print sheet (plate, material and AMS slot, Clear the bed); the agent's `slice_plates` never sends.
- **Print mode** (⌘P, File ▸ Print, Build ▸ Lay Out Plates, Lay Out Plates in the Build tab's Printing section, ⌘K): the canvas shows one plate (`three/plates/plateView.ts`, its own WebGL canvas while open; the scene viewport pauses) with the bed, its keep-outs and the parts in print orientation (shared geometry). Drag to move (saved as `at`), F Lay on Face, R Turn 90°, ←/→ plates, Esc closes. The Print panel replaces the inspector and holds everything about printing; the Build tab shows only the plate count and total time (§8b). The panel: Print Fit Test beside Done in its header (below), Printer (with Skip N printed parts once something is printed), the selected part (Lay on Face, Turn 90°, Plate, Copies, Don't print), the plate (thumbnail when sliced, its state, warnings, Send / Print Plate N, Open in Bambu Studio, Mark Printed / Failed) and **Printed parts** (`PrintedSection`, collapsed with its count: per-part size, time, plate and issues, parts with issues first, copies as “2 ×” before the name; a click selects the part on its plate), with Done (Esc) in its header. Slicing every plate at once is ⌘K ▸ Slice Plates; Send slices a plate that isn't. Either way a progress toast with Stop follows the slice wherever you are and turns into the result or the error; the plate section shows the progress with Stop too, and keeps the error. The bottom bar is the only plate list (each plate's number and material) and holds Auto Arrange; it has no close button, since Done, Esc and ⌘P already close.
- **Fit test** (`print/fitTest.ts`, `three/analysis/fitCoupons.ts`, `workspace/useFitTest.ts`): Print Fit Test (in the Print panel's header and ⌘K, offered while the scene has a printed part and a fit) plates small coupons cut from the design, so a tight pocket shows up in a short print, not after the full plate. Fits are grouped by kind and spec (`fitKey`): a heat insert by its size, length and outer diameter, a servo or motor pocket by catalog component, a bearing seat by bearing type and size, a screw clearance by size. For the first instance of each group with a host, the analysis worker (task `fitCoupons`, rest pose) finds the printed part that holds it (its surface within 0.5 mm of the bought part's box, or the box's centre inside it; the largest box overlap wins) and intersects that host with the bought part's own box plus a 4 mm wall (`FIT_WALL_MM`, three-bvh-csg). Each coupon keeps its host's chosen print pose (`down` from the design's plan) and goes through the same `reportFromShapes` → `buildPrintPlan` path as any part, so the plate packs, slices and sends as usual; its 3MF is written from the coupons' own triangles (`useFitTest`'s `threeMf`), and its slices go to their own job (`<scene>-fit-test`), so the design's cached slices stay. The plate is temporary: the coupons are `sculpt_mesh` parts that exist only while it's open, never in the scene; you can't move them, Auto Arrange and Mark Printed are hidden, and sending one records no print. The panel's header reads Print Fit Test, and Done or Esc returns to the design's plates.
- **Prints tracker** (`print/tracker.ts`, `project.prints`): a record per plate sent (parts with their shape keys, printer, state from live status or marked by hand). A part counts as printed while its shape is unchanged, and Skip N printed parts (on by default) leaves those parts off the plates, so editing one bracket after printing gives a plate with just that bracket.
