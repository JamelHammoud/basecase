# Security

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 0h. Security (mandatory)

Published-skill discovery shares platform-neutral validation and download contracts in `src/hub/skillDownloads.mjs`, `skillSearch.mjs` and `remoteOutcomes.mjs`. Desktop uses the existing Hub client, and web builds use an anonymous worker on the fixed Hugging Face origin. Account and repo names pass `checkedName` before constructing a URL. Search and model metadata are capped at 2 MB. All six required install files must be present and each declare a positive size within 32 MB before downloads begin. Downloads of `robot.json` and `skill.json` are capped at 32 MB each. Downloads use the commit SHA returned by the Hub, and the revision cache is bounded to 128 entries and 64 MB. Each result list is capped at 64 MB of candidate files. The embedded policy and evidence must match their file metadata at that commit, using Git object ids or LFS SHA-256. Git blob ids use the SHA-1 digest required by the Git protocol. They detect mismatched files and do not authenticate a publisher or prove a policy. Schema, policy dimensions, action joints and evidence bindings are checked before ranking in a worker. Install still downloads and validates the full package and runs Arena on the target. Exploit tests in `electron/hub/skillSearch.test.mjs` refuse escaped repo names before file requests and drop oversized `robot.json`, tampered policies, incomplete packages and offline results.

Browser skill downloads use the fixed `/api/resolve-cache/models/<repo>/<commit>/<file>` address for commit-pinned JSON. This avoids the normal resolve address's opaque browser redirect. A returned `X-Repo-Commit` must match the selected commit. All requests omit credentials. API requests refuse redirects. Downloads inspect each visible redirect before following it, accept HTTPS only on Hugging Face's Hub and named CDN hosts, and stop after three hops. Opaque redirects are refused, so externally stored LFS JSON that requires one cannot install in the browser. Basecase publishes the six install JSON files as regular Git files. Desktop off-origin hops use `publicFetch` in manual mode so every later redirect is checked again.

Browser installation outcomes retain the existing schema in IndexedDB. A worker hashes and bounds each record to 256 KB, caps local storage and scans at 1,000 entries, returns at most 100 local and public results for ranking, and deduplicates by the record's SHA-256. A single IndexedDB read-write transaction puts, counts and trims outcome keys, so concurrent tabs share the same cap. Public reports are downloaded at the metadata's commit and checked against Git blob or LFS hashes. Reported outcomes affect ranking, but do not authenticate execution. Local Arena still decides whether the target skill is retained. `src/hub/webHub.test.ts` covers anonymous discovery, pinned selection, hostile refs, redirect refusal and commit-header mismatch. `src/utils/platform/web/webHubJob.test.ts` covers reload, deduplication and oversized or corrupted local outcomes.

Scene and gallery imports validate sheet settings and affine transforms before rendering, including fields inside boolean operands and custom model nodes (`src/sheet/validation.ts`). Unsupported materials, nonpositive or nonfinite thicknesses, nonfinite matrix entries, perspective, singular and reflected transforms are refused. Boundary tests in `src/sheet/importValidation.test.ts` cover both `.basecase` files and gallery bundles.

World imports (`src/cases/worldImport.ts`) read only the dropped file set and perform no network fetches. The set is capped at 256 files and 64 MB, the mesh at 200,000 triangles and 600,000 vertices, and the splat at 1,000,000 points. Counts, indices, coordinates and transforms are validated before allocation or rendering. glTF buffers and images must name files inside the drop. Absolute URLs, schemes, encoded traversal, backslashes and parent segments are refused. Malformed or non-finite data refuses the whole import. Scene world assets are parsed again on restore and must match their SHA-256 key before any are registered. Reader exploit tests cover oversized drops, NaN vertices and a glTF buffer URI outside the dropped files.

Restored world assets validate encoded payloads before registration (`src/cases/worldAssetPayloads.ts`). Splat bytes pass through the import reader again, and their actual format and point count must match the saved metadata. Texture headers must match the saved MIME type, remain within 8192 pixels per side, and total at most 16 million pixels across the asset's materials. A valid content hash does not skip these checks. `src/cases/worldAssetPayloads.test.ts` covers malformed and oversized splats, nonfinite PLY properties, incorrect metadata, oversized image headers and aggregate pixels under fresh matching hashes, and verifies that one rejected payload registers none of the table's assets.

The agent reads untrusted pages and files and drives an app that can spawn processes, so treat every input from the renderer, the HTTP bridge, the agent and downloaded assets as hostile. The full checklist, attack surface and accepted risks are in the `security-audit` skill; these rules hold for every change:

- **HTTP bridge:** every `/api/*` middleware is wrapped in `guardBridge` (`electron/bridgeGuard.mjs`: loopback `Host`, same-origin `Origin` and `Sec-Fetch-Site`). Vite plugin middlewares run before Vite's own host check and CORS, so nothing else protects them. A website could otherwise POST `/api/bridge/acp-connect` and run a command.
- **IPC** registers through `trustedIpc` (`electron/appOrigin.mjs`, main frame of the app origin only). Compare origins with `isAppUrl`, never `startsWith`; open only `isExternalWebUrl` links.
- **Robot computers** (§8k): the daemon's explicit `--listen` control port and the app's network link accept only private, link-local or loopback addresses. The app checks every DNS answer, then connects to the checked literal address. Discovery is untrusted data, never proof of identity. Pairing uses a one-use six-digit code and a password-authenticated exchange implemented by the daemon at both ends. Saved keys remain in the main process and robot's private files. Discovery advertises a stable SHA256 key fingerprint, and the signed greeting must match that fingerprint and the saved key before an endpoint alias is kept. Hostname, IP and DHCP changes reuse the same robot credential. Each later connection uses a fresh random challenge, and command and telemetry signatures bind the challenge, direction, sequence and exact JSON body. Malformed, unsigned, reordered and oversized lines close the connection before dispatch. The app also closes after one second without an authenticated reply, including a connection still accepting outgoing heartbeats. The robot's watchdog owns stopping when heartbeats cease. Network tests cover unpaired commands, replayed enrollment and commands, public addresses, hostile discovery records and a virtual 1 GB input without allocating it.
- **Training computer settings** (`electron/remoteTraining/routes.mjs`): the four `remote-training:` calls use trusted IPC and the guarded HTTP bridge. The preload allows only status, configure, clear and selection. Configure delegates validation and pinned-host verification to `RemoteTraining`. Status returns host, user, public host key, attempt and concurrency settings and whether an identity is saved. It never returns the identity path or private key bytes. The renderer’s status adapter also drops unexpected fields. Selection checks the completed child identity, seeds, work and exact input hashes against the parent journal, and refuses changed evidence on replay. The configuration is sealed in `library/training-computer.json`, outside scene and skill exports. Browser builds hide Training and refuse configuration and selection. Deselecting restores local execution while keeping remote jobs recoverable.
- **Installing a robot computer** (`electron/robot/robotInstall*.mjs`): validate `user@host`, the SSH key file and the scene's joint map before spawning OpenSSH. Resolve every host answer to a private address and pin that address with `HostName`, while retaining the original name for host-key checks. SSH disables configuration files, proxies and local commands, uses batch mode and passes arguments without a local shell. Remote script data is base64 encoded. The installer seeds the first code through a private file that the daemon removes after pairing state is loaded, keeping the code value out of service arguments and environment. The staged daemon identifies the interface owning the checked SSH address, and the service resolves that same interface to a private address each time it starts. Missing or public addresses never select another interface. Downloads use `publicFetch`, a 128 MB cap, the release's SHA-256 checksum and an ELF architecture check. The uploaded binary must refuse a real motor port before replacing the installed service. Tests execute the generated script through an SSH shim and reject public DNS answers and host strings with shell characters.
- **Ids that become paths** go through `checkedFileId` / `isSafeFileId` (or `safeFileId`) in `electron/backend/constants.mjs`. `library/agent.json` holds the command the app spawns.
  - The tries store (`electron/library/tryStore.mjs`, §8h) checks every id before it touches a path: a try's id and its scene id on save, the id on reading a recording, filmstrip or session log and on appending to a session or keeping a video, and every id in a delete before any folder goes. A manifest is at most 256 KB, a recording 1 GB, a session log 256 MB, an operator video 2 GB and a filmstrip 2 MB. Only the main process's Operate recorder appends to a session log (§8k); the page's `robot:record` samples are rebuilt from checked fields (`checkedContext`, `checkedSample`), and a video is kept only beside a try that already has its manifest. The main process stores a recording's bytes and never parses them; the page decodes them with bounds checks (`decodeRecording`). Exploit tests in `electron/library/tryStore.test.mjs` (`..`, `../auth`, a backslash, a slash, `CON`, an empty or 200-character id, a number, a delete list with one bad id). `tries:manifests` checks every id and reads at most 500 a call. `tries:update` checks the manifest's ids like a save, and writes only into a folder that still holds a manifest, so it never brings back a deleted try. Camera video reads and writes use `/api/tries/video/<try>/<camera>` through `guardBridge` in Vite and the app protocol in desktop builds, with byte ranges and a 2 GB cap. The saved manifest must name exactly one matching camera. Imported camera names are hashed into generated filenames, and the only legacy filename is `operator.mp4` for an Operate operator camera. The upload worker sends raw binary PUTs with an expected SHA-256 hash and declared byte length. A streamed upload stops past its declared length or 2 GB, and the hash and exact length must match before the temporary file becomes a content-addressed asset in `.videos/`. A small POST binds an existing asset to a declared camera through a generated reference file after streaming its bytes through SHA-256 again. A verified PUT replaces changed cache bytes. Uploads retain the original try directory identity and camera metadata, and refuse to bind after either changes while the stream is running. Reference hashes are 64 lowercase hex digits, and asset and reference files must be regular files. Deletes serialize asset cleanup with uploads and preserve assets another try references. `electron/library/tryVideoUpload.test.mjs` covers streamed caps, hash mismatches, traversal, wrong cameras and shared-clip deletion. Declared video paths never become filesystem paths. Symbolic-link directories and files are refused. `electron/library/tryVideo.test.mjs` covers traversal, wrong cameras, missing manifests, symbolic links and ranges. The web try store keeps each content hash once as a Blob in IndexedDB, with separate checked try and camera references. Writes and deletion hold the same Web Lock across workers, and cleanup removes a Blob only after its last camera reference is removed. A worker reads them directly through `readWebTryVideo`, which checks the saved manifest and the same 2 GB cap before returning a Blob. Deleting a try deletes its clips, with an exact try-id prefix. `src/cases/tryStore/webTries.test.ts` covers reopening, deletion, wrong cameras and removed camera metadata. The search index (`library/.try-index.bin`) is at most 512 MB, written atomically, and parsed by the page, which refuses it whole when its format name or version is wrong (`searchIndex.ts`).
  - The dataset store (`electron/library/datasetStore.mjs`, §8h) keeps each dataset as `library/datasets/<id>.json`. It checks the dataset's id before it writes, and every id in a delete before any file goes. It lists only `<id>.json` files whose id is safe, skipping any over 16 MB, unreadable, or naming another id. A dataset is at most 16 MB on save, room for 100,000 members with a few versions. Selected snapshots are checked against their canonical SHA-256 before consumption. Publishing unpacks its saved archive in the dataset worker with safe paths, 20,000 entries and a 1 GB expanded cap checked before inflation. Stored ZIP entries must report equal compressed and expanded sizes so a false expanded size cannot hide copied bytes. The main process checks version-history immutability as well as the dataset id and size, while the page validates the full dataset. The page reads every listed file fail-closed (`readDataset`). Exploit tests in `electron/library/datasetStore.test.mjs` (the same ids as the tries store's, a delete list with one bad id, a file over 16 MB). Content blobs live in `library/datasets/content/<sha256>` and use lowercase 64-hex SHA-256 keys checked before any path access. Each blob is at most 1 GB, with HTTP base64 length and canonical encoding checked before decoding. Exclusive writes never replace an existing blob, and both save and read verify its bytes against its hash. The browser stores the same verified bytes in `basecase-dataset-content`. Deleting a dataset retains its blobs so a version in another dataset remains readable. Content has no garbage collection until deletion can account for all version references. Desktop, browser and page saves merge saved versions by their number before writing. A stale edit cannot remove history or replace a version’s hash, labels, member list or timestamp. An archive hash can be assigned once and then stays with that version. The page serializes writes for each dataset id. Browser saves read, merge and write inside one IndexedDB readwrite transaction, so separate tabs share the same ordering. A save resolves only after that transaction commits, and a merge or storage failure aborts it. Both backends return the committed dataset, and the page publishes that record so versions merged from another window remain visible after a stale save. `electron/library/datasetVersions.test.mjs` and `src/datasets/datasetStore/datasetVersions.test.ts` cover stale updates, concurrent saves and metadata replacement. `electron/library/datasetContent.test.mjs` and `src/datasets/datasetStore/desktopContent.test.ts` cover malformed keys, oversized files, changed bytes and hostile transport replies.
  - Image frame sets (`electron/library/frameSetStore.mjs`, §8h) use `library/frame-sets/<id>/manifest.json` and separate `<frame>.jpg` and `<frame>.depth` files. Every set, scene, Case, staging and frame id is checked before a path is used. A manifest is at most 16 MB and 10,000 distinct frames, each JPEG or depth blob at most 64 MB, each dimension at most 8,192 and each image at most 16,777,216 pixels. A manifest is committed only after every JPEG exists and every depth file has exactly four bytes per pixel. Finalizing a staged run checks both ids before copying its blobs and writing the final manifest. Listings return metadata and counts, previews read JPEGs alone, and full frames are read on demand. Frozen image packages are unpacked and validated in the image dataset worker, with an expanded size cap of 192 MB and three entries. Stored ZIP entries must declare matching stored and expanded sizes before any bytes are copied. The page checks frame dimensions and annotation-list bounds before requesting image blobs and rejects manifests carrying embedded image data. Optional frame provenance accepts only `import` and participates in the content hash. It validates frames and their labels in `frameStore.worker.ts`, exports in `imageDataset.worker.ts`, and refuses image members whose content no longer matches the dataset's SHA-256. `electron/library/frameSetStore.test.mjs` covers hostile ids, staging paths, size caps, corrupt manifests and missing or mismatched depth. `src/vision/imageDataset.test.ts` covers missing and changed content.
- **Latest-run reading:** the read-only `robot:read-run` channel shares the trusted robot IPC registration. It accepts a checked unit name and reads only that unit's recorder-owned session id, never a page-supplied file id. `sessionSink.read` checks its recording id before opening the path and reads at most 1 MiB from the end, excluding incomplete boundary lines. The reader validates timestamps and vector lengths and returns only the latest 20 seconds of positions, at most 1,024 positions and 1,024 accepted goals including the preceding replay goal. `electron/robot/recordedRun.test.mjs` covers traversal, malformed vectors, unit separation, unaccepted goals and a sparse 512 MiB log. The HTTP reader uses the existing `guardBridge` middleware and returns null because that backend owns no robot link.

- **Outbound fetches the agent controls** use `publicFetch` and `readCapped` (`electron/publicFetch.mjs`): public addresses only, every followed redirect re-checked, bodies capped. Callers using `redirect: 'manual'` receive the redirect without following it, and `redirect: 'error'` refuses it, so a caller can enforce a narrower host policy at each hop. The renderer fetches agent URLs over https only (robot import: `fetchBytes` in `utils/robotImport/sources.ts`). A repo link is read only from its own host: GitHub repos from `api.github.com` and `raw.githubusercontent.com`, Hugging Face repos from `huggingface.co` (`hub.ts` builds every URL from the parsed owner, repo and revision, encodes each path segment, drops listed paths that climb out of the repo, follows the listing's next page only on the same API path, and reads only listed files plus the one file a file link names; exploit tests in `hub.test.ts`); zips it unpacks drop entries that climb out of the archive (`archive.ts`, exploit test in `archive.test.ts`). A file link on `raw.githubusercontent.com` reads its meshes and includes, absolute links among them, only inside its own owner, repo and ref (`urlResolver`; a `refs/heads/<name>` or `refs/tags/<name>` link keeps to that ref, and a short branch name with a slash in it is scoped to its first segment, since the URL can't say where it ends; exploit tests in `sources.test.ts`). Xacro (`xacro.ts`) never runs code: expressions go through a small arithmetic parser (`xacroExpr.ts`) that knows only its operators and a fixed list of math functions, looks names up in a `Map`, and refuses any other call or attribute. `xacro:include` takes only paths inside the import (an `http:`, `file:` or drive-letter path is refused before reading; the tree resolver reads only listed files), includes nest at most 8 deep and 200 in all, macros nest at most 40 deep, expansion stops at 200,000 nodes, at a million characters in any one value, at 16 million characters of strings computed along the way (every joined value and string `+`, kept or not), and at 16 million characters in the whole expanded document (tags, attribute names and values, and text, counted as they're built), a property that refers to itself fails, and document type declarations (entity expansion) are refused. Exploit tests in `xacro.test.ts` and `xacroExpr.test.ts`.
- **Publishing to Hugging Face** (`electron/hub/`, §8h): the token lives only in the main process, sealed with `safeStorage` (`hub-keys.json`, memory only without encryption); the page gets a signed-in flag and the account name. Every Hub URL is built from the fixed origin (`https://huggingface.co`, or `BASECASE_HUB_URL` for tests, which must be https or loopback http so it can't send the token in plain text off this computer) and checked to stay on it; repo names and the account name must match the Hub's name rule (letters, digits, `.`, `_`, `-`, no `--` or `..`, at most 96), file paths are plain segments, and a version tag is `dataset-v` and 1 to 6 digits, all checked before any request. Requests to the Hub refuse redirects. LFS upload addresses on another origin must be https and go through `publicFetch`, and never get the token; only verify calls on the Hub itself carry it. Error text from the Hub has the token cut out. `electron/hub/hub.test.mjs` holds the exploit tests. **Install Skill** (§8i) downloads from the Hub's resolve addresses only: `skillFiles` checks the account and repo with the same name rule and the branch as one plain segment before any request, reads a fixed list of six files (`SKILL_DOWNLOADS`), sends the token only to the Hub's own origin and only when signed in, follows at most 3 redirects, sends one off the Hub only over https through `publicFetch`, and stops reading a file past 32 MB (`readCapped`). The page parses the files fail-closed, checks each against `skill.json`'s hashes and loads the policy as data through the policy runner, never as code. Exploit tests: `electron/hub/skillRepo.test.mjs` (crafted accounts, repos and branches that try to leave the repo, an oversized file, an http redirect) and `src/skills/hubSkill.test.ts` (a tampered `policy.json`, a policy the runner can't load). **Dataset downloads** (`datasetFiles`, `electron/hub/datasetRepo.mjs`) check the account, repo and revision the same way before any request, resolve the revision to a 40-hex commit sha and read the listing and every file at that sha, follow the listing's next page only on the same API path, and download only plain listed paths. LeRobot metadata and parquet files, canonical image manifests, COCO annotation JSON, YOLO data YAML and text labels, VOC annotation XML and split lists, JPEG/PNG images, float32 depth files and image parquet files are allowed. A supported manifest, VOC annotation or parquet file must be listed before any payload is fetched. When a YOLO YAML manifest is listed, plain text files are included too, so its split image lists remain available to the worker. Videos, code and model weights are excluded. Listed file sizes, total bytes and file count are checked before downloading, and response bytes are capped again while reading: 256 MB a file, 1 GB and 2,000 files in all, with the same redirect and token rules as Install Skill. Exploit tests in `electron/hub/datasetRepo.test.mjs` (crafted accounts, repos and revisions, listed paths that climb out, a revision reply that isn't a sha, a next page off the listing, files and datasets over the caps).
- **Vision models** (`src/vision/`, `electron/hub/modelRepo.mjs`): manifests pin one ONNX file to a 40-hex Hub commit, an exact byte count and SHA256. Owner and repo names use the Hub's checked name rule, every file path segment is plain, and the whole file is at most 256 MB. The guarded Hub client downloads with the same redirect, token and public-address rules as Install Skill. Bytes are size and hash checked before an atomic write to `library/models/<hash>.onnx`, and cached files are rechecked before reuse. The renderer receives only a same-origin cache URL. The inference worker reads the binary through `/api/vision-model/<hash>` and checks it again before ONNX Runtime sees it. That GET accepts only a 64-hex hash and a regular cached file, refuses symlinks and oversized files, rehashes bytes before serving them, carries a same-origin resource policy, and uses the bridge guard in development. Web builds use anonymous fixed-origin Hub resolve URLs, capped streaming bodies and hash checked IndexedDB entries. No model is evaluated as JavaScript. Traversal, tampered bytes, mutable revisions, caps, cache corruption and binary route probes live in `modelRepo.test.mjs`, `modelRoute.test.mjs` and `src/vision/manifest.test.ts`.
- **Local vision training** (`electron/visionTraining/`, `electron/visionTrainer/`): the six `vision-training:` calls use `registerCalls` for trusted IPC and the guarded HTTP bridge. Callers supply checked job and dataset ids and SHA-256 content references, never filesystem paths. Jobs live in `library/vision-training/jobs/<id>/`, with images staged from verified frozen dataset-content ZIP references into fixed `images/<hash>.jpg` paths by a Node worker. JPEG bytes never cross the new training calls. Staging accepts stored ZIPs with one JPEG, one depth file and one manifest, capped at 192 MB expanded, and refuses duplicate paths and false stored sizes. Jobs accept at most 10,000 images, 64 MB per JPEG and 600 MB of image bytes altogether. Job metadata is capped at 16 MB, saved run records at 8 MB and artifacts at 256 MB. A run listing accepts at most 10,000 records and 64 MB altogether. HTTP payloads stop at 24 MB before JSON parsing. Reads require regular directories and files, reject symlinks and recheck opened file identity and size. Job inputs and image bindings are immutable in `spec.json`, so resume must name the same frozen inputs. The backend writes the checked resume flag into `job.json` before spawning and clears the old stop file. Jobs, saved runs and the isolated environment use separate directories. The trainer runs pinned dependencies in a separate uv environment, uses architecture definitions without pretrained weight downloads, accepts only bounded task settings and loads local checkpoints with `weights_only=True`. Stop and app shutdown write a fixed stop file instead of sending OS signals. A fresh job starts without resume, and a resumed job needs its matching specification and a regular checkpoint under 256 MB. Model, baseline, predictions and checkpoint artifacts enter the verified dataset-content store. Saved comparison records are immutable under `runs/<datasetId>/<runId>.json`. Browser builds refuse the desktop training routes. Exploit coverage in `electron/visionTraining/store.test.mjs` checks hostile ids, content mismatches, symlinked paths, size limits and resumed-input changes.
- **Prompt segmentation** (`src/vision/segmentationModels.ts`) pins five SAM 2.1 small ONNX graphs from [Diffusion Studio's export](https://huggingface.co/diffusionstudio/sam2.1-small-video-onnx-fp16/tree/927ecec6e6ae2727d0af7720eefdb07f2efe4689). Each graph uses the existing guarded desktop model cache or the anonymous web model cache, with its own exact size and SHA256 checked again before session creation. The 7 × 64 learned memory-position table is committed as data in `segmentationConstants.json`, copied from that same revision's `constants.json`. Image pixels and tracking memories stay in the segmentation worker. Clicks are limited to 64 finite points inside the source image, with at least one foreground point. Tracking accepts one seeded frame and at most 30 following frames at the same image size. `segmentationEngine.test.ts` refuses tampered model bytes before session creation, `segmentationMath.test.ts` refuses malformed clicks and masks, and `segmentationRuntime.test.ts` checks desktop cache refusal and worker shutdown.
- **Shared robot links** (`app.basecase.so/r/<account>/<repo>`, §8h): the web page reads the account and repo from the path with the same Hub name rule (`sharedRobotPath` in `src/gallery/galleryLinks.ts`) and fetches only `https://huggingface.co/datasets/<account>/<repo>/resolve/main/basecase-robot.json`, built by `sharedBundleUrl` and checked to stay on that origin, without credentials. The bundle is read fail-closed (`fetchBundle.ts`, `readGalleryBundleBytes`): a `Content-Length` over 8 MB is refused, the body stops downloading the moment it passes 8 MB, and `parseGalleryBundle` caps parts and joints, checks every inlined mesh's indices against its vertices, and accepts a policy or skill only when it validates (a skill's record must hash to the skill it carries). A shared Case's code panels are the one part that runs: someone else's code, served on our origin. They run only as code panels do everywhere (above): the opaque-origin sandbox and the CSP, so a frame can't reach the page's IndexedDB (Open Scene's store), its cookies or the Hub. The page itself holds no Hub sign-in; the token lives only in the desktop app's main process. Exploit tests: `src/gallery/sharedRobot.test.ts` (crafted accounts and repos that try to leave the Hub, a bundle and a download over the cap, a code panel that takes a bundle over it), and `e2e/gallery.e2e.test.ts`, where a shared code panel on the web build tries to list the page's IndexedDB, read `document.cookie` (with a cookie set on the page) and post to `huggingface.co`, and each fails with nothing reaching the Hub.
- **Map tiles** (`electron/earth/`, Place on Map, §12): the Google Map Tiles key lives only in the main process, sealed with `safeStorage` (`earth-keys.json`, memory only without encryption); the page learns only whether one is saved. The page asks for a tile by path alone (`earth:tile`), and `tileUrl` rebuilds every request on the fixed origin (`https://tile.googleapis.com`, or `BASECASE_EARTH_TILES_URL` for tests, which must be https or loopback http): a path that isn't a plain `/v1/3dtiles/…` path (an absolute or protocol-relative URL, a backslash, `..` or its encoding, another API) is refused before any request, every query parameter but a well-formed `session` is dropped, and the key is added there. Requests refuse redirects, so the key never follows one off the host; replies are capped at 32 MB, and a refusal reads as a fixed sentence by status, never Google's text. The page checks the same host and prefix before asking (`tilePathOf`), and the tiles it gets are parsed as glTF only. Exploit tests in `electron/earth/earth.test.mjs` (hostile paths, a redirect to another server that must see nothing, the key never on disk or in a reply) and `src/earth/tileFetch.test.ts`.
- **Agent CLI downloads** (§0i) fetch only `https://registry.npmjs.org/` tarballs named in the build's manifest, refuse redirects, and install only when the sha512 matches the lockfile's `integrity`.
- **Print service quotes** (`electron/print/services/`, §8f): the Slant 3D API key lives only in the main process, sealed with `safeStorage` (`print-service-keys.json`, memory only without encryption); the page learns only whether one is saved. Every API request is built on the fixed origin (`https://slant3dapi.com`, or `BASECASE_PRINT_SERVICE_URL` for tests, https or loopback http only) and refused unless it stays under `/v2/api/`, with redirects refused, so the key, sent as a Bearer token, goes nowhere else. Part names never reach a URL: the upload's file name is the name with everything but letters, digits, spaces, `_` and `-` replaced, sent in the JSON body. File, platform and filament ids from the service must be UUIDs before they go in a path or a body. The STL upload address the service returns must be https on another host and goes through `publicFetch` without the key (or stays on the API origin itself). Replies are capped at 1 MB and parsed fail-closed: one that isn't JSON, a total that's negative, not finite or not a number, or a quote for a different quantity is refused, never shown. A refused part's text is the service's message cut to 200 characters with control characters removed. `electron/print/services/slant3d.test.mjs` holds the exploit tests.
- **Roboflow datasets** (`electron/roboflow/`, §8h): the API key stays in the main process, sealed with `safeStorage` in `library/agent-config/roboflow-keys.json`, or memory only without encryption. Account replies expose only a saved flag. Project links accept only HTTPS links on `app.roboflow.com` and `universe.roboflow.com` with plain workspace/project slugs and a positive version of at most six digits. API requests rebuild paths on `https://api.roboflow.com`, refuse redirects and cap JSON at 1 MB. Archive links must start on that API origin or match `https://app.roboflow.com/ds/<token>`, and carry no saved API key. Up to three archive redirects are followed manually, with every address checked again. Redirects may also reach HTTPS ZIP files under `storage.googleapis.com/roboflow-platform-regional-exports/`, the storage used by Roboflow exports. ### Installation feedback

Installation reports use the guarded Hub client and its fixed origin. Each report is capped at 256 KiB, including its normalized JSON representation. A malformed or expanding remote record is dropped without discarding other reports. Remote discovery checks at most 100 repos in batches of four, with 2 MiB metadata caps and commit-pinned downloads verified against Git or LFS digests. Local reads scan at most 1,000 hash-sorted filenames through asynchronous iteration, and discovery stops local reads once its response holds 100 unique records. Uploads consume local reports one at a time in the background during discovery. Publication metadata replaces its file atomically so concurrent discovery never reads a truncated update. Feedback is untrusted reported evidence, never a local verdict. The renderer validates exact source repo, commit, skill and schema hashes, target schema and environment bindings, Arena version, counts and recomputed pass result before ranking. Reported joint depths must fit within the schema's joint count before joint maps are allocated. Reports for changed revisions, stale Arena versions or mismatched physics and contracts have no effect. Cancellation and infrastructure failure cannot lower a source's score. Publication writes through the installer's authenticated namespace, so installing a public skill grants no access to its author's repository. Local persistence precedes publication so an unavailable Hub does not discard an outcome.

### League adjudication

League receipts and frozen evidence use the existing Hub dataset infrastructure. Browser boards accept frozen data only from the shipped League directory or a commit-pinned `JamelHammoud/basecase-leagues` dataset. An entrant’s repo and a hash beside its claimed result confer no authority. The board verifies the manifest, closure, bundle, seed and result hashes, then recomputes summaries and ordering.

The dispatched `League adjudication` workflow runs only from `main` and checks out the dispatch commit for preparation and publication. Replay checks out the manifest’s creation commit, including its locked dependencies and catalog, and frozen provenance must match it. Its `create` operation validates a bounded manifest against the installed runner and engine, requires a future deadline and starts with no entries. The trusted publisher refuses to replace an unfinished League or reuse its identity. Its `admit` operation reads an immutable submission, checks its manifest and bundle, and stamps the receipt with CI time before the deadline. Git timestamps and the entrant’s claimed entry time are not admission evidence. A separate publisher writes that receipt to the trusted League repo. Closing takes the current trusted receipt list, creates random entropy after the deadline and publishes the closure before replay. Every later dispatch reuses that closure and its seeds, including after interruption. A moving branch cannot alter an entry’s pinned robot revision or bytes.

Replay has no publishing token. Catalog geometry must load before any replay measurements, and missing models refuse the replay. Each entry runs in a child process with a 512 MB JavaScript heap limit and a 180-second execution limit, with a small environment, no network fetches and the repository’s installed runner. It never installs an entry’s dependencies or loads its scripts. Code panels, Routine logic, imported worlds, recursive custom models and external mesh references are refused explicitly. Baked CAD is accepted only with validated finite cached triangles, and component ids must belong to the shipped catalog before local mesh paths are built. Bundles keep the gallery’s 8 MB limit. There are at most 100 entries and 32 seeds per League.

The replay job emits results only after every entry and seed completes. The final trusted publishing job validates the artifact’s manifest, closure and exact workflow provenance before publishing complete standings. Existing frozen measurements cannot be replaced. An identical replay leaves the original frozen evidence intact. Fixture dispatch runs the same bounded process and checks every measured standing against the committed rover fixture. The workflow adds no job to pull request Check.

### Fleet authentication and authorization

The self-hosted Fleet service is a separate authenticated HTTPS origin, never a relaxation of the desktop bridge. `electron/bridgeGuard.mjs`, `electron/appOrigin.mjs` and `electron/robot/robotRoutes.mjs` keep their existing guards. Fleet refuses remote HTTP, nonloopback HTTP binds, forged Host and cross-origin browser API requests. Public app code and the sign-in shell carry no registry data. Organization assets, list queries, exports, subscriptions and mutations require live credentials and the single default-deny evaluator described in [Fleet](fleet.md).

Organization UUIDs partition every resource lookup, parent relationship, role reference and status update. Explicit denies override grants from every role and group. Scoped service credentials intersect the issuing account's current roles. Passwords use salted scrypt. Session, enrollment and service tokens have 256 random bits and are stored only as SHA-256 hashes. Enrollment is single-use. Session revocation and role changes invalidate subscriptions through PostgreSQL notifications. HTTP errors never expose database details. Inventory exports cannot read the credential or password tables.

Local organization recovery uses the service operator's database authority, never a remote endpoint or email ownership. One dedicated account and role per organization are protected from ordinary deletion, replacement, enrollment and group references. Identity mutations, login and local recovery serialize on the organization row, and HTTP identity writes reauthenticate after acquiring it. Recovery rotates the password through the existing scrypt implementation and deletes all selected-organization credentials, causing existing subscription resets. It never restores revoked service tokens or changes robot identities. Federation and provisioning callers must preserve the protected local identity contract in [Fleet](fleet.md#local-organization-recovery).

Recovery secrets enter bounded noninteractive stdin, never arguments or persisted browser data. Success and its secret-free audit row commit atomically. Refused protected edits roll back before recording the attempt separately. The local inspection command reads organization-scoped pages of those records. Attribution names the database login, host and OS account, or the authenticated Fleet account UUID. Database administrators can rewrite both authority and audit. Shared operator accounts share attribution, and interrupted processes or unavailable databases cannot guarantee refusal records. [Recovery boundary evidence](../notes/node.md#fleet-local-recovery) records tests and limits.

The studio publisher reads its origin and token only from an operator-selected local configuration file, never from agent or renderer data. Its HTTPS and loopback HTTP connector intentionally supports private self-hosted addresses. It refuses redirects and URL credentials and caps requests and replies. It does not use the public-only fetcher, whose private-address refusal remains authoritative for agent-controlled URLs. No Fleet token enters a scene, export, preload or bridge response.

`tools/fleet/authorization.test.mjs`, `service.test.mjs` and `adapter.test.mjs` cover authorization matrices, cross-organization references, revoked credentials, protected assets, live subscription invalidation, hostile origins, oversized batches and insecure remote transports. [Boundary evidence](../notes/node.md#fleet-authorization-boundary) records the tests and limits.

### Fleet facility assets

Facility metadata, geometry, source hashes, registration and conversion require site authorization through the existing Fleet evaluator. Authentication and authorization precede the large-body read, and writes recheck authority after preparation. At most two 64 MiB request preparations run at once. Source packages are capped at 32 MiB and 256 files. Large JSON and geometry validation run in bounded JavaScript workers. Registry enumeration exposes no geometry and no registration through robot-only grants. Tile subpaths are refused and the globe has no external tile requests.

Local USD imports use the pinned SimReady process and inspect package dependencies before stage composition. The [SimReady guide](simready.md#local-fleet-facilities) records resolution, deadlines and the absence of an OS sandbox, the Linux and Windows memory limits and the macOS memory gap. `electron/simready/localFacility.test.mjs` checks traversal, oversize packages, absolute and remote layer references, escaped textures and valid local sublayers. `tools/fleet/facilities.test.mjs` covers authorization, cross-organization requests, revocation, unknown registration, incompatible vertical frames and refused tiles. [Fleet evidence](../notes/fleet.md#facility-placement-and-imports) keeps their limits together.

### Fleet incident history

Fleet incidents consume the existing robot event channel. No command, IPC handler, HTTP route, deployment interface or recording format is added. Acknowledgment writes only local incident state. It cannot issue a robot command or clear a daemon latch. Existing command validation, motor locks, control precedence and ladder checks continue to own motion.

`fleetIncidents.ts` treats restored local storage as untrusted data. It bounds input to 256 KiB of UTF-8 JSON and 128 incidents, validates unit names, safe ids, timestamps within JavaScript's date range and hashes, and rebuilds known fields only. A recording reference that differs from the incident's session is discarded. Messages and names remain React text. Incidents contain references and fingerprints, never credentials or recording bytes. `openIncidentTry` uses `loadManifests` and the existing timeline recording reader, whose backend routes retain their file-id checks. A deleted or unavailable recording cannot substitute the unit's latest try.

The condition worker evaluates existing Case contracts without running Case code or movement actions. Missing readings stay unknown before evaluating negation. Per-unit work has one in-flight sample and one pending sample, capped at 32 units. Dropping an intermediate sample resets continuous-duration evidence. Hostile storage and unavailable or mismatched recording references are covered by the incident tests. [Evidence and limits](../notes/testing-robot-runtime.md#retained-fleet-incidents).
