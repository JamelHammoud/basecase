# Window framing and macOS integration

Part of the Basecase guide. [AGENTS.md](../../AGENTS.md) holds the rules every change follows and the index of these files; section numbers (§) are shared across them.

## 2. Window Framing & macOS Integration

- **Structure (like the ChatGPT desktop app):** an outer **window chrome** (`.window-chrome`, `#121212`, darker than every card) holds a 44px title bar, a **view rail** down the left edge, and three rounded **cards**: sidebar, canvas, inspector. Cards have 12px corners and **no border**: they read as surfaces by lightness alone.
- **Title bar, left to right:** stoplights · Basecase logo · sidebar toggle (`PanelLeft`, ⌘B) · scene tabs (§5a) · the scene's Undo · Redo, Export and inspector toggle (`PanelRight`, ⌘I). The toggles and Export never move; collapsing a panel just closes its card and its gap.
  - Nothing names or creates the scene outside the tabs: no scene-name header and no New Scene button in the sidebar.
  - The one top bar is this title bar. **Never** render fake stoplights or a second bar that pushes the cards down.
- **View rail** (`nav` "Sidebar views" in `SceneWorkspace`): the sidebar's views as 36px icon buttons on the chrome, under the close button: Parts (the default view), Robots, Objects, Play (Cases, Routines and Operate as tabs, §5), Layers, Library; Settings (⌘,) at the bottom. Tooltips open to the right. The open view has a soft fill and its icon turns filled (outline while idle): Parts is a hex nut, Robots a round robot face looking straight ahead (solid eyes; the filled state's holes are cut a little larger so they look the same size), Play a cube (the same as Cases; filled, the cube is solid with its edges cut out), Library a bookmark (`src/design-system/icons.tsx`). Clicking another view opens the sidebar on it; clicking the open view collapses the sidebar (like an activity bar). The rail stays when the sidebar is collapsed. Once an update has downloaded (§0i), a 28px blue circle with a down arrow (`ArrowDownIcon`, `primary`) sits above Settings, tooltip “Restart to install ⟨version⟩”; a click restarts into it.
- **Card headers:** each side card starts with a 44px header row (no hairline under it) whose content centers on y = 66, in line with the first rail icon. The inspector's header holds 28px controls with 8px padding, an even 8px on every side. The sidebar's header names the open view (15px semibold); the inspector's holds `PanelTabs` (Inspect · Pose · Simulate · Build · Agent; Pose and Simulate only with joints; Agent shows the white spinner while the agent works) and nothing else.
- **The grid** (`LAYOUT` in `theme.ts`; keep these numbers in sync with `trafficLightPosition` in `electron/main.mjs`):
  - **One centerline, y = 22.** Stoplights (14px buttons, 23px apart, measured on macOS 27) are at `trafficLightPosition: { x: 19, y: 15 }`, so they span x 19–79 and y 15–29. Toggles, actions, tabs and + are all 28px tall at `top-[8px]`: 8px from the window top and 8px above the cards (y = 44).
  - **The rail column:** icons span x 8–44 and center on x = 26, under the close button. They're 4px apart; the first centers on y = 66 and Settings ends 12px above the window bottom.
  - **8px everywhere outside the cards:** cards start 8px after the rail (x = 52), sit 8px from the window's right and bottom edges and 8px apart; the logo's 28px slot is 8px after the stoplights (x = 87), the sidebar toggle 4px after it (x = 119); tabs start over the canvas card's left edge while the sidebar is open (8px after the Scenes menu when it's closed) and end 8px before the title bar actions.
  - **12px from a card's edge to its content** (`px-[12px]`; lists 8px, since rows pad themselves). The title bar actions' right edge (width − 20) lines up with the inspector's content.
  - The root font size is 14px, so `rem`-based Tailwind sizes (`h-10` = 35px, `px-3` = 10.5px, `gap-1` = 3.5px) are off-grid. Use px values for chrome, card padding and anything aligned to the stoplights.
  - Main-process changes (like `trafficLightPosition`) need an Electron restart; the renderer hot-reloads.
- **Window dragging:** the title bar uses `DRAG_REGION`. Every interactive child uses `NO_DRAG_REGION` (both exported from `src/design-system/theme.ts`).
- **Vibrancy:** on macOS the Electron window uses `vibrancy: 'sidebar'` with a transparent background. An inline script in `index.html` adds `html.is-electron` before the first paint (macOS only: the class means “the desktop shows through”), and `.window-chrome` turns translucent only in Electron, so the title bar and gaps show the desktop like a macOS sidebar. The cards stay opaque. In full screen there's no desktop behind the window, so `main.tsx` adds `html.is-fullscreen` (from the `window:fullscreen` events) and the chrome turns solid `#121212`.
- **Window size:** minimum 1240 × 720.
- **Windows frame** (`WINDOWS_FRAME` in `main.mjs`): `titleBarStyle: 'hidden'` with `titleBarOverlay` (`#121212`, 44px tall), so Windows draws its own minimize, maximize and close buttons at the top right, and a solid `#121212` window (no vibrancy, no `is-electron`). `useCaptionInset` reads the buttons' width from `navigator.windowControlsOverlay` (138px fallback); the title bar actions, the tab strip's right edge and the guide viewer's close button move left by it. There are no stoplights, so the title bar starts with a Menu button (`MenuIcon`, x = 12, under the rail column) that pops up the native menu (`menu:popup` → `popupAppMenu`), then the sidebar toggle. The menu has no App menu there: Settings sits in Edit, and Check for Updates, Get Beta Updates and About in Help.
- **Logo:** the Basecase ring (`BasecaseLogo`, 18px, `white/90`) in a 28px slot on the title bar's centerline, everywhere except Windows (where the Menu button takes its place). It's not a button. On macOS it sits right after the stoplights. With no stoplights (web, macOS full screen) it's at x = 12, centred over the rail column (x = 26), and the sidebar toggle, Scenes menu and tabs start at x = 58, so the toggle's glyph (about 6px inside its button) lines up with the sidebar's content (card at 52 + 12px inset).
- **Boot screen** (inline in `index.html`, dismissed by `src/app/boot.ts`): the logo ring on the window chrome. It turns a quarter turn into place on a spring and seats like a nut being tightened (rotate −90° → 0, scale 0.7 → 1, 6% overshoot), then a light sweeps across it, leaving it lit, the glass edge of the app icon. It's plain CSS in the HTML, so it paints on the first frame, before the 3 MB bundle loads. It animates only `transform` and `opacity`, which run on the compositor, so it stays smooth while the main thread parses and mounts. The window is created hidden and shown on `ready-to-show` (2 s fallback), so it never appears blank. `#root` stays at opacity 0 under it, still rendering. Once the active scene has drawn its first frame, the ring fades and grows as the UI fades in (300 ms), but not before the turn has settled (520 ms). Reduced motion: no turn or sweep, just a fade. The overlay never takes pointer events; the title bar's drag region underneath still moves the window. No wordmark or text.
- **App name: Basecase**, and **Basecase (Dev)** in dev mode (`npm run electron[:dev]`, the Vite dev server), so a hot-reloading build never passes for the real app. `npm start` runs the production bundle (`--bundle`) and stays Basecase with the normal icon. `DEV_MODE` and `APP_DISPLAY_NAME` live in `electron/appName.mjs`. `app.setName('Basecase')` never changes: Electron keys the keychain item that holds `safeStorage` secrets on the app name, so renaming it would lock dev out of saved API keys. Dev mode shows its name through the menu labels (`app-menu.mjs`: the app menu, About, Hide, Quit) and `app.setAboutPanelOptions`. Settings stay in `Application Support/Basecase` either way, and the old `Robotics 3D Studio` folder (localStorage) moves there once. macOS names a running app after its bundle (menu bar, Dock, ⌘Tab, Force Quit), so both scripts launch through `tools/electron-dev.mjs`, which keeps an APFS clone of Electron.app per mode with its own executable (`Basecase`), name, bundle id and icon: `node_modules/.cache/basecase-electron/Basecase.app` (`app.basecase.dev`, `build/icon/compiled/`) for `npm start`, and `node_modules/.cache/basecase-electron-dev/Basecase (Dev).app` (`app.basecase.devmode`, `build/icon/compiled-dev/`) for dev mode. Each is rebuilt when Electron's version, its name or id, or its compiled icon changes. Because the executable isn't named Electron, `app.isPackaged` is true in both; check `process.defaultApp` for from-source behavior, and `DEV_MODE` for dev-server-only behavior.
- **App icon:** a white squircle ring (superellipse n = 4, 600 of 1024, opening 0.446 of the ring) on a dark grey glass background made from the app's own surfaces (`#121212` chrome up to a lifted `#3c3c3d` highlight). The source is the Icon Composer file `build/icon/Basecase.icon`: the ring (`Assets/ring.svg`) is a glass layer, so macOS adds the specular edge, frosting and shadow; the mesh (`Assets/background.png`) is a flat layer under it. The mesh comes from `build/icon/mesh.html` (solid colour fields + a conic fan + directional veils, blurred as a share of the tile, with grain), rendered by `node tools/icon-mesh.mjs [seed] [out] [palette]` (grey seed 7 ships; a blue palette is kept as an alternative). `npm run icon` compiles `build/icon/compiled/Assets.car` (Liquid Glass) and `Basecase.icns` (fallback) with Xcode's actool; `tools/electron-dev.mjs` installs both in the dev bundle. `build/icon/basecase-1024.png` is macOS's own rendering, for docs. Restart the app to see a new icon.
- **Dev icon** (`build/icon/BasecaseDev.icon`, dev mode only): a blueprint of the app icon. A blue gradient (`#00a3ff` → `#1261eb`, top to bottom) with a white keyline (an inset rounded square, 14 of 1024) and dashed guides on the ring's outer edges (x and y = 212 and 812), 6 thick at 75% (`Assets/blueprint.svg`, flat). `node tools/icon-dev-guides.mjs` lays out the dashes, not `stroke-dasharray`: one is centred on every crossing and on the keyline where each guide ends, so none ends half-cut. The guides run full length and the ring overlaps them. The whole set is one path under one group opacity, so crossings don't stack. Over it sits the same ring as a frosted glass layer, white fading from 92% to 38% with a 12px white outline (`Assets/ring.svg`). `npm run icon:dev` compiles it to `build/icon/compiled-dev/`; `build/icon/basecase-dev-1024.png` is its rendering (Icon Composer's `ictool --export-image`).
- **Favicon** (`public/favicon.svg`): the ring alone, no background, black in light mode and white in dark (`prefers-color-scheme` inside the SVG).
- **Native menu bar** (`electron/app-menu.mjs`): App (Check for Updates in packaged builds, Settings ⌘,), File (New Scene ⌘T, Open Scene File, Reopen Closed Scene ⇧⌘T, …, Export Scene, Export STL, Print ⌘P, Import Mesh, Import SVG, Import Robot, Import BVH, Close Scene ⌘W, Close Window ⇧⌘W), Edit (…, Find Parts ⌘F), View (Camera ▸, Two-Finger Scroll ▸, grid, reference images, panels), Window (Show Previous / Next Scene ⇧⌘[ / ⇧⌘], then every open scene with ⌘1–⌘9), Help (Keyboard Shortcuts ?).
  - Items send `menu:command` ids to the renderer: tab commands (`new-scene`, `close-tab`, `reopen-tab`, `next-tab`, `prev-tab`, `tab:<id>`) run in `App.tsx`, the rest in the scene in front (`runMenuCommand` in `SceneWorkspace.tsx`). Both report checkmarks and enabled state back with `menu:state` (partial updates merge).
  - Shortcuts the renderer already handles are display-only (`registerAccelerator: false`), so keys never run twice or fire while typing. Undo, Redo and Select All stay registered so text fields keep native editing; the renderer ignores a menu repeat of a key it just handled.
  - macOS ignores `registerAccelerator: false` and fires the key equivalent for any key the page doesn't `preventDefault` (a `?` or `D` typed in a text field opened Settings). So `item()` clicks drop events with `triggeredByAccelerator` (`clickOnly`): the renderer owns those keys, and only mouse clicks run the item.
  - Every new app-level command gets a menu item when it fits one of these menus.
